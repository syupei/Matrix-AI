# 代码工程：职级与风险、缺陷对照

何时读：给本专业的任务标难度、定风险、给缺陷定级；判断某个实例能否承担某个任务时。职级的编号与横向参照见 C21，风险与缺陷的定义与处理见 C22，这里只写本专业的例子。

使用范围：T2–T9。

| 职级 | 能做 | 能判断 | 不能做（越权） |
| --- | --- | --- | --- |
| T2 | 在指导下写小脚本和单元测试 | 无 | 合入代码；改接口；在正式环境执行任何操作 |
| T3 | 按任务卡写简单函数，带测试 | 函数内部的写法 | 改接口契约；引入新依赖 |
| T4 | 按接口契约写带测试的函数或小模块；改配置 | 模块内部的实现方式 | 改契约；引入新依赖；合入未经检验的代码；写含破坏性操作的脚本 |
| T5 | 实现一个模块，含模块级测试；写在预发布环境执行的脚本 | 模块内部的设计 | 改模块边界与对外接口；做关键技术选型 |
| T6 | 一个子系统及其接口；增量的拆分与整合；小组 master | 子系统内的技术取舍；拆分与派发 | 跨子系统的契约变更（交架构负责人）；关键选型的最终确认（交人） |
| T7 | 代码工程 master：承接建模、技术方案的大部分、增量规划；关键选型的候选与推荐 | 委托内的技术决定 | 关键选型的最终确认、发布、接受风险（交人） |
| T8 | 架构与关键技术选型方案；审阅各子系统；跨专业的技术判断 | 技术方案的推荐与否决 | 最终拍板（交人） |
| T9 | 最复杂、最新的技术问题；定本专业的方法与标准 | 方法与标准的推荐 | 最终拍板（交人） |

**风险对照**（C22）：
- F0：在正式环境迁移或批量修改全部用户数据；删除用户数据的逻辑；登录、权限、会话与密钥管理；发布上线、切换流量、域名与证书；带着已知高危漏洞发布；在正式环境执行含破坏性操作的脚本。
- F1：支付、扣费与对账；只涉及部分用户数据的迁移；跨模块接口契约与数据库结构变更方案；核心业务逻辑；共享组件与基础库；构建与部署配置；并发、缓存与一致性；**写含破坏性操作的脚本**。
- F2：按契约实现一个核心模块；主要页面的前端逻辑；客户端接入接口；新增不外发数据的普通依赖；没有在正式环境执行过的导入导出脚本。
- F3：有单元测试的函数；非核心页面；内部工具脚本；不含个人数据的日志与指标。
- F4：代码格式与命名；注释与内部文档；测试数据整理。
- F5：用完即弃的试做；调研笔记；本地实验分支。

**缺陷对照**（C22）：
- Q0：发布包无法启动；严重安全漏洞（即使还没被利用）；大规模数据丢失；路径写错的删除脚本会在有真实数据的地方运行。
- Q1：越权；扣错钱；部分数据丢失；主流机型闪退；偶发的重复扣款。
- Q2：主流程明显变慢；数据不一致但可以恢复；敏感信息写进日志；前后端字段不一致（非核心流程）。
- Q3：边界条件出错、很少遇到；个别机型排版错位；日志级别配错。
- Q4：命名与格式；注释错误。
- Q5：重构与改进建议。
