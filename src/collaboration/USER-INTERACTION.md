# 用户确认与流程位置

规则版本：interaction-flow/0.5。角色入口仅引用本文。PM接管时由统一入口展示；其他角色提交同一份审阅材料。

## 确认协议

先完成可独立的授权工作及自检，再提交：request_id、role/stage、成果路径与版本/摘要、scope、关键取舍、未决、next_action。实际展示正文摘要与可访问成果后，提供两个选择：**确认，可继续** / **需要进行调整，进入调整对话**，自由文本始终可用。

记录实际展示与真实回应的来源引用，将批准绑定请求、成果摘要及范围。工具调用成功只证明已展示；预选、关闭、超时、无回复、自检或单纯修改意见保持待确认。用户明确自然回应可按上下文确认具体范围；局部批准只覆盖该范围。旧版批准遇内容变化仅回查影响部分，既有免审委托须有可定位范围。

保存并回读实际成果后再生成主链接，标明版本/章节。对话链接按当前宿主解析；本地文件用实际绝对路径，包内文档用相对路径。打不开时展示可读内容与访问缺口，不要求盲批。最终需要人行动的回复须自包含摘要、入口、范围、回复方式与下一步，工具输出或状态文件不替代这条提示。

“好，继续”只有在先前已展示单一版本/范围并请求批准、且无互斥未决项或版本变化时才作为该范围的自然确认；“已阅/收到”含义不明时只澄清该决定。此前只是进展播报则直接恢复已授权工作；漏发真实审阅提示则补齐，未展示内容保持待审。回应期间直接编辑时保留人的修改并回查受影响确认。

当前授权、输入充足的工作持续到实际审阅点；最终停止原因只能是需要真实决定/信息、约定范围完成、用户暂停或确有外部/执行阻碍。说明实际已完成与恢复方式，有真实运行依据才承诺自动恢复。独立可做部分先完成；普通进展消息不作为结束理由。

## 宿主适配

先检查当前会话实际工具及用途/模式限制，再选择通道；工具名只是适配线索，不是必然可调用的API。

| 宿主 | 原生候选 | 操作原则 |
| --- | --- | --- |
| Codex | `functions.request_user_input_async`；其它提问工具按当前限制 | `title`含成果/范围/下一步，两个`options`为上述原文；仅可用于澄清或受Plan限制的工具不用于批准 |
| Claude Code | `AskUserQuestion` | 按当前工具schema映射问题、标题、选项与说明；实际提交答复才算回应，headless不假设存在可交互UI |
| 其它宿主/原生不可用 | 下述通用HTML或文本 | 说明通道限制，交付相同请求与选项；未收到回传保持待确认 |

[Claude官方用户输入说明](https://platform.claude.com/docs/en/agent-sdk/user-input)。宿主实现可能变化，实时工具定义优先。

通用控件：打开 [review.html](../shared/review.html)，导入含上述字段的请求JSON并查看成果，选择后导出带request_id、artifact_sha256、scope及choice的回复；将文件回传原任务才能记为收到。HTML无网络发送、无自动批准，导出不是宿主已接收，也不提供身份认证。不能显示HTML时直接展示同样两种文本回答。

## 审阅边界

产品S1–S7在主要阶段成果就绪后主动询问调整/补充，明确批准后推进依赖阶段；明确范围的自主授权可沿用。设计只设D1基础、D2粗结构A、D4关键交互/代表视觉B、D6完整设计C四审；D1材料按 [基础审阅](../.agents/skills/experience-design-agent/references/foundation-review.md) 实际展示。E1在E1.4集中交接审阅。普通编辑/内部检查不增加审批。切换执行 [阶段关卡](STAGE-GATES.md)。

选择调整时保持相关范围待确认，先收齐 [本批反馈](FEEDBACK-PROTOCOL.md)，修订、自检后展示新版本；明确改法直接处理。用户说继续但此前只是进展播报时恢复已有授权，不能追认为批准未展示成果。等待只暂停依赖该决定的工作。

## 可见流程位置

实质进展、切阶段、待审、返工和交付显示：**{流程}：共N步，当前进行第X步「名称」｜真实状态与范围**。产品7步、设计7步、E1四步；PM按实际已规划任务计数，项目层与角色层分开。未知全貌显示本轮已规划范围，返工注明回查与返回点。步骤位置不是完成率，内部工具调用和对话轮数不充作步骤。
