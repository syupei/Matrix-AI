# 性能与容量

何时读：E1 写性能与容量场景时；E2 试做、骨架压测与定工程基础时；质量验证测量与做发布验收时。按档位取用：小型档只测核心场景；"建议"按风险选用。

## 1. 场景（E1）

- 每个重要场景写：对象或操作、负载与数据规模、设备与网络、指标（如时延的 p95 与最差值、帧时、内存、包体、冷启动）、目标与来源。没有依据的数值标为建议值。
- 写明最低支持的设备与网络，测量都在它上面做。只在高配设备或模拟器上测的，写明证据层级（CORE §2）。

## 2. 方案与骨架（E2）

- 风险试做与骨架压测按技术方案的试做指引进行；按目标负载的一定比例压测时，写明外推依据。外推得出的结论写成外推，不写成实测。
- 分层的项目，把时延、帧时、内存、成本的预算分给各部分（C02 §4）。
- **容量与成本模型**（建议，一页）：目标负载、外推依据、下一个瓶颈及触发条件（例如同时在线超过某个数值）、每千名活跃用户的月费估计。

## 3. 持续检查（E3，建议）

从骨架起选 2–5 个关键指标做基准，例如关键接口 p95、包体、冷启动、帧时。每次合入或每天跑一次，超出预算就上报。放宽预算由人决定（C02 §5）。

## 4. 验收（质量验证）

- 测量方法：负载、数据与设备固定，先预热，重复多次，保留原始样本，报告百分位与最差值。
- **长时间稳定性**（建议）：服务和长时间运行的客户端（如游戏），发布验收时连续运行若干小时，看内存、连接、句柄是否持续增长。
- 达不到的层级写明由谁在哪个阶段验证，例如真实负载只能在分批发布中观察。
