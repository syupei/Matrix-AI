# 协作请求与返回模板

字段语义以 [共用约定 0.1](CONTRACT.md) 为准。以下是可复制的 Markdown 模板；使用真实值替换占位符。一个记录可以含请求、答复和处理结果，避免双份事实；宿主传输可序列化这些字段，模板本身不会发送消息。

## 请求

```markdown
# {请求 ID}：{一句话事项}

- 协议：professional-collaboration / 0.1
- 项目/任务：{实际标识}
- 请求修订/替代关系：{修订标识；有旧请求则引用}
- 来源角色/实例 → 目标角色/实例：{实际已配置实例；未知写未配置}
- 类型：{查找解释/设计协作/变更建议/验证反馈等}
- 授权与允许范围：{来源、可自行决定什么、允许改哪些产物、哪些仍需人确认}
- 输入基线：{基线标识、实际文档版本、条目 ID、接收方可访问的引用或对应版本快照}
- 当前问题与影响：{具体缺口；阻断哪些工作，不影响哪些工作}
- 已查依据与候选建议：{已知事实、假设、建议分别列明；没有则写无}
- 期望回答/产出：{对方完成到什么程度才有帮助}
- 返回与恢复方式：{实际通道及恢复能力；尚未具备就如实说明}
- 运行状态及依据：{已准备/已发出等；实际证据，没有则无}
```

## 返回

```markdown
## 对 {请求 ID / 修订} 的返回

- 答复者/角色规则版本：{实际实例与专业规则版本}
- 本次所依据的输入：{基线/文档版本/条目；无法访问时不能声称已读取}
- 结论类型：{既有定义解释/授权内专业决定/待审阅变更建议/需要信息或人决定/无法处理}
- 结论与依据：{直接回答，引用真实依据；推导与事实分开}
- 产出与修改：{实际文件/条目/版本；仅建议则明确未合入}
- 影响范围：{涉及的规则/功能/设计/验收与待复核内容}
- 是否需人决定及原因：{无则说明在何授权范围内解决；有则给具体问题与可比较选项}
- 请求方下一步：{可继续的工作、仍受阻范围}
- 处理结果：{仅已返回，不擅自替请求方宣布采纳/人工确认}
```

## 请求方核对与关闭

```markdown
## 接收处理

- 当前版本核对：{输入是否仍适用；旧结果哪些可用及依据}
- 采用/不采用/需补充：{理由、实际合并位置与版本；不修改对方维护的事实源}
- 审阅状态：{是否涉及原定人工确认；确认记录引用或待确认}
- 请求状态：{已解决/仍等待信息/已替代等；与运行依据一致}
- 恢复位置：{实际接续的任务；本轮能继续就继续}
```

## 示意：现有规则可以直接回答

下面是假设情境，用于解释行为，不是任何真实项目的既有事实：

- 设计角色询问：“提交超时后是否能直接重试？目前只看到成功和失败的描述。”
- 产品角色查到该假设项目基线中的规则：“结果未知时先查询，不直接重新提交”，返回其版本和条目，并补相关引用。
- 若核对只是遗漏引用、没有改变规则及授权边界，可以直接答复并继续，不新增人工审批；不虚构不存在的规则。
- 若查不到相关定义，则返回建议及影响，区分可在既有授权内决定的内容与需人确认的产品承诺；不能照搬上面的示意作为默认规则。
