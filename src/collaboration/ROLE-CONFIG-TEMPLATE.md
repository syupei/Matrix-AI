# 角色配置模板

何时读：为项目接入某个角色的实际实例、更换模型或工具、调整某角色分工时。这是字段模板，不是已启动的 Agent 注册表；没有实例、模型、工具或通道就写"未配置"。

## 1. 每个角色记录

| 字段 | 内容 |
| --- | --- |
| 角色标识与名称 | 如 `product` / 产品 Agent；实际实例另设 ID，不与模型名混用 |
| 专业规则与版本 | 实际 skill 位置与版本、能力标准版本、用户追加的专业要求 |
| 输入与预期输出 | 可处理的任务、必需前提、产物类型与完成判断 |
| 可决定的范围 | 已被委托的产品或设计决定及授权来源 |
| 维护的成果 | 正文或条目范围；跨职责修改走建议返回 |
| 需要升级的情形 | 缺用户意图或领域事实、超范围、冲突、不可执行的要求 |
| 实际执行配置 | 模型、工具与版本、可访问资源；凭证由宿主管理，不写进共享文档 |
| 协作接入 | 协议版本、实例地址或宿主路由标识、输入输出的实际访问方式 |
| 反馈处理 | 反馈索引位置（`collaboration/feedback.md`）与当前维护责任 |
| 恢复与限制 | 能否运行、如何接收返回并继续、已知能力缺口 |

## 2. 角色与责任

| 角色 | 专业责任 | 维护的成果 | 本包提供 |
| --- | --- | --- | --- |
| 产品 | 产品事实、范围、规则、体验要求、取舍与验收依据；受理其他角色的澄清与变更建议 | 产品基线及确认与变更记录 | product-agent |
| 交互与视觉设计 | 空间、交互、视觉方案的比较、制作、自检与验证；可提出产品调整建议 | 设计方案、可编辑成果、原型、设计规格、验证记录 | experience-design-agent |
| 研发承接（E1） | 输入核对与澄清、逻辑工程模型、评审与交接 | `engineering/intake/` 下的依据与映射 | engineering-intake-agent |
| 技术方案（E2） | 技术决定、风险试做、可运行骨架与工程基础、技术评审 | `engineering/solution/` 下的决策、证据与评审记录 | engineering-solution-agent |
| 增量构建与发布（E3、E4） | 增量规划、任务卡、组织实现、检验与集成、范围完成评审；小型、中型项目的发布准备、逐批发布与交接 | `engineering/build/` 下的增量计划、增量记录与评审，`engineering/release/` 下的发布与交接记录；代码在 `code/` | engineering-build-agent |
| 项目前台 | 主对话：启动检测、按文件回答问询、登记并转交要求、展示待决事项并记录答复 | 不维护专业成果；登记写入反馈索引与运行登记 | project-front-desk-agent |
| 项目管理 | 顶层任务、依赖、子项上报、检验与集中人审 | 任务事实、事件与派生视图 | project-management-agent |
| 专业协作 | 真实请求、唤醒、应答、合并与恢复 | 通信状态与专业源引用 | professional-agent-collaboration |
| 质量验证 | 验收条目与覆盖、非实现者检验、质量测量、发布验收、缺陷分级与回归 | `engineering/qa/` 下的验收条目与检验记录；验收测试在 `code/` 下的验收目录 | quality-verification-agent |
| 发布（大型及以上） | 发布与交接 | 各自产物 | 未提供，接入时另行配置 |

参与项目的人（BOSS、产品经理、美术、工程师等）及其决定权登记在 `collaboration/people.json`，规则见 [TEAM](TEAM.md)。content-design-review 是产品与设计共用的写作审读方法，不是独立岗位；product-capability-model 是共享的能力标准，不是角色。设计 Agent 不是某个设计软件的操作包装：它负责专业判断，并用系统实际可用的工具落地，工具调用成功不代表设计成立。

研发承接实例的登记示例：角色 `engineering-intake`；输入为有效产品基线、相关设计成果、确认/变更/反馈和现有工程资料；输出为工程输入基线、逻辑工程模型与映射、评审与交接；成果默认在 `engineering/intake/`；可自行处理授权内的阅读、推导、缺口分析、模型走查与协作请求；产品事实归产品、具体体验归设计、外部专业事实归来源方、未委托的关键取舍回到人。

## 3. 路由与调整

- 产品问题送产品，空间/交互/视觉送设计，实现送技术，测试执行送 QA。跨职责问题通过请求返回责任方，不为补一个产品问题重启全部访谈。
- 各实例只加载自己的角色 skill；不要把所有角色的 skill 当作每个实例的常驻指令。独立角色不要求每个阶段新建实例；替换实例时从有效成果和协作记录恢复，不依赖原会话的私有记忆。
- 单独调整某角色时记录：改了哪条专业要求、依据、新规则版本、对进行中任务的适用范围。局部调整不改变已确认的产品事实或其他角色的权限。
- 更换模型或工具后，核对新实例能否读取原基线、保留条目引用、按规定返回结果、访问和编辑相应成果、正确报告失败；进行中的请求保留原请求 ID、输入版本和处理记录。能加载 skill 不等于兼容通过。
