# 总入口：专业目录与单对话用法

何时读：项目启动、决定用哪些专业和多大规模时；对话里指定使用本技能包、不另建实例时。安装见包里的 START.md。

本技能包由共同底座和若干专业组成。共同底座是所有专业都遵守的规则，从 [共同底线](CORE.md) 和 [共用规则索引](GUIDANCE-INDEX.md) 读起。每个专业在 [professions/](professions/) 有一份登记，写明它处理什么、何时参与、由哪些技能组成；下面的目录由登记生成。技能在安装时指定的技能目录里，例如 `.agents/skills/<技能>/SKILL.md`。

## 2. 项目启动时选专业

- 技能包不预设项目配置。由人决定：哪些专业参与；规模（单对话、每个专业一个实例、多实例团队）；各专业由谁当 master。
- 推荐由项目前台做；没有前台时由 PM 或当前对话做。对照项目描述和登记里的"处理什么""何时参与"现算组合，每个专业写一句理由；人已经指定的专业照用，只补充建议。
- 项目涉及、但本包没有对应专业的领域（例如法律与合规、安全），照实说明，建议由具备相应资质的人审阅，不由现有专业代替判断。
- 多人参与或中型以上的项目，建议加入调度类（项目管理、项目前台）。
- 人决定之后才按决定拉起实例、派发任务；之后增减专业或改规模，同样由人决定。

## 3. 单对话用法

对话里指定使用本技能包、不另建实例时，这个对话就是所有参与专业的 master：

1. 先读共同底线和共用规则索引。做哪类工作，就读哪个专业的技能，按它的阶段、人审点和成果要求做；回复里写明当前按哪个专业、在哪一步。只读当前步骤需要的文件，不一次加载所有专业。
2. 成果写在项目文件里，例如产品定义、文案表、设计说明、代码与测试；任务清单可选。
3. 人审点照常保留；几个人审点合并成一次展示，要人明确安排（C01）。
4. 检验和制作是同一个实例：记录写明"同一实例检验"，证据层级如实标注，不写成独立检验。
5. 按 C21 标难度，按 C22 定风险、给缺陷定级。风险 F0 由人判定后才生效；风险 F1 的成果和缺陷 Q0、Q1 在对话里直接告诉人。
6. 出现下面任一情况，向人建议扩到更大的规模，由人决定：需求条目多到一个对话难以跟踪（例如超过 20 条）；出现 F0 或较多 F1；两个以上的人参与；需要并行加快进度。
