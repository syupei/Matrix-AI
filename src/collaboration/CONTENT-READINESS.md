# 内容分期：规格、样本与上线前补齐

何时读：发现资料或素材缺口、设计需要代表样本、交付基线、PM 规划上线准备时。把批量资料的收集与产品本身的设计分开，沿用原产品/设计内容源、反馈索引和 PM 任务，不新建内容岗位或平行正文。

## 1. 按依赖决定时点

| 类型 | 当前必须具备 | 补齐时点 |
| --- | --- | --- |
| 决定目标、规则、核心体验或正确性的事实与内容 | 有依据的事实、规则和当前决定所需资料；缺失就暂停依赖它的结论 | 当前相关阶段，不能用占位绕过 |
| 验证行为、结构和风格的代表内容 | 足够的真实样本或明确标注的模拟样本，覆盖典型与必要边界（长短、数量、缺图等） | 对应设计与验证之前；样本不冒充全量内容或领域事实 |
| 按已定规格替换或扩充、不影响主流程的批量内容 | 用途、类型、格式、数量或覆盖范围、质量要求、来源与负责人、表达标准、验收条件 | 主要功能与设计稳定后、上线验收前集中补齐 |

关键按钮、错误提示、风险说明和决定操作判断的文字属于当前设计依据，不能统称"文案"一起推后；决定核心识别、布局或操作的素材也不能因为是图片就后置。内容本身就是核心价值时按依赖判断。

## 2. 登记

产品在原定义或交付的内容章节登记缺口（或引用已有条目）：稳定 ID、用途与使用位置、类别及理由、规格/样本/有效源版本、数量或覆盖范围、负责人或提供方、触发条件与最迟完成点、验收条件、状态及阻断范围。设计补充实际使用位置和替换后的复验要求；PM 任务引用这份记录，不复制正文或状态。

## 3. PM 发起"内容与资料补齐"

主要功能与设计稳定、可以开始最终填充时，PM 发起补齐环节，安排在上线验收之前并留出替换、复核和修正的时间；没有待补项就记录核对结果，不制造空任务。

1. 提供或制作方按已定规格补齐，写入约定的唯一源；不重新讨论已有效的产品基础，不凭空生成专业事实。
2. 产品审阅事实语义、表达与完整覆盖；专业来源由相应责任人提供依据。
3. 涉及图文替换和版面的由设计检查实际呈现；涉及导入、运行或既定验证条件的由研发或 QA 核对并回归受影响范围。
4. PM 核对实际覆盖、未解决缺口和必要人审，满足约定判据才关闭。补齐暴露出规则或结构问题时，返回相应责任方局部修正。

人员或能力未接入时标出真实缺口，不虚构内容岗位或 QA 已完成。只有产品角色时，维护待补范围与接力条件。

## 4. 与文案检查和阶段完成的关系

[COPY-QUALITY](COPY-QUALITY.md) 覆盖所有实际生成、引用和交付的文字；后置的只是制作时点，不是免检。当前样本与已成稿内容照常审读；未来批量内容标"未制作/待补"，不能从样板通过推定全量通过。判据明确且没有当前阻断时，产品与设计可以交付基线，但要写明后期批量内容的范围、责任和触发；不能称上线内容已齐备。上线必需内容未齐或检查未过，阻断上线验收；缩小上线范围须按授权并留审阅记录。
