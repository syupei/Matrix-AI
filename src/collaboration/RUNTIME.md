# 协作运行入口

何时读：发生具体的跨角色澄清、收到协调请求、恢复待决问题，或为项目接入实际实例与通道时。运行层负责路由与接续，不替任何角色作专业决定。

## 1. 运行层做什么

- 按已配置的职责路由请求；提供接收方可访问的基线和必要上下文；记录真实的投递与执行结果；把返回交回请求方并恢复其工作；处理重复、过期、失败和取消。
- 记录项目当前阶段与主责任方；各角色只记录本职责内的状态并用请求 ID 关联，不各自维护互相矛盾的全项目进度。没有运行层时，如实报告已知的角色局部状态。
- 具体操作见 professional-agent-collaboration skill。已有协作授权时，使用真实可用的独立子 Agent 或任务通道完成问询和接续，不让用户手工搬运常规消息。

## 2. 对人的两种入口

- **协调入口**：项目前台（project-front-desk-agent）；没有前台时为主任务或 PM。跨角色的待决事项、合批的审阅、进度与群摘要从这里发出。责任角色能自行解释或在委托内决定的直接处理；确实需要人时提交具体问题，由协调入口展示并登记真实答复，再唤起原角色继续。区分三类情况：缺工具或通道、缺专业事实、待批准的业务变更；不要把每个工程选择都交给人。
- **讨论入口**：各角色自己的会话或子 Agent。人可以直接到某个角色的会话里深入讨论本领域的问题；该角色把结论、确认与新要求写进自己的源文件与反馈记录，协调入口从文件读取，不转述整段讨论。角色在讨论入口里只谈本领域，需要别的角色时走协作请求，不让人转话。
- 一个角色的会话过长时，先按 [FEEDBACK-PROTOCOL](FEEDBACK-PROTOCOL.md) §6 做对话核对，再换新会话；新会话只从文件恢复。

## 3. 状态与本项目登记

- 角色与在途请求的实际状态保存在 `collaboration/runtime/state.sqlite3`，用协作 skill 的脚本查看；未初始化表示运行接入尚未完成。
- 本项目实际使用的宿主能力（定位或创建实例、发送、唤醒、等待与读取、中断；说明见 professional-agent-collaboration 的宿主通信适配）及其工具名，在首次接入时登记到项目自己的 `collaboration/runtime/host.md`（本文件随安装更新，不在这里填写）。skill 只描述能力，不绑定特定宿主。登记格式：

```markdown
| 能力 | 本项目使用的工具或方式 | 限制与恢复方式 |
| --- | --- | --- |
| 定位已有实例（子 Agent 或独立任务） | | |
| 创建子 Agent | | |
| 发送消息 | | |
| 唤醒空闲实例 | | |
| 有界等待与读取回复 | | |
| 中断或停止在途实例 | | |
| 再次唤醒同一实例（续接方式） | | |
| 同时运行上限 | | |
| 统一人工确认 | 宿主的选项式提问工具，或文本回退 | |
```

安装本包不会初始化运行账本，也不会启动任何实例或后台监测；宿主无法唤醒时如实报告，不以文件存在冒充运行成功。

## 4. 启动检测与按需拉起

- **检测**：每次新会话启动时，主对话按自己实际拥有的工具判断：能否创建子 Agent、能否再次唤醒同一个、能否并行、同时最多几个。结果写进 `host.md`；不能确定的记"未知"，不凭宿主或模型的名称推断。
- **一次授权**：第一次检测到可用时，请人授权"按需为各角色创建子 Agent"，写进项目授权；之后不再逐次询问。修改或收回授权由人决定。
- **按需拉起**：某个角色的第一项任务就绪时才创建它，不在启动时把全部角色拉起来。能续接的宿主复用已创建的实例；只能一问一答的，每次新建，从工作区文件恢复。
- **只传任务包**：交给子 Agent 的是项目路径、角色 skill、请求与范围，不带主对话的聊天记录。
- **不支持或未授权时**：在主对话里切换角色；阶段切换后建议换会话，换之前做对话核对。
- **看得见**：任务登记真实的执行者，项目总入口据此显示各角色以什么方式运行：子 Agent、独立会话或主对话内。

## 5. 同岗位多个实例

岗位能力可以由多个实例并行承担。按具体就绪任务选择实例，分别登记稳定 ID、实际 endpoint 和独立写范围；同一 skill 可对应多个路由，不覆盖正在执行的实例登记。主干规则与接口共享有效基线，共用源由指定维护方合并。按 [任务完整性](PM-INTEGRITY.md) 映射岗位、责任实例、执行实例和任务；PM 管项目层，专业实例自管内部子项。

## 任务派发与返回接续

同专业与跨专业请求均按实际实例 ID 路由；通过 [团队工具](TEAM-RUNTIME.md) 将任务与原请求账本关联，负责人决定局部安排，宿主负责实际发送/唤醒。专业依据、任务状态、投递状态各有唯一源。工具调用按 [工具授权](TOOL-ACCESS.md) 接入；未验证隔离不作隔离承诺。
