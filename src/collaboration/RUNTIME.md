# 协作运行入口

何时读：发生具体的跨角色澄清、收到协调请求、恢复待决问题，或为项目接入实际实例与通道时。运行层负责路由与接续，不替任何角色作专业决定。

## 1. 运行层做什么

- 按已配置的职责路由请求；提供接收方可访问的基线和必要上下文；记录真实的投递与执行结果；把返回交回请求方并恢复其工作；处理重复、过期、失败和取消。
- 记录项目当前阶段与主责任方；各角色只记录本职责内的状态并用请求 ID 关联，不各自维护互相矛盾的全项目进度。没有运行层时，如实报告已知的角色局部状态。
- 具体操作见 professional-agent-collaboration skill。已有协作授权时，使用真实可用的独立子 Agent 或任务通道完成问询和接续，不让用户手工搬运常规消息。

## 2. 唯一的人类对话入口

主任务（或 PM）是唯一面向用户的入口。责任角色能自行解释或在委托内决定的直接处理；确实需要人时提交具体问题，由主入口展示并登记真实答复，再唤起原角色继续。区分三类情况：缺工具或通道、缺专业事实、待批准的业务变更；不要把每个工程选择都交给人。

## 3. 状态与本项目登记

- 角色与在途请求的实际状态保存在 `collaboration/runtime/state.sqlite3`，用协作 skill 的脚本查看；未初始化表示运行接入尚未完成。
- 本项目实际使用的宿主能力（定位或创建实例、发送、唤醒、等待与读取、中断；说明见 professional-agent-collaboration 的宿主通信适配）及其工具名，在首次接入时登记到项目自己的 `collaboration/runtime/host.md`（本文件随安装更新，不在这里填写）。skill 只描述能力，不绑定特定宿主。登记格式：

```markdown
| 能力 | 本项目使用的工具或方式 | 限制与恢复方式 |
| --- | --- | --- |
| 定位已有实例（子 Agent 或独立任务） | | |
| 创建子 Agent | | |
| 发送消息 | | |
| 唤醒空闲实例 | | |
| 有界等待与读取回复 | | |
| 中断或停止在途实例 | | |
| 统一人工确认 | 宿主的选项式提问工具，或文本回退 | |
```

安装本包不会初始化运行账本，也不会启动任何实例或后台监测；宿主无法唤醒时如实报告，不以文件存在冒充运行成功。
