# 职级：难度与谁能承担

何时读：拆分任务、给任务标难度时；判断一个实例能否承担某个任务时；派生实例、指明职级时。

## 1. 编号与横向参照

职级 T1–T9 用于专业实例；T10 留给人。各专业只定义自己用得到的一段（见各专业的登记）。同一编号在各专业之间大致对应：

| 职级 | 横向参照 |
| --- | --- |
| T1 | 助理：照指令做最简单的整理与格式工作 |
| T2 | 实习生（未毕业）：在指导下做基础工作，结果要有人检查 |
| T3 | 初级：按明确要求独立完成小任务 |
| T4 | 中级：独立完成一个完整的功能、模块或文档 |
| T5 | 高级：负责一块，能处理信息不全的问题 |
| T6 | 资深：负责一个子领域或小组，可以当小组 master |
| T7 | 专家：本专业的整体方案与把关，可以当专业 master |
| T8 | 资深专家：跨专业的关键判断 |
| T9 | 首席：最复杂、最新的问题，定本专业的方法与标准 |
| T10 | 人：方向与最终决定 |

各专业的职级表逐级写明能做、能判断、不能做（越权）。写法参照四个方面逐级递进：自主、复杂、范围、知识。

## 2. 任务的难度

- 拆分任务的 master 用本专业的职级给任务标难度，例如"技术 T4"，并写明理由。
- 只派给职级不低于任务难度的实例。
- 想降低难度，就把任务拆小，不改标签。
- 任务比标注的难，或落在本职级的"不能做"里，执行者上报 master，不硬做。
- 难度决定谁能做；怎样检验、要不要人审，由风险决定（C22）。

## 3. 保留给人的决定

以下不属于任何职级，T9 的实例也不能决定：

- 发布；
- 接受已知的严重风险；
- 花钱、签约；
- 改变委托边界；
- 风险 F0 的判定。

实例可以准备材料、提出建议。
