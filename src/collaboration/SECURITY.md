# 安全与隐私

何时读：E1 判定失败代价、开启安全与隐私要求时；E2 定委托边界、关键技术选型与工程基础时；质量验证写验收条目与做发布验收时；E4 准备交接时。按档位取用：小型档只做 §1；"默认"指中型及以上默认要做，不适用时写明理由；"建议"按风险选用。

## 1. 最低限度（各档位）

- 凭证不进仓库、文件、日志、测试数据与对话；运行时由宿主或部署环境注入，各环境分开。
- 依赖锁定版本；自动检查包括密钥扫描。
- 测试与演练不用真实个人数据。

## 2. 默认检查

- **依赖漏洞**：自动检查加依赖漏洞扫描。已知高危漏洞阻断合入与发布；暂时修不了的按缺陷分级处理（质量验证的缺陷分级），放宽由人决定（C02 §5）。新增依赖记下来源与维护状况，停止维护或来源可疑的先换掉。
- **越权**：每个有归属的对象（订单、消息、档案等），至少一条"别人的看不到、改不了、删不掉"的验收条目，在接口层检验，不只测界面。
- **发布验收最少测**：依赖漏洞、越权、未登录或凭证过期时的访问、注入、错误信息与日志中是否带出个人数据或凭证。

## 3. 数据与威胁清单（建议，一页）

E1 起草，E2 设计对策：

- 个人与敏感数据：收集什么、为什么、存在哪、存多久、谁能看、是否交给第三方或出境；
- 主要威胁：谁、想得到什么、从哪里下手（接口、被篡改的客户端、批量请求、内部人员），后果多大；
- 每个威胁的对策与验证方式。

发布前核对隐私政策与这份清单一致。

## 4. 按需

- **加密与密钥**：用公开审计过的成熟方案与库，不自行设计算法或协议；写明密钥存在哪、怎样轮换、设备丢失怎样处理、服务器仍能看到哪些元数据。加解密与密钥管理的代码列入合入前必须人审的类别。
- **外部 AI 服务**：写明发出哪些数据、供应商是否用于训练、输出是否需要审核；用户输入能影响模型时，不让模型输出直接触发有副作用的操作。
- **大型及以上**：威胁建模评审、外部渗透测试。

## 5. 安全事件

运行手册写明：怎样发现；由谁决定处置；多久内通知谁，包括法规要求通知的用户或监管方；怎样吊销与轮换凭证。接触生产环境按 [OPERATIONS](OPERATIONS.md) §5。
