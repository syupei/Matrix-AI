# 外发任务包

何时读：把一项具体工作交给不在本角色会话里的执行者时，例如编码子任务、外部的前端或设计 Agent、群里的工程师或美术；收到执行者的回交时。

执行者按任务包完成工作；切分任务、集成、检验与各项决定仍由发包方和各责任方承担。人和 AI 用同一种格式。

## 1. 什么样的任务可以单独外发

同时满足四条：

1. **新人测试**：一位有能力的新成员只看任务包，就能做完并自检；
2. 只改一个模块或一组素材，跨模块只经过已定义的契约；
3. 有自己的验收条目或确认标准；
4. 用到的产品规则都已确定，或已标为待定并写明暂时怎样处理。

不满足时，先补契约、规格或验收再外发，不靠多塞项目背景来弥补。

## 2. 任务包

| 部分 | 内容 |
| --- | --- |
| 任务 | 编号、所属上层任务、目标（做完后用户能做到什么） |
| 摘录 | 只抄所需条目的原文：产品规则、设计规格、验收条目、接口契约。每条带来源编号与版本，标"派生、只读"。执行者能读项目文件时，可以改为给条目链接 |
| 性质 | 每条标"必须保持 / 范围内可自定 / 待澄清"（CONTRACT §2）；待澄清的写明暂时怎样处理 |
| 约束 | 只能改哪里、通过什么接口、不得依赖什么、用哪些设计系统组件；新增依赖或外部服务先提请求 |
| 运行环境 | 分支或工作区、怎样运行与测试、测试数据；不放凭证与真实个人数据 |
| 完成证据 | 对应的验收条目、要到哪一层（CORE §2）、需要的截图或录屏 |
| 不提供的背景 | 明确列出，免得执行者去猜 |
| 提问与回交 | 缺信息时找谁问，不自行假定；回交按 §3 |

来源变了，按 CONTRACT §5 通知执行者，只重做受影响的部分。

## 3. 回交包与处理

执行者交回：

- 改动：分支、提交、合并请求或素材文件；
- 运行记录：命令、环境、原始输出；
- 逐条验收的结果与证据层级；
- 做了哪些假设，还有哪些问题；
- 新增的依赖、外部服务或数据外发；
- 与设计或约束的偏差及原因，以及没做的部分。

发包方先核对：新增依赖与外部服务按关键技术选型筛查；设计偏差交设计判断；假设与问题回到责任方。人的回复由发包方整理成回交记录。

回交只算执行者自检：验收由质量验证独立检验，必须人审的代码照常人审，集成与端到端检查由发包方负责。

## 4. 执行者登记

在角色配置中登记（ROLE-CONFIG-TEMPLATE）：

- 专长与自带规范。
- 冲突时谁优先：本项目的契约、验收、设计规格与委托边界优先；模块内的写法、命名与风格按执行者自己的规范。
- 抽查比例：初始按委托边界；按执行者分别记录被推翻的次数与原因，推翻少可以降低比例，推翻多就收紧，调整由人决定。检验与人审不因执行者是人还是 AI 而免除。

## 5. 不外发的

- 决定：产品规则、设计取舍、关键技术选型、契约变更、放宽质量门槛；执行者可以提建议，由责任方决定。
- 集成与发布的责任。
- 凭证、真实个人数据，以及与任务无关的代码和文档。
