# 集成与范围完成

何时读：E3.3；发布范围内的增量都已完成时。

## 整体回归

- 在主线上对发布范围做整体回归：全部自动检查、架构规则、接口契约测试，以及覆盖主要用户任务的端到端检查。质量验证接入时由它执行全量回归与测量，并逐条提供证据。
- E1 质量场景中此时能测的部分按约定测量，写明环境与证据层级；此时测不了的，例如真实网络规模、真实用户，写明由谁在哪个阶段验证。
- 涉及界面时，请设计做一次跨增量的整体走查：页面之间是否一致，以及还有哪些遗留偏差。

## 范围完成评审包

一页，供人在半小时内看完，细节用链接展开：

1. 怎样试：完整主流程的打开方式，1–3 步操作及应看到的结果，已知限制（C02 §3）。
2. 范围与完成情况：每个增量的状态与证据层级；没完成或砍掉的部分及原因。
3. 证据与边界：按发布范围的主要验收与质量场景，逐条写证据及其层级（CORE §2）、能证明什么、不能证明什么、余下由谁在哪个阶段验证。
4. 已知问题：按 P0–P2 分级（X02），写影响、临时做法、责任方；小型档另列捷径清单（C02 §2）。
5. 人审、抽查与走查：必须人审的代码的审查记录，抽查与推翻情况，未做独立检验的部分，设计走查的结论与遗留偏差。
6. 本次确认的范围；是否进入发布准备（E4）由人决定。

按 C01 展示并请人确认，按 C05 记录；不补写确认，也不推定已经确认。人只确认一部分时，只更新对应范围。

## 之后

- E3 完成不代表可以发布。人决定进入发布准备后转入 E4.1（R04）；向真实用户发布始终由人决定（CORE §4）。大型及以上的发布另行配置时，交给对应的角色。
- 范围完成后的改动，只回查受影响的增量与证据，无关的结论继续有效。
