# 发布、观察与交接

何时读：E4.3；批次到点、指标越过阈值或发布后发现问题时；E4.1 起草交接包时。

## 执行发布

- 开始前用阶段检查核对 E4.2 的发布决定（C05）；没有有效的决定就不发布。
- 有授权、且宿主提供了发布通道时由你执行；否则写好逐步操作交人执行，由你核对结果。凭证由宿主或人保管，不写进文件，也不出现在对话中。
- 每批发布后在真实环境中做上线后检查：走一遍主要用户任务，看关键指标与告警，核对数据。写明结果与证据层级（CORE §2），记入发布记录。

## 推进、停止与回退

- 指标在继续条件之内、观察时长已到：按计划推进下一批。人在决定中选了逐批确认时，先请人确认。
- 触发停止条件：立即停止放量，按计划回退，然后报告现象、指标与已做的处理。按计划回退不需要另行请示。
- 需要偏离计划时（改阈值、跳过某批、带着新问题继续）交人决定。
- 发布中发现的新问题由质量验证分级，P0/P1 按停止条件处理。修复后再发布需要新的发布决定，可以合批、从简；修复照常走增量循环与质量验证复验。

## 交接包

| 项目 | 内容 | 怎样核对 |
| --- | --- | --- |
| 源码 | 发布版本对应的提交与标签 | 与发布构建一致 |
| 可编辑的源资产 | 设计源文件、素材源文件 | 与设计的素材登记一致 |
| 依赖与许可证 | 依赖清单和各自的许可证 | 在委托边界允许的范围内（X01 §1） |
| 构建、部署与环境说明、版本锁定 | 工具链与依赖的锁定版本、环境配置与重建步骤（不含凭证） | 由非作者在干净环境中照着构建并重建环境一次 |
| 测试证据 | 发布验收与回归的原始记录 | 链接到质量验证的记录 |
| 运行手册 | 部署、回退、备份与恢复、常见故障的诊断、监控与告警、服务目标、值班与事故处理 | 回退与恢复各演练过一次 |
| 到期与续费清单 | 证书、域名、账号、许可证、付费服务的到期日与负责人 | 逐项核对到期日 |
| 费用告警 | 达到月费上限一定比例时通知运维负责人 | 交接前触发一次测试告警 |
| 已知问题与捷径清单 | 级别、影响、临时办法、负责人 | 与缺陷记录一致 |

- 没核对的项写"未核对"及原因，不写成可用。
- 凭证不进入交接包，只写由谁保管、到哪里申请。
- 小型档只交交付说明（怎样运行或部署、依赖、已知问题）与捷径清单。

## 运维负责人与交接

- 上线后的运维负责人由人指定（C02 §5）。有服务端的产品没有运维负责人就不发布，除非人明确接受。
- 观察期结束后，把交接包交给运维负责人，记录其确认收到的原话；之后的持续运维不在本流程内。
- 发布后收到的问题按 C03 登记。需要改动时按新的变更处理：增量循环、质量验证复验、新的发布决定。

## 完成

按人的决定完成发布（或按决定不发布、只发部分用户），上线后检查通过，观察期结束，运维负责人确认收到交接包。用阶段检查记录 E4.3 → 完成，并更新工作状态。
