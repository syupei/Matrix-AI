# 增量构建工作区模板

建立 `engineering/build/` 下的文件时按需取用；小型档可以合为一份。项目已有的组织方式、ID 和人的修改优先。`{...}` 为填写处，不相关的字段删去；还没形成的成果写"未形成"，不给假链接。

## 00-工作状态.md

```markdown
# 增量构建工作状态

- 负责人：{人员 id，只有一人时写"用户"} / engineering-build
- 当前位置：{增量构建：共 3 步，当前进行第 X 步「名称」；正在进行的增量}
- 工作情况：{…}
- 最新已确认成果：{范围完成评审的版本与范围；没有写无}
- 进行中：{增量与任务卡}
- 在等谁：{人员与事项，如必须人审的代码、回升事项、体验判断；没有写无}
- 下一步：{下一动作或停止原因与恢复}

（以上七行是摘要块，供 PM 汇总，见 TEAM §5；以下为详细状态。）

- 项目/任务：{标识}
- 角色与规则版本：{engineering-build，skill 版本}
- 输入基线：{E2 交接与核心评审记录的位置与版本；产品、设计基线}
- 委托边界：{位置与版本；必须人审的代码类别}
- 本轮完成与阻断：{…}
```

## engineering/build/README.md（多人或中型以上项目；首次建立工作区时写，只放稳定导引）

```markdown
- 这里是什么、给谁看：{…}
- 按读者的阅读顺序：{例如 技术负责人：01 → increments/；产品、设计：02 范围完成评审；工程师：任务卡与代码位置}
- 源文件与生成物：{哪些可以直接修改，哪些由工具生成、不要手改}
- 当前状态：见 00-工作状态.md 开头的摘要块
```

## increments/INC-{n}.md

```markdown
# INC-{n} {用户可见的能力}

## 任务卡 INC-{n}/T-{m}
- 目标：{…}
- 引用：{产品 ID；TD-编号；AC 或场景编号；设计规格}
- 输入与版本：{…}；约束：{模块边界、契约、不得依赖的方向}
- 完成证据：{测试、层级、端到端检查}；检验者：{非实现者}

## 记录
- 变更：{合入、对应的任务卡与测试}
- 自动检查与交叉审查：{结果与发现}
- 非实现者检验：{检验者、逐条结果与证据层级；或"未做独立检验"及原因}
- 端到端检查：{命令、环境、结果}
- 设计走查与人审：{请求、回复与范围}
- 证据与边界：{能证明 / 不能证明 / 余下由谁在哪个阶段验证}
- 怎样试：{打开方式；1–3 步操作及应看到的结果；已知限制}
- 上报：{事项、去向与处理}
```

## 02-范围完成评审.md

```markdown

| 验收或质量场景 | 证据与层级 | 能证明 | 不能证明 | 余下由谁、在哪个阶段验证 |
| --- | --- | --- | --- | --- |

4. 已知问题与捷径：{级别 P0–P2、影响、临时做法、责任方}

6. 本次确认范围；是否进入发布准备：{由人决定}

## 确认记录
| 日期/记录 | 范围与版本 | 实际回应 | 快照 |
| --- | --- | --- | --- |
```
