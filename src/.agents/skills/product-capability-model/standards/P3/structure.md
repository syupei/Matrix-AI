### 8.1 覆盖与内部边界

三组敏感内部边界按以下口径分责：

概念命名 / 用户语境：产品正式概念与稳定名称 / 具体用户和场景中的表达调整；

状态表达 / 复杂转译：当前事实、结果与直接原因 / 规则、限制、例外与修复路径；

复杂转译 / 语境与吸引：复杂内容如何说清 / 对当前用户如何说得进去。

### 8.2 与相邻一级能力的边界

| 相邻能力 | 该能力主责 | P3 主责 |
| --- | --- | --- |
| P1 产品逻辑 | 规则、对象、状态和结果是什么 | 如何让用户理解这些事实；不用表达掩盖未定义的逻辑 |
| P2 认知与心理引导 | 用户形成何种理解、预期、感受和行为 | 为支持这些目标采用什么具体表达方式；允许强关联 |
| P4 空间与结构 | 信息在哪里，如何分类、分层、排序、连接和到达 | 信息叫什么，如何被表达 |
| P7 感知体验设计 | 文字的外在表现及图标、颜色、动效等非文字表达如何被感知 | 文字内容本身如何表达事实、倾向与引导 |

六项能力会对用户认知、情绪和行为产生影响，这是正常的产品协同，不构成删除 P3 能力的理由。只要专业判断仍聚焦“具体如何表达”，就不侵入 P2 对理解目标和行为机制的主责。

### 8.3 表达吸引性的范围

“表达吸引性 / 可接受性”应保留在 P3：

用户不愿意读的信息，即使字面准确，也没有完成实际意义传递；

语气、句式、节奏、信息密度和叙述入口是语言表达的内在属性；

只追求字面严谨，会产生政府公文或科研报告式表达，把内部严谨的成本转嫁为用户的理解负担；

保留吸引性不等于把 P3 改造为营销文案能力，它仍受事实准确、用户知情与不操纵边界约束。

是否属于营销，不能仅根据表达是否存在倾向判断。产品对行为收益的明确告知、对风险的突出提醒和对合理下一步的引导，本就是产品设计的一部分。

### 8.4 遗漏检查

六项能力同时从“表达对象”与“跨对象质量”两个方向形成完整覆盖：

| 待解决的表达问题 | 主责能力 |
| --- | --- |
| 价值、对象、角色、能力和分类如何形成稳定概念 | 产品概念命名 |
| 行动、选择、作用对象、收益与风险如何表达 | 动作语义设计 |
| 当前事实、结果、原因、影响与下一步如何表达 | 状态语义表达 |
| 规则、专业信息、限制、异常、指引与修复路径如何说清 | 复杂信息转译 |
| 概念和语言如何在产品内外、跨场景与跨时间保持一致 | 产品语言一致性 |
| 上述所有内容如何面向当前用户说得进去、愿意被读取和接受 | 用户语境适配与表达吸引 |

用户语言研究是六项能力的共同输入，不需要再设立独立能力；标题、标签、按钮、说明、错误与结果文案都可根据其主责问题归入前四项；语气、句式、节奏和信息密度归入第六项。未发现仍无法解释的重大文字表达对象。

### 9. V1.0 结构验证与冻结结论

P3 二级能力树冻结为：

1. 产品概念命名能力

2. 动作语义设计能力

3. 状态语义表达能力

4. 复杂信息转译能力

5. 产品语言一致性能力

6. 用户语境适配与表达吸引能力

正式展开与案例回验确认：

六项能力对文字表达对象与跨对象质量形成完整覆盖，十类跨类型案例未发现需要新增第七项能力的结构性缺口；

复杂信息转译与用户语境适配不因与 P2 关联而删除；

表达准确性、易理解性、语境适配性与吸引引导性必须同时进入质量判断；

表达可以包含合理产品价值倾向和行为引导，不因存在倾向而自动归入营销；

产品语言一致性同时覆盖产品内部共同概念、对象命名、动作与状态描述，以及面向用户的跨界面语言；

非文字语义和文字外在表现形式暂不纳入 P3 重点，已转为 P7 的明确研究待办。

与相邻一级能力的主责边界成立：P1 定义产品事实，P2 定义用户应形成的理解、预期与行为条件，P3 定义具体如何用文字表达，P4 定义信息如何分类、分层、排序与到达，P5 定义行为闭环，P6 定义时间过程，P7 定义文字外在表现和非文字感知。各能力可以共同影响用户认知和行为，但未形成主责冲突。

六项能力已按“能力定义、核心问题、关注重点、为什么重要、常见错误、简洁案例、与相邻能力边界”统一模板完成正式展开，并通过 Apple、微信、Google、ChatGPT/AI、Booking/Agoda、航空旅行、银行支付、Google Home、Microsoft 365 和 Microsoft Teams 案例回验。

案例回验重点检查结果：

1. “用户语境适配”与“产品概念命名”可按正式概念 / 当前用户表达稳定分责；

2. “复杂信息转译”足以承接规则说明、异常解释、指引与修复路径；

3. “表达吸引”可按是否促进真实理解、是否保留知情条件与风险进行专业判断，不依赖营销效果或风格偏好；

4. 六项能力在不同产品类型与高低风险场景中保持完整性与一致粒度；

5. 产品内部语言与用户界面语言的一致映射可通过共同词汇、跨渠道检查和版本迁移观察与治理。

据此，六项二级能力的名称、顺序、基本定义与主要边界自 2026-08-24 起冻结为 V1.0。当前不进入能力分级、评分或职级行为标准设计；只有后续正式评审出现结构性反证时，才重新打开冻结结构。
