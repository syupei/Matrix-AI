# P3-5 产品语言一致性能力

### 6. 产品语言一致性能力

能力定义

建立并维护产品的核心概念、对象命名、动作、状态和表达规则，先在产品内部形成共同且可追溯的语言体系，再使其与面向用户的界面语言建立稳定映射，并在不同功能、页面、通知、终端、角色和版本中保持一致含义；当事实或用户语言变化时，管理改名、废弃、迁移、兼容与语义债务。

一致不意味着所有场景使用完全相同的句子，而是同一概念保持同一含义，场景化表达不改变事实边界。

核心问题

同一对象、动作和状态是否在不同入口保持一致语义？

产品、设计、研发、运营和客服对核心概念、对象、动作和状态是否使用同一套语言？

产品内部概念与面向用户的表达是否保持稳定、可追溯的对应？

“收藏”“保存”“标记”是不一致命名，还是真实不同的动作？

页面、通知、邮件、帮助与客服是否共享同一套概念？

改名或规则变化时，如何保护用户已经形成的理解？

关注重点

核心概念、对象、动作和状态是否有唯一、可追溯的正式含义；

产品内部不同专业角色能否基于共同语言讨论同一产品事实；

内部产品概念与面向用户表达之间是否存在稳定映射；

场景化措辞变化是否保持概念边界和结果含义不变；

页面、通知、邮件、帮助、客服、不同终端和角色视图的一致性；

新功能、改名、合并、拆分和废弃时的迁移、兼容与过渡说明；

同义多名、同名异义、历史残留和局部特例形成的语义债务。

为什么重要

产品语言不是单个界面的文字集合，而是用户长期理解产品的共同坐标系。语言在入口、团队或版本之间漂移，会迫使用户反复确认同一概念，也会让产品内部对对象和规则形成不同解释。稳定的语言体系能够积累用户理解、支持跨团队协作，并让产品演进时的变化可解释、可迁移。

常见错误

只维护界面文案规范，不建立核心产品概念及其正式含义；

各团队按局部场景独立命名，造成同一事实多种说法；

强求所有句子字面一致，忽略不同语境需要适当调整；

产品内部概念与用户语言没有映射，导致功能演进时含义失控；

改名后只更新主页面，遗漏通知、帮助、客服话术和历史记录；

为兼容旧称长期叠加别名，却不治理语义债务；

把真实不同的对象强行统一命名，造成表面一致、事实混乱。

简洁案例

将“工作区”改名为“团队空间”时，在过渡期显示“团队空间（原工作区）”，同步更新页面、通知、帮助与权限说明，并保留旧链接和历史记录的可解释性。

与相邻能力边界

前四项负责单个概念或场景中的表达质量，本能力负责产品内外、跨场景和跨时间的语义稳定。P1 决定事实如何演进，本能力决定变化如何进入产品内部与用户语言系统。这里的“内部语言”是产品概念与语义的共识，不要求数据库字段或技术实现采用同样字面。
