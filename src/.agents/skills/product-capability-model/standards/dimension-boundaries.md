# 七大能力的维度边界说明

> 《产品领域专家能力要求模型》总纲 V0.2 原文，按章节拆分，正文未改写。

## 维度边界说明

版本：V0.2状态：一级边界已冻结

### 1. 文档目的

本文档用于说明产品本体七大能力的主责问题、相互关系和常见边界，避免后续拆解二级能力时重复建设。

能力维度是观察和判断产品的专业视角，不是组织岗位、交付物或严格串行的工作流程。

### 2. 七大能力的核心边界

| 能力 | 主要回答 | 不主要回答 |
| --- | --- | --- |
| 产品逻辑 | 产品为何存在、为谁服务，由什么构成并按什么规则运行 | 某个按钮如何操作 |
| 认知与心理引导 | 用户为什么能理解、接受并完成行为 | 具体使用哪个词或哪种反馈样式 |
| 语义与表达 | 产品如何用用户熟悉的语言表达 | 信息和入口放在哪里 |
| 空间与结构 | 信息、功能和对象如何组织与到达 | 内核规则和具体视觉风格是什么 |
| 交互与反馈 | 用户如何表达意图，系统如何回应 | 反馈通过哪种感官形式呈现 |
| 过程与状态 | 产品如何随时间变化，用户如何经历这一过程 | 技术为什么慢，如何优化性能 |
| 感知体验设计 | 状态、层级、重点、品质和情绪如何被感知 | 对象规则、交互机制或专业视觉制作 |

### 3. 主责判定原则

一个真实产品问题可以同时涉及多项能力。归属时不按界面元素或交付物判断，而按“当前要解决的主要问题”判定主责：

1. 先明确问题主体和设计目的；

2. 再选择直接回答该问题的主责能力；

3. 其他能力可作为支撑或约束，不必强求唯一标签；

4. 同一设计元素可服务于不同能力，归属取决于其设计目的。

### 4. 高频边界说明

### 4.1 产品逻辑与过程与状态

产品逻辑定义对象有哪些状态、哪些转换合法、转换导致什么结果；

过程与状态关注这些状态如何随时间发生，以及用户如何经历等待、进展、中断、失败和恢复。

例如，会议邀请可否从“已接受”回到“待回复”是产品逻辑；修改时如何告知用户当前阶段及后续变化，是过程与状态。

### 4.2 认知与心理引导与语义与表达

认知与心理引导关注用户的心智模型、预期、负担、动机和风险感知；

语义与表达关注用什么概念、命名和文案准确传达信息。

例如，删除前是否需要强确认，主要取决于风险预期与心理负担；按钮应叫“删除”还是“移到回收站”，主责是语义与表达。

### 4.3 空间与结构与感知体验设计

空间与结构决定信息、功能和对象的分类、层级、入口和导航关系；

感知体验设计决定这些层级和重点如何通过视觉、声音、触觉或动效被感知。

例如，“会议记录应从哪里进入”属于空间与结构；“当前记录如何在列表中被视觉突出”属于感知体验设计。

### 4.4 交互与反馈与感知体验设计

这是最容易重叠的一组边界：

交互与反馈关注“行为关系”：用户如何操作，系统何时、以什么结果回应，能否取消、撤销或修正；

感知体验设计关注“感官通道”：该回应通过何种颜色、形态、声音、震动或动效被用户感知。

例如，按钮点击后应立即进入处理中并防止重复提交，属于交互与反馈；处理中是通过按钮形态、动效还是震动表达，属于感知体验设计。

### 4.5 交互与反馈与过程与状态

交互与反馈关注一次或一组用户行为如何形成闭环；

过程与状态关注任务跨越时间后的阶段、转换和连续体验。

例如，用户点击“生成报告”后系统立即确认接收，是交互与反馈；报告经历排队、生成、完成或失败，以及用户中途离开后如何继续，是过程与状态。

### 5. 技术与产品边界

技术实现慢、资源占用高或架构不合理，属于工程与技术性能问题。当一项功能客观上需要 4 秒时，如何让用户理解正在发生什么、预期还需多久、能否离开，并安全地继续任务，属于产品问题。

两者应同时被正视，但不应混为同一能力或相互替代。

### 6. 模型总边界

七大能力是产品本体能力，不是 UX/UI 能力模型，也不覆盖商业、市场、增长、运营、组织管理、项目交付、技术架构和技术性能。这些领域可与本模型组合使用，但需保持定义与评价边界。
