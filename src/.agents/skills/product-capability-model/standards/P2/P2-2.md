# P2-2 认知负担控制能力

### 3. 认知负担控制能力

能力定义

识别用户在完成具体任务时需要投入的注意、理解、比较、记忆、回忆与规则学习成本，区分必要复杂性与可由产品承担的不必要复杂性，并根据用户经验、任务目标、使用情境和风险水平，使认知投入保持在合理范围内。

认知负担控制不是简单减少内容、选项或步骤，而是让用户只承担完成目标和作出必要判断所需的心理工作。低风险任务应避免无意义打断；高风险任务则不能为了表面简洁而隐藏关键信息。

核心问题

用户此刻必须注意、理解、比较和记住什么？

哪些复杂性来自任务本身，哪些只是产品内部结构被转嫁给用户？

当前信息量、选项数和规则学习是否超过用户在此情境中的认知资源？

用户是否必须跨页面、跨时间或凭记忆拼接关键信息？

减少步骤是否真的减少心理成本，还是增加了判断和风险？

产品应在何时分步、延后、提供默认、保留上下文或提供外部记忆支持？

关注重点

注意竞争、信息过载、选择过多与主次不清；

工作记忆负担、跨步骤记忆和重复回忆；

概念、规则、状态和操作方式的学习成本；

必要信息与非当前信息的区分；

新手与熟练用户、低频与高频任务的负担差异；

任务风险、时间压力、疲劳和设备环境对认知资源的影响；

由产品承担默认、计算、保存、关联和回忆的可能性。

为什么重要

人的注意和工作记忆有限。产品把内部复杂性、无关选择和跨步骤记忆转嫁给用户，会使理解、判断和行动同时变差。认知负担控制能够让复杂产品仍然保持简洁，但这种简洁来自合理取舍和产品承担复杂性，而不是删除用户作出知情判断所需的信息。

常见错误

把页面留白多、字少或步骤少直接等同于认知负担低；

一次展示所有能力，要求用户在真实需要出现前完成学习；

让用户记住上一页信息、内部规则或系统生成的临时编号；

提供大量近似选项，却缺少与用户目标相关的区别；

对所有场景增加同等强度的确认，造成注意疲劳；

过度使用默认和自动化，省去步骤却让结果难以理解；

为熟练用户持续保留强制引导，或让新手直接面对专家复杂度。

简洁案例

搜索任务的起点只要求用户表达当前查询，而不是先选择内容类型、排序方式和高级范围。必要的筛选可以在结果出现后按需提供。产品没有消除搜索的真实复杂性，而是让用户在每个阶段只承担当前必要的判断。

与相邻能力边界

“用户心智模型理解能力”判断用户如何解释概念和行为；本能力判断这种理解过程需要投入多少认知资源；“用户行为动机与引导能力”判断负担如何阻碍开始或继续行动。信息如何分组、分层和排序属于“空间与结构”；具体措辞属于“语义与表达”；视觉如何突出重点属于“感知体验设计”。
