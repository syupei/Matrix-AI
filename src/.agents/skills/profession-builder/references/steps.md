# 步骤与写法

何时读：创建或修改专业的每一步开始前。要写清的项目见 C23 §1；这里写怎样写、参照哪里。现有专业的登记在 `collaboration/professions/`，可以对照。

## 1. 范围

- 标识用小写英文与连字符，例如 `content-design`；名称用中文。类别四选一：调度、定义、制作、保障与审查。
- "处理什么"写三到五条能据以判断归属的问题；"不处理什么"写明交给哪个专业。参照内容设计与审读：程序内部的异常归代码工程，法律条款的内容归法务。
- 参与条件写成能对照项目描述判断的事实，例如"产品有面向最终用户的文字时参与"，供启动引导推荐。
- 接管：新专业接过现有专业的部分职责时，列出被接管专业要改的文件与条目、改后的说法，写进创建提案；登记里只写接管后的范围。

## 2. 成果、标准与决定

- 每类成果写一个正式来源；别处引用版本，不复制正文。
- 写本专业的复用单位（登记的"复用"）：同一结构、只是数据或文字不同的成果怎样做成一份。
- 写输入（登记的"输入"）：每个阶段需要上游的哪个阶段、到什么状态；条目输入默认按上游风险，只能更严。
- 评判标准引用能力标准或行业标准，并写明"什么算好"能怎样检查。
- 阶段与人审点写成 `stage_flows`：阶段编号、人审的阶段、需要的上游阶段。阶段编号写成 `缩写-序号`，例如 `Q-1`，子步骤写成 `Q-1.1`；缩写写在登记的 `abbr`，各专业之间不重复。阶段检查直接读取这里；改了要跑阶段检查的测试。没有阶段关卡的专业写空列表。
- 决定权分三类：自己能定的；交人或交其他专业的；有约束力的结论（别的专业不能改，只能提请求）。

## 3. 职级与对照

- 先定使用的 T 段与 master 的最低职级，再逐级写能做、能判断、不能做；按自主、复杂、范围、知识四个方面逐级递进（C21）。
- "不能做"写越权的具体事，例如"改变产品规则的含义"，不写"超出能力"。
- 风险 F 与缺陷 Q 每一级至少一个本专业的例子；确实不会出现的级别写"一般不会出现"，并说明按什么定级。例子按 C22 的后果表定，不改级别的含义；涉及法律、数据与安全、资金的，不因少见而降级。

## 4. 技能

- 入口按骨架 T03：启动、工作流、硬性关卡、职责边界、完成的含义。入口只写判断与流程，细节放参考文件，每份写明"何时读"。
- 指引索引只列本专业的指引，加一行 L01 指向本专业的职级与对照；共用规则用 C 编号引用。
- 工具与模型能力写需要的能力，例如"能看图""选项式提问"。

## 5. 评测

- 按模板 T04 写情境：用户原话、能打分的判据（每条 0 或 1）、每条判据怎样算通过。
- 至少覆盖每个人审点、最常见的两三个风险，以及一个越权的诱导（例如用户要求替人决定）。
- 另外通过底座情境，每个专业都要过：
  - "继续"、沉默或旁人的意见不算确认；
  - 说"通过"时写明证据到了哪一层；
  - 不声称已运行、已发送或已启动；
  - 超出本专业或本职级的要求，交给有权决定的一方；
  - 风险 F0 交人判定，F1 的成果与 Q0、Q1 缺陷主动告知。

## 6. 检查与接入

- 运行 S01：登记完整、职级与对照、阶段数据、技能与索引、字数预算、总入口是否最新。
- 运行 S02 重新生成总入口的专业目录，不手工编辑那一段。
- 被接管的专业按接管清单修改，改动按 C04 交给它的负责方采用。
- 评测通过后，才在结果里写"已接入"；未评测的范围照实写。
