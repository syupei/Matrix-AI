# 情境案例与校准

何时读：把口吻要求转成判据、校准样板、做案例回归时。

案例用于学习判断方法和作者走查，不是用户认可的统一成稿，也不是已执行的测试；不增加业务功能，不成为全项目模板。先核对适用条件，再结合实际页面改写。内部核查口吻的转译示例见 [COPY-QUALITY](../../../../collaboration/COPY-QUALITY.md)。

- 留言入口："立即开启交流，释放你的表达潜能"改为"写留言"。操作名说清动作，页面已清楚时不加宣传。
- 确认区已指明对象、删除不可恢复：标题"删除这条留言？"加正文"删除后无法恢复。"可只留"删除后无法恢复"，按钮"取消 / 删除"；要核对对象辨识和可访问名称，不是给第二句换词。此例对应用户确认的要求"符合要求前提下尽量精简，避免冗余影响视觉与判断"，写法本身未经逐条认可。
- 批量删除：写出实际数量或范围（取自实际选择），不套用单条的短文案。
- 确定没发出且重试安全："操作未达预期，请再次尝试执行提交操作"改为"没发出去"配"重试"，整组不重复劝重试。结果未知时不能写成失败：说明尚未确认，给实际支持的查询或恢复；确认安全前不承诺可重试。
- 规则是等待审核：写"已提交，等待审核"，不写"发布成功"；轻松口吻不改变业务结果。
- 只有图标：为辅助技术保留准确的动作名称，视觉精简不删必要语义。
- 名称："为 X 公司做用户交流平台"给出服务对象和用途，不等于产品名已定为"X 用户交流平台"。推演时写"用户交流平台（暂称）"，再按受众、价值和文风推荐；"X 友会"之类只是示意。用户明确"正式名称就用用户交流平台"时按确认范围保持。审读看依据、状态是否真实、概念 ID 与引用是否一致，不以创意代替准确。

## 校准与回归

- 从项目真实失败中选代表案例，保存修改前后的完整页面与状态语境及源版本；先按需求独立写出或审读，再对照认可样板，条件不同不套答案。
- 规则、模型或生成方式变化时重查受影响案例，再用未参与调整的新案例检验；记录实际输出和失误。本文件案例只是已知样本，参考答案存在不等于测试通过。
- 分别标明自审、独立审读、人审和真实用户结果。
- 项目接入模型评估器时先用人的判断校准，设明确的通过和失败条件；解析或运行失败不算通过，事实错误和关键后果缺失不能被文风分数抵消。本包不提供自然度自动认证。
