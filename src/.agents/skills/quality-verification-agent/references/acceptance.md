# 验收条目与覆盖

何时读：Q1 建立验收计划；续做；来源变化或收到变更通知时。

## 输入

- 产品 ACCEPTANCE：验收场景（角色、前提、动作、预期与不可接受的结果）、覆盖与优先级、验证接力。
- 研发承接的工程需求与质量要求（带编号与条件）。
- 设计交付说明中的"QA 对应"：设计条目、页面与状态到 AC 的映射，可观察的期望与不允许的结果。
- 技术方案：决定的验证与推翻条件、接口契约、测试策略。

缺失或互相矛盾时按 C04 回到维护方，只暂停受影响的条目。

## 验收条目

| 字段 | 内容 |
| --- | --- |
| 编号与来源 | TA-编号；对应的 AC、质量要求或 TD 决定 |
| 来源版本 | 来源文件与条目，以及建立时的文件摘要（`python3 collaboration/tools/stage_gate.py --project . --digest <文件>`） |
| 场景 | 前提、步骤、数据（固定的随机种子或样例；不用真实个人数据） |
| 关闭条件 | 可观察的结果，以及不允许出现的结果 |
| 必需证据 | 要到哪一层（CORE §2），留什么记录：命令、日志、原始样本 |
| 执行方式 | 可执行测试的位置，或由你操作版本的步骤 |
| 状态 | 未写 / 已写 / 通过（附层级）/ 未通过 / 待复核 / 未接入 |

- 先覆盖核心任务、规则与用户损害大的场景，再按适用性补异常、权限拒绝、边界值、重复提交、中断恢复、并发、跨端。每个有归属的对象，至少一条在接口层检验的越权条目：别人的看不到、改不了、删不掉（C06 安全 §2）。
- 能自动化的写成验收测试，放在技术方案约定的位置（默认是 `code/` 下单独的验收目录）；其余写成你操作版本的步骤。

## 覆盖表

- 发布范围内的每条 AC 与质量要求，至少对应一个验收条目，或写明不适用、留给发布或真实用户验证的理由。表中能直接看出缺口。
- 覆盖表记下每个来源文件的摘要。

## 来源变化

- 每次检验前（Q2、Q3）和续做时，重新计算来源文件的摘要，与覆盖表比对。摘要变了：找出变化的条目，把相关验收条目标为"待复核"，复核或改写后再用，并定回归范围（R03）。
- 产品、技术方案、增量构建改动已交出的内容时，应按 CONTRACT §5 通知你。通知与摘要比对，任一发现变化都要处理。
- 摘要变了、条目没变时，记录"已核对，无影响"，更新摘要。
