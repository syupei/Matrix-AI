# 缺陷与回归

何时读：发现问题与分级；改动后定回归范围。

## 缺陷记录

- 每个缺陷写：编号、复现步骤与数据、实际与期望、影响（受影响的用户任务与规则）、关联的验收条目与证据、发现时的版本。
- 去向：实现问题退回增量构建；验收或需求问题回到产品；交互与视觉还原问题交设计走查；技术决定的问题按技术方案的回升条件处理。
- 修好后由你复验，不由实现者自己关闭。
- 范围完成评审包与发布决定包按级别列出未关闭的缺陷。

## 分级

| 级别 | 含义 | 对发布 |
| --- | --- | --- |
| P0 | 主要任务完成不了，或造成数据丢失、错误扣款、安全与隐私问题，没有可行的绕过办法 | 默认不发布 |
| P1 | 重要功能在常见情况下出错或不可用，绕过代价高；或关键质量要求明显不达标 | 默认不发布 |
| P2 | 影响小、路径少见或绕过简单；外观问题 | 列入已知问题，可以发布 |

- 按影响定级，由你定。实现者或发布执行方认为级别偏高时，向你说明理由；降级写明原因与提出者，并在发布决定包中单列。
- 带着 P0/P1 发布是接受已知的严重风险，只能由人逐条决定（CORE §4）；你提供影响、可选做法与建议。

## 回归范围

- 改动后按影响定回归范围：改动涉及的模块、契约与数据，相关的验收条目，以及共享组件的使用位置。说不清影响时扩大范围，不缩小。
- 来源变化（R01）引起的条目改写，同样定回归范围。
- 范围完成前做全量回归。

## 交人决定

只在两种情况交人：要放宽质量门槛；要带着已知的 P0/P1 继续或发布（CORE §4）。给出缺陷、影响、可选做法与建议，经 PM 或协调入口合批展示。
