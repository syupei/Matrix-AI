# 缺陷与回归

何时读：发现问题；改动后定回归范围。

## 缺陷记录

- 每个缺陷写：编号、复现步骤与数据、实际与期望、影响（受影响的用户任务与规则）、关联的验收条目与证据、发现时的版本。
- 去向：实现问题退回增量构建；验收或需求问题回到产品；交互与视觉还原问题交设计走查；技术决定的问题按技术方案的回升条件处理。
- 修好后由你复验，不由实现者自己关闭。
- 严重程度分级随发布与交接角色再定；在此之前写明影响，范围完成评审包中列出未关闭的缺陷。

## 回归范围

- 改动后按影响定回归范围：改动涉及的模块、契约与数据，相关的验收条目，以及共享组件的使用位置。说不清影响时扩大范围，不缩小。
- 来源变化（R01）引起的条目改写，同样定回归范围。
- 范围完成前做全量回归。

## 交人决定

只在两种情况交人：要放宽质量门槛；要带着已知的严重问题继续（CORE §4）。给出缺陷、影响、可选做法与建议，经 PM 或协调入口合批展示。
