# 协作与反馈

何时读：首次接入项目；发出或收到跨角色请求；反馈涉及 E1–E3 时。

请求、返回、授权、版本与合并按 [CONTRACT](../../../../collaboration/CONTRACT.md) 和 [请求与返回模板](../../../../collaboration/REQUEST-RESPONSE-TEMPLATE.md)；本角色的配置登记示例见 [ROLE-CONFIG-TEMPLATE](../../../../collaboration/ROLE-CONFIG-TEMPLATE.md) §2。

## 发出与接收

- 没有可用通道时，把请求存到项目 `collaboration/requests/`，标"已准备、未发送"，写明由谁读取、在哪回复、怎样恢复；人可以用文件接力回传。
- 请求中不发送私人会话、凭证或本项目之外的记忆。
- E1 只更新工程派生与引用；产品或设计的修改由其维护方合入。
- 一个执行者经用户允许依次承担多个角色时如实记录；没有实际执行其他角色，不说产品或设计已审过。没有产品实例时保留问题和候选建议，不自问自答制造上游确认。

## 反馈归入 E1–E3

按 [FEEDBACK-PROTOCOL](../../../../collaboration/FEEDBACK-PROTOCOL.md) 处理，本角色的处理时点：

| 反馈内容 | 处理时点 |
| --- | --- |
| 目标、范围、业务事实、使用端变化 | 立即评估来源和相关模型，必要时回产品或设计，局部阻断 |
| 模型语义、关系、状态、工程需求修正 | 当前 E1.2/E1.3 处理，已过阶段也主动回查 |
| 技术路线、框架、架构选择 | 记为 E2 决策入口；其中真实的硬约束现在纳入 |
| 编码、优化、部署细节 | 记为 E3 触发与依赖；会改变当前行为或质量目标的部分现在处理 |
| 新证据、确认、审阅意见 | 在 E1.4 或当前回查中核对范围与版本，更新结论 |

新记录补 E1 子环节、来源、范围、目标阶段、触发、责任方或"未接入"、解除条件。后续角色实际接收前由 E1 保留跟进，不以"已交给 E2"关闭。
