# 技术评审（委托优先）

何时读：E2.1 取得或修改技术委托边界；E2.2 判断决定是否为关键技术选型；E2.4 准备核心评审；E3 引入新的存储、第三方组件或算法时；E3 或其他角色要求改变已确认的决定时。

默认采用委托优先：人先划定边界，AI 在边界内作决定；人在 E2 出口看一页核心评审包，并处理例外。高风险项目或首次涉足的领域，人可以改为标准模式，即"必须确认"与"条件确认"两级逐项由人确认。

## 1. 技术委托边界

边界在团队或项目层设定，项目可以覆盖团队的设定。没有边界时，由你按团队已有规范与项目约束起草，经人确认后生效。修改边界只能由人决定。边界包括：

- 技术栈白名单与版本策略：认可的语言、框架、数据存储等；
- 允许使用的供应商与服务；
- 费用上限：按月计，可按档位区分；
- 允许使用的许可证范围；
- 安全与数据底线：数据存放地域、个人信息处理、认证方式；
- 各档位的最低质量门槛；
- 回升条件：默认见 §3，可以增加；
- 合入前必须人审的代码类别（默认：支付、账号与权限、个人信息、不可回退的数据迁移）与事后抽查的比例。

边界保存在 `engineering/技术委托边界.md`（项目已有位置时沿用），记录确认者、日期与版本。

## 2. 各级决定怎样处理

| 级别（C02 §5） | 委托优先下的处理 |
| --- | --- |
| 必须确认 | 边界内由你决定并记录；边界外逐项交人确认 |
| 条件确认 | 由你决定，经独立复核；人可以展开或收回 |
| AI 自主 | 只记录 |

关键技术选型列在核心评审包第一节，其余委托给你的决定列入"已委托清单"。

不可委托的四项见 CORE §4。多人项目中，核心评审交给技术决定人；涉及费用、风险接受与对外发布的事项，交给对它们有决定权的人（见 TEAM）。

### 关键技术选型

不论级别，命中下面任何一问的决定都是关键技术选型：

1. 以后改代价大：要迁移数据、让用户强制升级，或重写多个模块；
2. 改变用户能感知的行为或承诺：时延、离线、顺序、隐私、可用性、费用；
3. 带来费用、供应商绑定或许可证约束；
4. 涉及安全、个人数据，或把数据交给第三方；
5. 影响谁能维护：团队是否熟悉、以后能否找到人；
6. 决定上线后谁来运行、运行成本是多少。

常见类别：存储与数据；算法与策略；语言、框架与架构形态；第三方组件与服务；通信与接口；身份、权限与安全；部署、运行与成本；数据演进与版本兼容；外部 AI 服务；日志中的个人数据；发布渠道与更新方式。改变用户可见结果的算法与策略回到产品决定（C02 §5）。普通工具库与模块内实现不列入，按原级别处理。

## 3. 回升条件

即使已经委托，下列情况也交人决定：

- 超出费用上限；
- 需要范围外的许可证或商业授权；
- 账号、支付或个人信息的安全方案发生变化；
- 推翻已确认的决定；
- 数据迁移不可回退；
- E3 中新增的选型是关键技术选型（§2），例如新的存储、新的第三方服务或会外发数据的组件、改变行为语义的算法；
- 实测推翻了原决定，例如目标设备性能不达标、需要换技术；
- 独立复核的结论与你的结论冲突，且无法消除。

## 4. 独立复核

核心评审前，由不参与方案制作的复核者只读检查决策记录、试做与骨架证据，任务是找反例。重点看：

- 成本与供应商锁定；
- 安全与数据；
- 可运维性；
- 熟悉度偏差：是否只因为常见就选了某项技术；
- 与产品承诺、E1 模型是否一致；
- 漏列：有没有该列入关键技术选型而没有列的。

宿主支持只读子任务时使用；不支持或项目停用时，如实记录"未做独立复核"。复核由 AI 完成、没有人工技术审查时，写明"由 AI 复核"。

## 5. 核心评审包

评审包只有一页，供人在半小时内看完，细节用链接展开：

1. 关键技术选型（§2）：每项一行，写选了什么、还考虑过什么、后果（成本、维护、以后改的代价、对体验的影响）、依据（试做或骨架的证据）、推翻条件。边界外的项与回升事项给出选项与推荐，请人选择；边界内已定的标"边界内"，人能看到，不另做决定。中型项目一般 5–15 项，超过时按主题合并。
2. 怎样试：骨架或可玩原型的打开方式，1–3 步具体操作及应看到的结果，已知限制（C02 §3）。
3. 证据与边界：主要风险与关键质量场景逐条写证据及其层级（CORE §2）、能证明什么、不能证明什么、余下由谁在哪个阶段验证；尚未消除的风险及处理建议。
4. 独立复核的发现与处理。
5. 已委托清单：其余委托给你的决定，每项写标题、级别和一句话理由，人可以展开或收回任一项。
6. 本次确认的范围与不在范围内的事项；待决的产品规则及其在实现中的处理。

按 C01 展示并请人确认；按 C05 记录请求与回应，不补写确认，也不推定已经确认。人收回某一项时，该项改为逐项确认，其余不受影响。

## 6. 评审之后

- 已确认的决定成为 E3 必须遵循的约束。之后需要改变时，只对受影响的条目做变更评审。
- 边界中列为必须人审的代码，由增量构建在合入前交人审。其余已委托的决定与代码，人事后按比例抽查，记录推翻的次数与原因。推翻少时可以放宽抽查比例与边界；推翻多或出现严重遗漏时收紧。调整边界由人决定。
