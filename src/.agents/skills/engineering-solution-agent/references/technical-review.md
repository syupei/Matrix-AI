# 技术评审（委托优先）

何时读：E2.1 取得或修改技术委托边界；E2.4 准备核心评审；E3 或其他角色要求改变已确认的决定时。

默认采用委托优先：人先划定边界，AI 在边界内作决定；人在 E2 出口看一页核心评审包，并处理例外。高风险项目或首次涉足的领域，人可以改为标准模式，即"必须确认"与"条件确认"两级逐项由人确认。

## 1. 技术委托边界

边界在团队或项目层设定，项目可以覆盖团队的设定。没有边界时，由你按团队已有规范与项目约束起草，经人确认后生效。修改边界只能由人决定。边界包括：

- 技术栈白名单与版本策略：认可的语言、框架、数据存储等；
- 允许使用的供应商与服务；
- 费用上限：按月计，可按档位区分；
- 允许使用的许可证范围；
- 安全与数据底线：数据存放地域、个人信息处理、认证方式；
- 各档位的最低质量门槛；
- 回升条件：默认见 §3，可以增加；
- 人事后抽查的比例。

边界保存在 `engineering/技术委托边界.md`（项目已有位置时沿用），记录确认者、日期与版本。

## 2. 各级决定怎样处理

| 级别（C02 §5） | 委托优先下的处理 |
| --- | --- |
| 必须确认 | 边界内由你决定并记录，列入核心评审包的"已委托清单"；边界外逐项交人确认 |
| 条件确认 | 由你决定，经独立复核；列入"已委托清单"，人可以展开或收回 |
| AI 自主 | 只记录 |

不可委托的四项：改变委托边界、接受已知的严重风险、实际花钱与签约、向真实用户发布。

## 3. 回升条件

即使已经委托，下列情况也交人决定：

- 超出费用上限；
- 需要范围外的许可证或商业授权；
- 账号、支付或个人信息的安全方案发生变化；
- 推翻已确认的决定；
- 数据迁移不可回退；
- 实测推翻了原决定，例如目标设备性能不达标、需要换技术；
- 独立复核的结论与你的结论冲突，且无法消除。

## 4. 独立复核

核心评审前，由不参与方案制作的复核者只读检查决策记录、试做与骨架证据，任务是找反例。重点看：

- 成本与供应商锁定；
- 安全与数据；
- 可运维性；
- 熟悉度偏差：是否只因为常见就选了某项技术；
- 与产品承诺、E1 模型是否一致。

宿主支持只读子任务时使用；不支持或项目停用时，如实记录"未做独立复核"。复核由 AI 完成、没有人工技术审查时，写明"由 AI 复核"。

## 5. 核心评审包

评审包只有一页，供人在半小时内看完，细节用链接展开：

1. 边界外的决定与回升事项：逐项给出选项、推荐与后果。
2. 可运行骨架与主要风险的实测证据；尚未消除的风险及处理建议。
3. 独立复核的发现与处理。
4. 已委托清单：每项写标题、级别和一句话理由，人可以展开或收回任一项。
5. 本次确认的范围，以及不在范围内的事项。

按 C01 展示并请人确认；按 C05 记录请求与回应，不补写确认，也不推定已经确认。人收回某一项时，该项改为逐项确认，其余不受影响。

## 6. 评审之后

- 已确认的决定成为 E3 必须遵循的约束。之后需要改变时，只对受影响的条目做变更评审。
- 人事后按比例抽查已委托的决定与高风险代码，记录推翻的次数与原因。推翻少时可以放宽抽查比例与边界；推翻多或出现严重遗漏时收紧。调整边界由人决定。
