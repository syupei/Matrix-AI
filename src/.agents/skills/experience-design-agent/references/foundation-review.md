# D1 设计基础确认

设计 Agent 读取产品交接材料后的第一个专业环节，是解读产品并形成整体设计基础，向用户明确展示并确认。获得对应版本和范围的明确同意后，才进入 D2 粗结构及依赖它的后续设计。这是正式的专业审阅，不是确认文件已收到或批准内部准备计划。

## 先形成可审阅的基础稿

沿 [产品情境与设计方向](design-direction.md) 推导，在现有 `design/01-设计依据与索引.md` 中形成单一有效的设计基础稿，默认一套推荐。按本项目适用性说明：

- **受众与情境：** 继承产品明确的目标人群、能力特征、使用环境及端/输入条件，说明它们如何影响设计。产品已确认事实直接引用，不重启访谈或另造一套人群定位。
- **核心体验与整体方向：** 产品核心活动、期待感受、注意力与信息组织原则，以及设计方推荐的整体呈现和操作方式。
- **视觉风格与表达：** 推荐的形态、色彩、字体、素材及语言方向，说明依据与适配理由。应能帮助用户形成清楚预期，不能只给“高级”“简洁”等空泛标签。
- **交互与感官原则：** 操作与反馈的整体节奏，适用动态/声音/触觉的表达取向、用户开关及关键限制；具体参数和样例在后续细化。
- **稳定边界与探索空间：** 必须保持、明确避免、授权内可细化、留待后续审阅的事项，以及实际未决或冲突。

区分继承的产品事实、设计推导及暂定假设；引用实际源条目/版本。影响基础方向的事实缺口先走原回查，不能用概括性批准掩盖缺口。基础稿必须按下文提供足以判断方向的可视材料并实际展示，不能只凭风格名称或长篇文字请求通过。它们是D1用于讨论方向的材料，不等于完整D2骨架、最终美术或已验证的交互；未确认前不扩展依赖这套基础的完整布局和精细制作。

## 用图文拉齐认知

默认一套推荐。先分别说明以下三个层面，再把它们表达在同一份方向稿中：

- **核心体验：** 用户在什么情境下进行什么核心活动、希望获得什么感受。继承产品事实，由设计解释其影响。
- **界面组织：** 核心对象、主要空间、注意力、操作与反馈如何关联；按任务选择场景、画布、内容阅读、列表表单等组织方式，可以组合，不是固定模板目录。
- **视觉表现：** 形态、材质、色彩、字体、素材与动态节奏如何服务上述体验；已有品牌/用户指定优先。

“游戏风格”“APP风格”等自然表达是理解偏好的起点，不能直接当作互斥皮肤选项。产品类别、运行端、空间组织和美术表现分别判断；同一产品的不同任务可以使用不同组织方式。设计先给有依据的推荐和取舍，不要求用户从零回答专业分类或重复已确认的产品信息。

基础稿至少包含：

1. **本项目的轻量方向示意。** 能看出主要空间、核心对象、操作与反馈的关系；用少量代表内容表达，不用通用盒子或无关参考拼图替代本项目判断。它只表达方向，不预先锁定全部页面、尺寸、状态与交互细节。
2. **可见的表现方向。** 用示意或实际查看过的适用参考说明拟采用的视觉语言，注明具体借鉴部分、来源和边界。不能只放参考而不说明与本项目的对应，也不能把未完成的模型/素材称为成品。
3. **图旁的具体取舍。** 解释最影响本项目的空间、体验和表现决定，以及应避免的偏离、已锁定项、后续可细化项和未验证项。确认重点按实际影响选择，不强制每个项目填满分类表。

关键方向只有通过时间变化才能理解时，补关键帧或短演示，注明模拟范围；不要求在D1完成全部动态或设备验证。按 [工具落地](tool-execution.md) 使用适用技能和可查看源，工具受阻沿原规则处理，不静默以纯文字替代必要可视材料后宣称基础审阅已就绪。

D1同时按 [核心场景适配检查](core-scene-fit.md) 先定义后续可观察判据，保存在现有设计依据；人的方向确认不替代专业检查。

## 实际展示与明确回应

通过当前统一入口实际展示方向示意及表现材料，并给出可访问源、版本/范围、图旁取舍和确认后的D2动作；不能只给文件链接而未让用户看到待确认内容。问题聚焦已展示的具体空间/体验/表现决定，说明本次批准什么、哪些尺寸/模型/状态留后续细化、哪些体验尚未验证，不只问“是否喜欢这个风格”。按 [统一交互规则](../../../../collaboration/USER-INTERACTION.md) 展示确认与调整选择；PM接管时由PM展示，设计方提供材料，不重复提问。

- **确认：** 核对对应内容/版本/范围，保存用户回应与可回查快照，记录为已确认设计基础，再继续已授权的D2工作。
- **调整：** 保持D1，接受用户指出图中区域、表现或文字说明的修改，在同一方向稿修订并回读，展示变化后重新请求确认；提出修改不等于同意其余尚未确认的内容。
- **未回应或含糊：** 保持待确认，不推进依赖这套基础的D2及后续工作。等待中可处理基础澄清、修订和其他独立授权工作，不用“先画出来再说”绕过确认。
- **部分确认：** 记录实际边界；只在用户明确确认的独立范围内推进，尚未确认的共同基础会阻断其依赖范围。

产品定稿、产品方已审STYLE、交接收到、设计Agent自检、上游Agent认可或PM登记完成，都不能单独替代本节点的用户确认。产品的自主推进授权也不能自动扩大为设计基础免审。

## 确认后的约束与变更

已确认基础作为后续结构、交互、视觉与素材的共同依据；后续审阅核对落实，不把基础方向每轮重新开放。明确留给设计的参数、组件和表现细化仍可自主处理。

需要改变受众适配、核心体验、整体呈现或已锁定风格等基础内容时，说明原因、与产品要求的关系及受影响成果，沿原所有权/回查处理并重新取得受影响范围的明确确认，再推进依赖变更的工作。确认表示稳定基线，不是永远不可修改；无关成果和确认保留。

## 流程位置与旧项目接续

D1仍为设计七步骤中的第1步，基础确认位于D1结束、D2开始之前。四个人审节点依次为：**设计基础确认 → A粗结构 → B关键交互与代表视觉合并 → C完整设计**。原A/B/C编号和历史记录保持，基础确认不与D2粗结构审阅合并后追认，也不推迟到D4。

续做先核对当前基础版本及真实确认依据。旧项目已经展示并明确获批的相同设计基础可沿用其有效范围，记录对应证据；仅产品获批或阶段号已经靠后不能推定本节点通过。缺少必要依据时，在当前阶段补展示和确认受影响的基础，不回退重做已有效完成的全部工作，不补写虚假的历史批准。

D1默认参照按 [设计方向](design-direction.md) 主动核对品类及目标人群的适用案例，用户指定经验优先。方向示意按 [空间判断](core-scene-fit.md) 说明核心活动、常用操作及情境信息的安排与具体依据，不等待用户提供个人经验；此时不要求完成全部控件与动态状态。
