# 关键交互的制作与复核

何时读：D3 设计关键交互、D4 制作代表样例、D6 走查时；采用外部方法或专项 skill 时。

把 P5/P6/P7 落实为设计动作，不替代产品事实、完整能力检查或项目规范。先按 R06 发现事件、选择模式。

## 从判断到样例
1. **先判断要解决什么**：意图、对象与范围、输入方式、频率与风险，再选控件与反馈；频率无证据标为假设。动效要帮助定位、理解变化、确认接收或达成合理的表达目标，没有收益就不加。
2. **沿用有效组件与项目表达**：先查已有组件的行为、变量、状态与样板再新增。时长、曲线、缩放与触觉强度是项目设计值，写明依据或标为待调校。
3. **同一交互条目写清行为与呈现**：产品 ID 与版本、前提与对象 → 用户动作 → 即时反馈 → 真实结果与异常 → 继续或恢复；按需补按下、移动、释放、取消的触发时点，连续输入、替代输入、原型节点与验证限制。
4. **实际制作并回读**：用真实内容、目标尺寸与关键状态做可操作样例；超出工具能力的部分写明示意与待验证条件，不静默换载体。

## 反馈对应同一事件与真实结果
- 写清哪个动作、对象与范围在反馈；收到请求、处理中、成功、失败、部分成功、结果未知分开表达。
- 重复触发是合并、替换、拒绝还是新任务，按产品规则定；组件能更新同一通知不证明业务已去重。
- 通知的出现与消失和任务生命周期分开：关闭通知不等于取消任务，动画结束不等于成功。重要的异步结果按产品要求可定位、可回查；缺少规则时回查，不自行承诺。
- 聚焦、选中、悬停、按下、不可用、执行中可辨；整行外观与实际操作范围一致；弹层与触发对象、进入与返回保持可解释的空间关系。
- 组合场景（D3/D6）：按产品 ACCEPTANCE 中适用的组合场景补页面、操作、状态、真实文案、输入保留或丢失、可行恢复与可演示范围；请求已发出、系统已接收与最终成功不混淆；规则不明时经协作澄清，不擅自新增业务恢复能力。

## 实际尝试的情境
按当前任务选用，不只看一次正常播放：

| 情境 | 判据 |
| --- | --- |
| 展开未完即关闭、快速切换 | 从当前呈现衔接，不跳回旧起点、不遗留遮挡或丢失焦点；终态符合最后一个有效动作 |
| 拖动中反向、释放或取消 | 对象与手势连续，边界与落位可理解；不误抢滚动；业务执行时点与保护符合产品规则 |
| 连续提交、批量部分失败 | 接收与结果可辨，失败对象可定位，输入与已成功部分按规则保留；真实防重复交研发验证 |
| 离开返回、迟到反馈、对象已变 | 回到正确对象与最新阶段，过期结果不冒充当前成功 |
| 键盘、鼠标、触控与辅助输入 | 等价意图的对象、范围、权限、后果与恢复一致；手势与悬停有替代，快捷方式不绕过保护 |
| 减少动态、静音、触觉不可用 | 必要事实仍可辨；不以颜色、声音、精细拖拽或震动作为唯一通道 |
| 移动键盘、长文字、缩放、安全区域 | 当前输入与必要操作可见可达；按实际输入能力核对，不只按屏宽推断 |
| 高频连续任务 | 不为装饰阻塞后续操作；提速不增加错对象、错范围与恢复成本 |

动画可中断不等于业务可撤销。网络、并发、设备性能与辅助技术的实际结果由实现与验证任务承担；设计中能验证的呈现与路径当轮完成。

## 证据
- 正常速度判断整体节奏，慢放或逐帧只用于定位。触控与系统协同有条件时用目标设备验证；模拟器与画布预览不标为真机实测；不从截图猜曲线，不从源码属性断言掉帧。
- “跟手”“轻快”“稳重”等模糊反馈映射到具体行为与可操作的例子（如拖动跟随与释放落位分别判断）；对用户用易懂的话。
- 每个问题记源/节点/状态/版本、条件、观察、任务影响、建议修改与复验结果。先处理事实与严重后果、任务完成与可访问性、控制反馈、连续与效率，再处理细节品质；不凑问题或动效数量，作者偏好不同不算缺陷。证据分设计示意、可操作模拟、真实实现、设备检查，记在现有评审与交接记录中。

## 外部方法与专项 skill
项目指定的外部资料按 R10 读实际版本并提取适用内容。方法类辅助判断，制作类产出成果，检查类定位问题，主要设计与验证责任仍在本角色。外部 skill 的默认做法——多方案、不给推荐、无任务时只回复就绪、逐项审批、自动启动其他 Agent、固定曲线与时长、键盘禁动效、统一按压缩放、批量错峰或模糊效果——不覆盖当前任务与授权，按任务调整并保留必要反馈、可发现性与可访问性；组件的命名建议不代替业务动作语义。库与技术配方只在已授权的制作或研发范围内使用，不因此安装依赖或进入生产实现；版本兼容与性能需真实验证；选定后保留审阅依据，不按外部配方删除既有版本。
