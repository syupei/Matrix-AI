# 外观目标与画面实现方式

何时读：用户给出风格词、样稿或参考图时（D-1）；D-4 做风格锚点前；选择或更换画面实现方式时；实现走查或美术回交需要对照外观时。

先定样子，再定做法。描述"看起来像什么"的词，不能当成"用什么做"；外观差距自动测试发现不了，只能与样稿并排看。

## 1. 外观目标（D-1）

- 把风格词与样稿写成可观察的特征：构图与视角、细节密度、光线与氛围、色彩、材质、人物比例与神态、动态感。每条标"必须保持"或"可调整"，注明出自哪张样稿，记入设计依据（T01）。
- 风格词只描述外观，不规定做法。例如"3D 风格"说的是立体感、光影与景深，不等于必须用三维模型制作。用户明确要求某种做法或能力时（如"视角能自由旋转"），按 [CONTRACT](../../../../collaboration/CONTRACT.md) §2 作为形式约束单独确认，并写明原因。
- 样稿是生成或手绘的静态图时，标"外观目标，可制作性未验证"。D-1 只写特征与参考，不做精细素材。

## 2. 画面实现方式

- 候选做法：2D 绘制或生成、分层 2.5D、预渲染三维、实时三维，或混合。设计提出候选与推荐，研发评估目标设备上的运行与性能。逐项比较：
  - 能否还原"必须保持"的特征；
  - 交互需要：镜头是否移动、旋转、缩放，人物是否走动；
  - 美术成本，以及由谁来做（已接入的工具、购买、委托）；
  - 多个场景、角色的多个动作能否成套保持一致；
  - 素材权利。
- 由人决定，记为[关键技术选型](../../engineering-solution-agent/references/technical-review.md)。不新增审阅节点：在 D-4 风格锚点确认时决定；研发需要更早锁定引擎或渲染方式时，并入技术方案的风险试做与核心评审。它是关键取舍，常涉及费用，不作为委托内的常规决定（C92）。
- 不按手头会用的工具或执行者熟悉的方法来选。定了以后，负责人按做法授权工具（C91）。之后要改做法，按关键选型重新交人决定。

## 3. 风格锚点：实做与并排对照（D-4）

- 锚点用候选做法实际做出一小块画面：一个场景局部、一个角色（含一小段动作）、一个关键物件。在目标设备上按实际镜头大小呈现，不用静态效果图代替。
- 与样稿并排，按特征逐条标"达到 / 接近 / 未达到"，由设计决定人判断。
- 先做推荐的一种。未达到，或几种做法的代价差别大（例如要购买或委托美术）时，再做第二种，并排交人选择。
- 都达不到时，"调整外观目标"还是"增加美术投入"交人决定，不悄悄降低外观。

## 4. 之后的对照

- 批量制作用已定的做法，素材的制作媒介随之确定（R12）。
- 美术交给执行实例或外部美术时，按[外发任务包](../../../../collaboration/TASK-PACKET.md)附样稿、特征清单、已定做法和授权的工具。回交附并排对照图，只算自检；设计负责人逐条核对后再整合。
- 实现走查时，与锚点或样稿并排，按特征清单对照。必须保持的特征明显不符，记为实现偏差（R13）。
- 对照图与逐条结果记在评审与验证（T01）。
