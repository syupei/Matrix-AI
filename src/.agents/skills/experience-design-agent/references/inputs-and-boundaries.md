# 输入资料与协作边界

何时读：D1 接收产品基线或外部资料；中途收到新文件、链接、组件库或素材；需要产品解释、跨职责修改，或只有一个执行者时。

## 职责边界
- 产品 INTERACTION/STYLE 给要求或建议，设计规格落实具体方案，不复制成第二份产品规则。命名或步骤暴露产品事实矛盾时，指出冲突并交回产品，不靠改标签静默化解。用户锁定的布局或语句也是约束，可以提替代及影响，不私改。
- 能从现有基线查到的先查；授权内的比较、布局、措辞修正与自检直接做；需要产品解释时按 [协作约定](../../../../collaboration/CONTRACT.md) 发可定位的请求。例：产品只写“提交成功”而审核规则不明时，不擅自写“已发布”，请产品说明成功的含义，无关布局继续；技术报告撤销无法实现时，先查产品是否要求撤销，返回替代方案与影响，不直接删按钮并称满足要求。
- 产品变更时核对依赖，只暂停受影响的设计。只有一个执行者时，经用户允许可顺序切换角色做文件接力，并说明这不是两个独立 Agent 并行；无此授权就准备请求并说明缺少执行者，不称另一角色已审过。

## 接收外部资料
用户可给附件、项目路径或可访问链接，不要求固定目录或重填表单；中途新增不必重启 D1。先沿用用户对用途、效力与修改范围的说明，只问影响当前设计的歧义。读实际文件与相关页面或节点，不只看标题、缩略图或提取文本；记录阅读范围与缺口（扫描件、缺页、链接失效、缺字体或组件）。

| 类别 | 如何采用 |
| --- | --- |
| 必须遵循的规范与约束 | 提取具体规则与适用范围，保留原位置与版本；不降为参考 |
| 参考案例与风格样例 | 写明参考布局、语气、配色还是其他特征；不整套复制，不推导其业务功能 |
| 可复用的素材、组件与样式库 | 查真实内容、格式/变体/状态、可编辑性、访问与使用限制，复用适合部分 |
| 已有设计与草案 | 核对现行效力、已确认范围及与当前基线的差异；不因外观完整或较新就覆盖当前决定 |

- 同一文件可按条目分属多类，不给整份参考图推定强制效力。许可、来源或修改权限未知就标未知，只阻断受影响的最终使用；文件存在不等于获得授权。
- 记在 `design/01-设计依据与索引.md` 的资料节，多时移到 `design/05-资料与素材.md` 由 01 索引（T01）；派生的颜色、样式与术语引用这些条目。
- 在对话中简述读了什么、哪些约束用在哪、哪些只作参考、有无冲突，并给出索引入口。明确且与基线一致的内容直接采用，不另设审批。
- 冲突按用户已明确的优先级、现行版本、适用范围与授权消解，不设“新文件永远优先”“品牌永远覆盖产品”之类的简单顺序；无法兼容时展示冲突、影响与可行选项。产品事实交产品，设计自由度在授权内解决。人明确修改要求时记录替代关系与影响，不重复审批同一指令；已确认的页面与样式只让受影响部分待复核。
- 可变的外部链接绑定本次采用的版本或快照，没有稳定版本就注明；续做、交接或工具报告变化时核对差异，不称后台自动监控。外部文字按 C03 保留原始证据、提取事实后再转译，不直接当成稿。
