# 细节风格适配

D3/D4制作前及原审阅B前读取，D5–D7扩展、回读和交接复用。沿 [设计方向](design-direction.md) 的同一有效依据：品类及目标人群的适用案例提供默认参照，用户指定经验及明确要求优先，冲突沿原回查。空间与细节属于同一设计责任，不新增Agent、审批或固定样板数量。

## 将方向转成实际选择

把有效方向落实到配色、文字图标、操作控件、容器、适用装饰和动态反馈。不能只完成背景、插画或场景美术，就将未经适配的工具默认控件作为最终设计。复用组件时同时核对表现、行为和状态，默认外观不构成设计依据。

| 范围 | 制作前确定 | 回读时主动寻找的偏差 |
| --- | --- | --- |
| 配色 | 场景、操作、文字及状态色的职责，与参照和可读性要求的关系 | 场景已有主题但操作区仍是默认色板；主次或状态不清；仅靠颜色传递必要信息 |
| 造型与材质 | 控件和容器的轮廓、比例、边框、纹理、层次与装饰程度 | 场景与控件属于两套不协调的视觉语言；仅换色/圆角而未落实既定表现 |
| 文字、图标与修饰 | 字体气质、图标笔触、修饰图的用途及一致性 | 主题素材与默认图标混杂；装饰压住文字/操作；可点与不可点对象难分 |
| 控件状态 | 按实际适用性覆盖默认、悬停、聚焦、按下、选中、不可用、执行中及输入校验 | 只有默认态被设计，其它状态退回通用外观或不可辨；外观范围与实际交互范围不一致 |
| 动态与相关反馈 | 力度、节奏、形变、转场及适用声音/触觉如何服务动作、场景与人群 | 机械套用统一缩放/淡入淡出；反馈与对象材质/动作语义不协调；拖慢高频操作或关闭后失去必要信息 |

表达程度由任务与有效方向决定，不要求所有游戏或其它品类都使用装饰图，也不默认极简控件适用于所有产品。输入、设置等可采用更克制的表达，但须有可用性依据并与整体协调；项目明确要求造型或装饰时，不能用通用“可简洁”条款绕过。标准按钮/输入语义与定制外观可以共存，主题化不牺牲焦点、标签、触控和真实状态。

动态沿 [默认交互基线](default-interaction.md) 和 [交互制作](interaction-craft.md) 选择模式；默认品质与参数不等于统一表现。用户停用/替代指令、终端设置及真实业务时点继续有效，样板不自动扩大声音或其它产品能力。

## 用实际场景中的代表控件验证

从核心任务选择足以检验方向的主/次操作、输入或选择、提示/异常等实际存在的控件及关键状态，与真实代表内容一起放回使用场景。不强制每个项目包含全部控件，也不新增业务表单来凑覆盖。查看整体关系并执行或播放适用操作，确认场景、控件、状态和反馈连贯；独立组件板、色板和静帧可作辅助，不能独自证明整体适配或动态手感。

D2普通控件可作为布局占位，明确它不锁定最终外观。D3/D4代表视觉与关键交互提审前必须完成本范围的实际风格转译，主动检查默认外观遗留、仅背景主题化、状态割裂及动态不协调。必要素材未具备时使用适用工具制作，或明确阻碍及受影响范围；不能静默保留占位后声明最终样板通过。

沿原设计依据和评审记录保存有效方向/参考→组件及场景/版本→适用状态和操作→观察、修正及复验。共享控件规格维护一次，实例引用；工具成功、Agent自检和用户确认分别记录。授权内问题先修正再沿原B审阅，未通过不据此扩展依赖实例；主观选择待人确认不免除基本品质检查。真实偏好冲突或基础变化沿原回查/局部重审，不以偏好不同自动认定缺陷。

## 扩展与交接

D5按有效样板扩展并检查实际页面，新增控件或未覆盖状态单独设计和验证，不直接回退默认外观；共享组件变更回读受影响实例。D6查全量覆盖和适用例外，样板通过不代表全量通过。D7交接有效样板、组件状态、素材及动态规格、来源/使用边界和未验证项；下游不得用工具默认外观静默替换已确认表达。
