# 产品情境与设计方向

何时读：D1 形成方向前；D3–D7 核对方向落实或调整方向时。

1. **主动形成方向。** 产品描述足以开展设计而未指定风格时，主动形成有依据的推荐方向，做成可审阅的成果；不因缺少风格名、参考图或组件要求而省略判断，也不套用最熟悉的模板。
2. **从实际情境推导。** 读目标、核心任务、受众及其能力、使用情境、内容特征、操作方式、频率与节奏、结果风险、期望感受与既有约束，只取对设计有影响的维度。品类可帮助找资料，不单独决定布局、密度、美术或交互；同一产品的不同任务可以采用不同的组织方式。
3. **区分事实缺口与设计选择。** 分别标明明确要求、设计推导、暂定假设与待澄清。会实质改变用户、核心任务、操作条件或既有承诺的缺失，先查已有材料，再经既定渠道做最小澄清。授权内的布局、配色、字形、素材与反馈由设计推荐、说明理由并在审阅节点展示，不让用户代做设计；不借设计推导新增产品事实、功能或规则。
4. **粗结构前先定整体方向。** 先定主要活动由什么承载、内容与操作如何组织、注意力如何分配，再细化视觉。方向写入现有设计依据：服务的用户与任务、空间与信息层级、视觉与素材语言、文案表达、交互与反馈、应避免的偏离、可观察的质量判据；不只写“简洁”“高级”。按 R03 取得同意后才推进粗结构。
5. **默认参照与指定经验。** 优先用有效的项目规范与已有成果；缺少时主动查找并实际核对品类与目标人群的惯用案例，结合核心任务、设备与输入条件建立默认参照，不等用户提供。用户指定的参考或体验方式在其范围内优先，与明确要求冲突时回查。记录来源、所见的空间/控件/交互关系、采用与不采用的部分；个例不证明惯例，未核对不称行业共识；参考可以跨行业，但不因外观相似照搬结构。运行平台、现有组件与工具默认输出不能替代设计判断。
6. **通用品质与项目表现分开定。** 可理解、可操作、反馈真实、连贯一致、可控、可访问是共同品质；布局、视觉语言、动态节奏、声音与触觉依产品情境而定。空间按 R04、细节按 R05 落实；简洁或装饰都要有依据，不以装饰多少判断品质。通用反馈模式只在适用处复用，承担核心任务表达的行为按实际语义设计。停用效果时保留必要的信息与操作。
7. **用代表任务校准并审阅。** 选最能验证方向的核心任务、真实内容与关键状态做样例，数量按覆盖需要定；不以首页、色板或静态截图认定整体体验成立。样例确认只覆盖所展示的范围，扩展中的新情境另行核对；用户确认不免除专业检查。
8. **检查适配与表现质量，交接实际依据。** 检查是否支持核心任务、适合受众与输入条件，信息与操作是否清楚，反馈是否符合真实状态与节奏；构图、比例、字体、色彩、素材与动态是否协调，是否实现所推荐的体验目标。看实际成果，不以文档完整、模板精致或标签相符代替。交接有效方向、来源与例外、样例、组件与素材规则、验证证据与未验证项。方向调整时核对受影响的成果与确认范围，不只换色或换装饰。
