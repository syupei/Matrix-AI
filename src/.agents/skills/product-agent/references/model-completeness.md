# 对象规格、参数依据与组合场景

何时读：S3 建模、S4 设计行为、S6 评审；S2–S5 需要数值或阈值时。补进已有 MODEL、BEHAVIOR、ACCEPTANCE，按复杂度取舍，简单对象一段话即可。

## 对象最小语义

对影响核心任务的对象检查适用项；沿用已有 ID，规则随具体实例变化时才区分定义与实例。

| 要点 | 需要明确 |
| --- | --- |
| 身份与作用 | 是什么、服务什么任务、与相近概念的区别 |
| 属性 | 关键属性的含义、允许值与边界、单位或计量口径、来源；不只列字段名 |
| 关系 | 关联谁、数量限制、归属与依存；删除或失效影响哪些关联对象 |
| 状态 | 合法变化与触发；可独立变化的状态（如发布与处理）分别定义并说明允许组合 |
| 动作 | 谁在什么条件下对什么操作；成功、失败、结果未知各意味着什么 |
| 后果与例外 | 本对象与关联对象的变化、不变条件、例外；只在确实支持时承诺撤销或恢复 |
| 判据 | 用什么可观察事实判断成立；引用 AC 或标明尚缺 |

事实在 MODEL 定义，BEHAVIOR 引用于流程，ACCEPTANCE 保存检查情境。不规定数据库、API、存储结构或技术状态机。

## 关键参数与未知项

- 记录含义与单位、适用范围、实际值或"未知"、依据与性质（用户要求/可核实事实/外部约束/AI 建议起点/待验证），确认状态另记。AI 给的精确数值不冒充实测或已确认值，未知不填零。
- 关键未知写明影响什么决定、怎样取得依据、什么结果可解除、最迟在哪个依赖决定前解决；没有指定提供方就写"未指定"，不捏造负责人或截止日期。涉及用户意图、领域事实或重要承诺时回到正确来源；授权内可逆的选择先给方案和理由，不把每个参数变成人工必答题。
- 例：留言长度上限若只是建议，写明任务、阅读负担等取舍依据和计数口径，保留待确认或委托的性质。

## 风险驱动的组合走查

- S4/S6 从真实能力中选少量高影响组合：多对象相互影响、状态同时存在、外部事件插入、重复动作、延迟结果到达。不枚举全部组合，也不为凑场景加账号、审核、并发等功能。例：已有编辑与删除时查编辑中对象被删除；提交结果可能未知时查再次提交的期望。
- 选中的场景写进已有 AC：关联对象与规则版本、初始组合、事件顺序、期望事实、禁止结果、用户可知信息与可行恢复、证据限制。S6 只记推演结论与缺口。
- 业务结果由产品维护，界面反馈由设计补；产品判据缺失时回到产品，不用一句友好提示掩盖规则未知。
