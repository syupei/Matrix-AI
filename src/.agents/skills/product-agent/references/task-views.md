# 从对象与任务推导集合和管理入口

何时读：S4/S5 推导集合与入口；S6 复核；设计 D2 承接时。对象、关系、任务集合与界面标签分别判断，不要求一个对象对应一个页面。

## S4/S5 主动推导

对需要查找、查看、管理或跨对象处理的任务，沿"对象与关系 → 用户任务 → 所需集合或工作空间 → 范围、可用行为与候选名称"推导，不等用户点名某个列表或标签页。说明用户在哪里找到什么、哪些对象进入集合、从哪里进入和返回、操作作用于谁并产生什么结果。简单项目在 INTERACTION 中简述即可，无适用集合不凑表。

- 集合范围引用 MODEL 的真实关系、权限和状态；跨对象工作空间引用同一任务的输入与结果。集合不必新增业务实体，也不规定数据库或技术形式。
- 已有关系足以推导时直接提出组织和入口；任务依赖的关系缺失时回 S3 补关系或规则。不能用名称倒推不存在的成员资格、归属或权限。
- 邀请、批量操作、审核、筛选等新行为要由任务与范围支持，在 S4 形成并审阅；"有管理集合"本身不授权这些功能。
- 候选名称按 [命名](naming.md) 反映真实范围与任务。名称准确不等于业务关系成立。

MODEL 保持事实与规则，BEHAVIOR 保持任务与操作，INTERACTION 引用两者写集合职责、范围、入口和当前名称，不复制业务规则，也不强制新增文件、对象类型或审批。

## 设计承接与 S6 核对

- 产品交付要承载的任务与职责、范围依据、必要操作、命名状态和形式约束；设计 D2 决定页面、标签页、侧栏等载体，并做任务与页面的双向覆盖。产品提出的载体若只是建议，设计可在授权内优化；真实业务关系和明确的形式约束须保持。
- S6 从实际任务检查：需要的集合是否有入口；包含与排除范围、操作对象是否有依据；名称是否准确；入口与返回能否闭环；界面组织是否误加业务语义或产品能力。记录检查对象、缺口和修订位置。

## 示例（非真实项目）

- 已有项目与用户归属，管理员要看当前项目人员：可推导人员集合和入口，提出"项目成员"等候选名，无需另造业务实体；加入、移除权限沿原规则。
- 只有系统用户、没有项目归属：按系统用户管理任务设计集合，不能称"项目成员"；任务确需项目归属时先提出关系缺口。
