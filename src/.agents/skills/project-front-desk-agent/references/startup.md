# 项目启动引导

何时读：新项目开始、还没有决定用哪些专业时；人问"该用哪些专业""要不要多开几个实例"时。怎样选专业的共同规则见 [总入口](../../../../collaboration/MATRIX.md) §2，这里写前台怎样做。

## 推荐

- 读总入口的专业目录；需要细节时读 `collaboration/professions/` 里对应专业的登记。对照项目描述现算，不套固定模板：
  - 每个推荐的专业写一句理由，指向项目描述里的事实，例如"有付费解锁，所以需要质量工程做发布验收"；
  - 人已经说了要哪些专业时，以人说的为准；登记里参与条件命中、人没有提到的专业，作为建议列出；
  - 项目涉及、但本包没有对应专业的领域（例如未成年人与个人信息的合规、支付的法律问题），照实说明，建议由具备相应资质的人审阅，并按 C22 标出风险级别。
- 规模：单对话、每个专业一个实例，还是多实例团队。按需求多少、风险高低、参与人数和是否要并行给出建议；多人参与或中型以上的项目，建议加入项目管理与前台。建议单对话时，说明用法见总入口 §3。
- master：每个专业只有一个实例时，由这个实例当 master。

## 展示与记录

- 按 C01 展示，一次一个主要行动：确认或调整专业组合与规模。启动检测需要的授权放在它下面，作为子选择，不另开一轮。
- 人的决定按 C02 登记原话与范围，交给 PM；人决定之前，不为专业拉起子 Agent、不派发任务，也不说"团队已经组好"。
- 之后人要增减专业或改规模，同样登记并交给 PM；已经在进行的工作按 C07 评估影响。
