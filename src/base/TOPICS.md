# 议题：跨专业的多轮交流

何时读：要与别的专业来回几轮，或涉及两个以上专业时；收到议题、要作决定或上交时；结论要上升为共同约束时；与外部专业交流时。一问一答用请求（[协作约定](CONTRACT.md) §4）。

## 1. 五种交互

| 类型 | 用途 | 决定归谁 | 以什么结束 |
| --- | --- | --- | --- |
| 咨询 | 问专业意见或专业事实 | 发起方（相关成果的责任方） | 带依据的意见 |
| 请求处理 | 请对方修改它负责的成果 | 对方 | 对方成果的新版本，以及给下游的通知 |
| 审查 | 按参与规则做检查 | 审查方给结论，是否放行按规则 | 审查结论；必需审查不通过就阻断 |
| 讨论 | 涉及几个专业，需要收敛 | 登记的决定方：受影响成果的责任方；有多个责任方时由 PM 协调，或交人 | 结论、分歧与后续动作 |
| 通知 | 告知变更 | — | 对方确认已复核受影响的部分 |

## 2. 开议题

- 先登记，再发送。登记写明：编号、类型、起因条目与版本、目的、参与方（内部或外部）、决定方、知情范围；轮数上限默认 3，可以写期限。
- 同一问题只开一个议题，重复的合并；由发起方负责结束。
- 登记过的实例在任职范围内可以直接开议题，不必经过协调方；投递与唤醒由宿主负责。宿主能点对点投递、只能经主会话转达、没有通道三种情况下，协议都成立；没有通道时只记为待发。
- 只发必要的摘录，并带版本。议题里只记要点与引用，不存整段对话。操作见协作技能的账本说明。

## 3. 谁知道什么

| 谁 | 看到什么 |
| --- | --- |
| 参与方、决定方 | 全部内容 |
| 受影响成果的责任方 | 结论会改到它的成果时，收到结论与依据 |
| 已在使用受影响成果的下游 | 按 C04 §5 收到变更通知 |
| PM | 只看头信息：谁发起、关于哪一条、类型、状态、结论类型、是否影响计划 |
| 人 | 需要人决定时，或主动订阅时 |
| 其他专业 | 不通知 |

保密议题的内容只给参与方和决定方，其他人只看到头信息。这是工具按操作者过滤，不是加密。

## 4. 按影响上交

| 情况 | 去哪里 |
| --- | --- |
| 结论只影响发起方自己的成果 | 发起方自行采用并记录 |
| 要改别的专业的成果 | 交该成果的责任方（请求处理） |
| 影响范围、进度、资源或对外承诺 | 转为变更，由 PM 登记（C07） |
| 需要关键取舍、接受风险、花钱或改委托边界 | 交有权的人，经对人入口合批 |
| 到了轮数或期限仍没有进展，或专业结论冲突 | 汇总分歧交决定方；决定方无权决定时交人 |

消息里写"请直接批准"，不改变接收方的权限（C04 §3）。影响别人成果的结论，要等责任方采用才生效；依据已经变了的结论，不能采用。

## 5. 结论的效力

- 结论标"约束"或"建议"。约束性结论只限登记里"有约束力的结论"声明的那几类。
- 约束：责任方必须满足，怎样满足由它决定；做不到时，由有权的人接受风险，并记录在案。
- 建议：责任方可以不采纳，但要写明理由。
- 结论落到正式文件并带版本，与条目互相引用。

## 6. 共同事实与共同约束

- 所有专业都要知道的只有四类：产品基线、命名、关键技术选型、跨领域约束（法务、安全、品牌）。它们由各自的责任方带版本发布，并登记在共享知识索引（[C26](SHARED-INDEX.md)）。
- 局部结论适用范围超出起因条目时，由决定方上升为共同约束：写进项目的 `shared/constraints.md`（第一次需要时才建），每条写编号、内容、适用范围、给出它的专业、版本和来源议题；再按登记里的接口找出受影响方，逐个通知。

## 7. 外部专业

参与方分内部、外部两级。外部只拿到任务包式的必要摘录（C17），不给凭证和个人数据；它的结论先算意见或自检，内部责任方核对后才采用。
