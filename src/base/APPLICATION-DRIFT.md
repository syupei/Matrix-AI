# 组织方式偏离信号

何时读：设计自查或贴合检查。按当前做法档的活动范围，对照方向样张与实际成果；逐项记位置、结论和依据，不能用“未见”代替查看。

场景为中心的核心区出现下列症状时，默认记为偏离并给改法；确有本活动需要时，说明保留依据及影响。设置、记录等事务范围可用常规控件，不据此判偏。

| 可见症状 | 对活动的影响 | 替代或保留条件 |
| --- | --- | --- |
| 操作排在远离对象的按钮排 | 选择、作用对象和结果难对应 | 动作靠近对象；全局操作可留 HUD |
| 局面拆为卡片列表 | 空间关系和活动主次被切散 | 放回同一场景；选关、历史可保留列表 |
| 核心操作变成表格、表单 | 填写挤掉观察与行动 | 对象内操作；确需比较、批量录入时保留 |
| 顶部导航、侧栏或整页跳转承载每步行动 | 动作与结果断开，返回丢局面 | 场景内换状态，临时工作用浮层 |
| 长页滚动才能看全局面或下一动作 | 核心对象离开视线 | 适配目标视口；规则长文另开可回入口 |
| 弹窗层层覆盖 | 连续打断且难恢复 | 合并短反馈；暂停或关键决定用单层浮层 |
| 默认组件压过对象造型 | 控件层级盖过已确认外观 | 调整尺度、轮廓与层次；适用 HUD/按钮保留 |
| 大段文字替代场景状态 | 玩家需翻译文字才能判断局势 | 状态落实到对象，文字补因果与规则 |
| toast 是结果的唯一载体 | 消失后无法回看，易错过后果 | 结果留在对象或持久状态，toast仅补充 |

非场景范围反向核对：事务、记录与创作是否被多余动画、装饰或游戏化打断；真实需要的批量处理、筛选、导出、撤销是否缺失。按业务需要选组织方式。共同成果绑定见[做法档](PRACTICE-PROFILES.md)。
