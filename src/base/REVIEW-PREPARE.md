# 1. 主动征求意见的节点

何时读：准备审阅、出现专业缺口或需要人的决定。调用前置与其余操作见[原入口](USER-INTERACTION.md)。

## 1. 主动征求意见的节点

- 产品：每个主要阶段（P-1–7，或用户约定的裁剪方案）形成成果并自检后，主动询问"这一阶段是否需要调整或补充？没有的话，是否确认进入下一环节？"，收到明确回应后再推进依赖它的工作。
- 设计：四个人审节点——D-1 设计基础、A 粗结构与核心交互、B 素材与代表稿（风格锚点、关键素材、填充后的代表页面与关键交互，合并审阅）、C 最终约定范围。D-1 未获明确同意，不进入 D-2。
- 研发承接、技术方案与其他角色：按各自 skill 约定的集中审阅点执行；技术方案的人审是 E-2 出口的核心评审，增量构建的人审是 E-3 结束时的范围完成评审，发布与交接的人审是 E-4.2 发布决定；质量验证默认没有人审。
- 合并多个阶段一起审阅，需要用户明确安排；项目简单不是跳过审阅的理由。普通编辑、自检和子任务不增加人审。
- PM 接管时，审阅与跨角色的待决事项由协调入口合批展示（有项目前台时由 PM 准备、前台展示）；子角色提交完整的审阅材料，不各自向用户重复提问。人主动到某个角色的会话里讨论或当场确认该角色的成果时，照常处理并记录，PM 从文件读取（见 [RUNTIME](../orchestration/RUNTIME.md) §2）。
- 已授权的登记、影响分析安排、内部拆解及计划准备完成后，直接报告结果和未决项，不为这些管理操作新增确认点。写“安排稿修订完成”本身不触发审阅；只有既定专业审阅节点、真实缺失事实或超出委托的重要取舍才需要人决定。
- **主动告知，不需要回复**：风险 F1 的成果与缺陷 Q1 合批告知相关的人；缺陷 Q0 立即告知；Q2 进入摘要。写明是什么、级别与检验情况，单实例时标明"同一实例检验"。除非现有规则要求人审，人不必回复（C22）。
- 多人项目按 [TEAM](../orchestration/TEAM.md)：确认请求发给该范围的决定人，澄清发给知情人；PM 按人合批，只 @ 需要行动的人。本文件中的"用户"指当时需要作答的那个人。
- **缺专家时**（CORE §7）：在本轮回复里一次列出缺的专业或领域、需要它的原因、风险级别与后果、应具备的资质，给出三个选择和你的建议：
  1. **指定专家**：人指定专家 Agent 或具备资质的人；本包里有的专业，也可以请人把它加进实例配置，由 PM 派生。你准备交接材料，按 C04 发出，等对方的成果，按来源记录。
  2. **由当前 Agent 完成**：人明确要求并表示了解风险后才做，原话按 C02 记录。按该专业的技能做；本包没有这个领域时，如实说明没有可用的技能。成果标"非{专业}专家产出，未经具备资质的人审定"，风险级别不因此降低，F0 仍由人判定后才生效，不说可以直接上线或已经合规。
  3. **列为人工待办**：记入人审点汇总表与"现在等人处理"，写明要什么、需要什么资质、挡住哪些工作；依赖它的部分等待，其余继续。

  每个领域只问一次。人选过的，之后同一领域的工作照这个选择做，不再询问，直到人改选或明确引入新的专家；选的是由当前 Agent 完成、而新工作的风险比选择时高的，再问一次。人还没选的，之后各轮只在待你处理里列一行："{编号} {领域}未设立：挡住{哪些工作}；选择见{首次告知或人审点的位置}"。这一行就是 CORE §6 的"怎么回复"，不再写三个选择，缩写成编号列表也不行；人问起，或挡住的工作有变时，再说明。有任务库时用缺口记录登记（PM 的任务工具，见 [任务库说明](../orchestration/TASK-TOOL.md)），单对话记在 `management/progress.md`。要交的责任方在项目里没有实例时同样处理：点名该专业，说明没有设立，给出这三个选择。

## 2. 审阅提示写什么

按自然语言组织，内容短时可以合并，但下列信息不能缺：

1. **现在要做什么**：例如"目标与范围草稿已完成，需要你确认本轮范围"，并与文件状态一致。
2. **看哪一份**：一个主成果的可点击链接，附实际版本和章节（写法见[第 6 节](REVIEW-RESPONSE.md#6-成果链接)）。辅助链接只在必要时给；一次只提一个主要行动，必要的子选择放在它下面。
3. **重点看什么**：一段足以作判断的摘要，加 1–3 个具体的决定、变化或待决项，并附你的建议。写出具体内容和取舍，不能只列栏目名。
4. **确认边界**：本次确认哪些内容，哪些不在范围内，相较上次改了什么。
5. **怎样回复**：两个确认选项（[第 3 节](USER-INTERACTION.md#3-确认选项)），同时接受自由文本、只确认一部分或请求解释。
6. **回复后会怎样**：例如"确认后我会建立对象与规则；如需修改，我先更新受影响的范围说明"。

```text
{流程}：共 {N} 步，当前进行第 {X} 步「{阶段}」｜依据：{本轮之前已有的记录文件，或按[第 7 节](USER-INTERACTION.md#7-流程位置)写推断}｜等你审阅｜范围：{本次内容}
{成果}已完成，现在需要你确认{范围}。
查看：{主成果链接}（{版本/章节}）
重点：
- {关键决定及建议}
- {本次变化或边界}
本次确认{范围}；{未包含的部分}。
请选择"确认，可继续"或"需要进行调整，进入调整对话"，也可以直接说明修改意见。
确认后，我会{下一步}。
```

花括号处填入真实内容，不要把占位符发给用户。
