# 协作请求与返回模板

何时读：需要写一条跨角色请求、返回或接收记录时。字段含义见 [CONTRACT](CONTRACT.md)。用真实值替换花括号；一条记录可以同时包含请求、返回和接收处理。模板本身不会发送消息。

## 请求

```markdown
# {请求 ID}：{一句话事项}

- 协议：professional-collaboration/0.1
- 项目/任务：{标识}
- 修订与替代关系：{修订号；有原请求则引用}
- 来源角色/实例 → 目标角色/实例：{已配置的实例；未知写"未配置"}
- 类型：{查找解释 / 设计协作 / 变更建议 / 验证反馈 / …}
- 授权与允许范围：{授权来源；可自行决定什么；可改哪些产物；哪些仍需人确认}
- 输入基线：{基线标识、文档版本、条目 ID、接收方可访问的引用或版本快照}
- 问题与影响：{具体缺口；阻断哪些工作，不影响哪些}
- 已查依据与候选建议：{事实、假设、建议分开列；没有写"无"}
- 期望回答：{完成到什么程度才有用}
- 返回与恢复方式：{实际通道与恢复能力；不具备就如实写}
- 运行状态及依据：{已准备 / 已发出 …；附实际证据}
```

## 返回

```markdown
## 对 {请求 ID / 修订} 的返回

- 答复者与规则版本：{实例、skill 版本}
- 依据的输入：{基线、版本、条目；无法访问就写明}
- 结论类型：{既有定义解释 / 授权内专业决定 / 待审阅变更建议 / 需要信息或人决定 / 无法处理}
- 结论与依据：{直接回答并引用依据；推导与事实分开}
- 产出与修改：{实际文件、条目、版本；只是建议就写"未合入"}
- 影响范围：{涉及的规则、功能、设计、验收及待复核内容}
- 是否需要人决定：{否：在什么授权内解决；是：具体问题和可比较选项}
- 请求方下一步：{可继续的工作；仍受阻的范围}
```

## 接收处理

```markdown
## 接收处理

- 版本核对：{输入是否仍适用；哪些结果可用及依据}
- 采用 / 不采用 / 需补充：{理由；合并位置与版本}
- 审阅状态：{是否涉及人工确认；确认记录或"待确认"}
- 请求状态：{已解决 / 仍在等待 / 已替代 …}
- 恢复位置：{接续的任务；本轮能继续就继续}
```
