# 项目做法档

何时读：P-1 生成或审阅项目做法档；专业阶段接手、复核或改变本范围的体验做法。实例只读当前活动范围、本专业段落和当前阶段的关卡要求。

## 生成与接力

- 用[通用模板](practice-profile-template.json)为实际业务写档。[类别提示](practice-profile-categories.json)用来找活动和比较参照。一个项目可混合多类，也可用表外描述。以不同活动真实发生的范围划分 `scopes`，在范围内明确该做法影响的场景。游戏区与管理区可采用各自组织方式。
- 产品从用户目标写出核心活动、完整过程、核心场景、希望用户理解和感受到什么、规则与约束。各专业按[方向样张](../orchestration/DIRECTION-SAMPLE.md)补本职内容。每个专业段落写具体做法 `approach`、常见偏离 `pitfall` 和检验方法 `check`。不适用说明业务理由，信息未得写清待决问题。
- 在调性契约的 `references` 附 2–3 个真实参照，说明来源、借鉴点及实际观察情况。未访问写作未观察；来源暂缺写明缺口。范例是填档和选择方法的参考，产品事实以本项目实际依据为准。
- [完整游戏范例](practice-profile-example-game.json)用一局棋盘活动贯通五个专业段落。内置专业按本范围的活动、特征与当前阶段选读对应方法，不以类别名代替判断。交互与视觉设计分别读交互和美术的适用部分。自有专家按[导入要求](../orchestration/EXPERT-IMPORT.md)使用已适配方法。
- 在 P-1 合看中确认做法档与方向样张，展示时固定方向摘要，完整答复与该摘要、范围绑定，不能复用答复给新方向背书。已确认档作为调性契约的 `parts.practice_profile` 引用，记录 `path/version/sha256`；关卡和受影响成果引用当前 `tone_contract`。语义改动生成新版本，按既有变更机制复核受影响试做、截图和贴合记录。

## 内容触发的阶段义务

每个活动范围都填七项特征 `features`，逐项记 `value`（`yes`、`no` 或 `pending`）和 `basis`（实际业务依据）。类别用于描述。阶段关卡按特征读义务，相应范围取并集；专业对冲突提出取舍。缺档、缺字段、材料与需求矛盾或待定已影响本阶段，暂停受影响的工作。采用范例在活动范围写 `example.id`。改动范例的特征值须在 `example.deviations` 以特征名逐项写业务理由 `reason` 与专业审阅摘要引用 `master_review`，由贴合检查核对后随 P-1 一次合看确认。

| 特征 | 何时为 yes；什么不算 | 完成条件 |
| --- | --- | --- |
| 场景为中心 `scene_centered` | 同一空间内对象关系承载观察与行动；普通列表/详情不算。 | D-2 按核心活动场景组织。 |
| 外观目标 `appearance_target` | 有须保持的可观察造型、材质或空间特征，即使人未给风格词；仅通用整洁排版不算。 | D-1 定特征锚点；E-2 渲染选型与外观试做；E-2.3 核心场景骨架、E-3 首个可操作增量各自贴合复核；Q-1 安排对照。 |
| 素材家族 `asset_family` | 多种/多状态对象须共享造型尺度与视觉语言；单张独立插图不算。 | D-4 按[锚点对照](ASSET-COMPARISON.md)做3–5个代表元素、并排实物与逐特征比较，再成套。 |
| 直接操作 `direct_manipulation` | 对对象进行点选落位、拖放、瞄准或等价键盘动作；普通表单提交不算。 | 按下方手感义务。 |
| 连续动画 `continuous_animation` | 运动过程持续表达状态、路径或因果；装饰轮播和普通页面过渡不算。 | 按下方手感义务。 |
| 关键时序反馈 `timing_feedback` | 输入、裁决、表现、下一行动的先后/延迟影响理解或操作；普通成功提示不算。 | 按下方手感义务。 |
| 流量高峰 `traffic_peak` | 有同时参与、集中开场等可预期突发负载；仅希望用户增长不算。 | 研发与质量定负载目标、方法并压测；未知先给依据估计，实测另记。 |

七项按本范围逐项写是/否的业务依据；不能判断写 `pending` 和待决问题，不用 `no` 隐藏缺口。直接操作、连续动画、关键时序反馈任一成立时，E-2 做渲染关键选型、外观试做与手感原型，检查时序、中断及预算；E-3 首个可操作增量贴合复核；Q-1 安排录屏、时序记录与人的试玩。

已有阶段人审照常。外观试做用候选技术画实际核心片段。命中骨架要求时，E-2.3 按样张画出活动对象、状态与基本动作，用实际截图复核；E-3.1 核对承接记录仍有效。E-2.4 交试做、骨架与限制；手感原型交人随核心评审或已有试用安排试玩。命中首增量复核时，E-3.2 对照当前方向做贴合与 D-6 设计走查。Q-1 的证据是计划，实际验收到 Q-2 等执行时留存。

骨架与首个可操作增量分别留贴合记录（skeleton_fit、increment_fit各用自己的文件）。比较当前契约图与本次实际截图，reference_screenshot引用方向图；reference_viewport与viewport同数值且等于契约视口，comparison_state写代表状态或复现步骤。方向无图时用reference_manual_review引用实际看稿依据，可同时采本次截图。采集、人员及人工回退格式只读[证据格式](REVIEW-EVIDENCE.md)，当前完成/历史来源、未变范围沿用、首增量时机与PM接力按[阶段证据](STAGE-EVIDENCE.md)。

设计自查和贴合检查按[应用感信号](APPLICATION-DRIFT.md)定位偏离。记录使用[阶段关卡](STAGE-GATES.md)所列格式，内置与导入专家按同一专业、阶段和活动范围执行。
