# 项目做法档

何时读：P-1 生成或审阅项目做法档；专业阶段接手、复核或改变本范围的体验做法。实例只读当前活动范围、本专业段落和当前阶段的关卡要求。

## 生成与接力

- 用[通用模板](practice-profile-template.json)为实际业务写档。[类别提示](practice-profile-categories.json)用来找活动和比较参照。一个项目可混合多类，也可用表外描述；采购可参考管理类提示。以不同活动真实发生的范围划分 `scopes`，在范围内明确该做法影响的场景。游戏区与管理区可采用各自组织方式。
- 产品从用户目标写出核心活动、完整过程、核心场景、希望用户理解和感受到什么、规则与约束。各专业按[方向样张](../orchestration/DIRECTION-SAMPLE.md)补本职内容。每个专业段落写具体做法 `approach`、常见偏离 `pitfall` 和检验方法 `check`。不适用说明业务理由，信息未得写清待决问题。
- 在调性契约的 `references` 附 2–3 个真实参照，说明来源、借鉴点及实际观察情况。未访问写作未观察；来源暂缺写明缺口。范例是填档和选择方法的参考，产品事实以本项目实际依据为准。
- [完整游戏范例](practice-profile-example-game.json)用一局棋盘活动贯通五个专业段落。内置专业在档内采用对应游戏做法时，按各自指引索引读本阶段资料。交互与视觉设计分别读交互和美术的适用部分。自有专家按[导入要求](../orchestration/EXPERT-IMPORT.md)使用已适配方法。
- 在 P-1 合看中确认做法档与方向样张。已确认档作为调性契约的 `parts.practice_profile` 引用，记录 `path/version/sha256`；关卡和受影响成果引用当前 `tone_contract`。语义改动生成新版本，按既有变更机制复核受影响试做、截图和贴合记录。

## 内容触发的阶段义务

每个活动范围都填七项特征 `features`，逐项记 `value`（`yes`、`no` 或 `pending`）和 `basis`（实际业务依据）。类别用于描述。阶段关卡按特征读义务，相应范围取并集；专业对冲突提出取舍。缺档、缺字段、材料与需求矛盾或待定已影响本阶段，暂停受影响的工作。采用范例在活动范围写 `example.id`。改动范例的特征值须在 `example.deviations` 以特征名逐项写业务理由 `reason` 与专业审阅摘要引用 `master_review`，由贴合检查核对后随 P-1 一次合看确认。

| 特征 | 完成条件 |
| --- | --- |
| 场景为中心 `scene_centered` | D-2 按核心活动场景组织，检查场景和操作关系。 |
| 外观目标 `appearance_target` | D-1 写可观察特征与锚点，即使人未给风格词。E-2 将渲染列为关键选型，实际试做外观；E-2.3 骨架画出核心场景并作贴合复核，E-3 承接并复核首个可玩增量；Q-1 安排与样张对照。 |
| 素材家族 `asset_family` | D-4 先做 3–5 个代表元素，放回核心场景对照后再成套。 |
| 直接操作 `direct_manipulation`、连续动画 `continuous_animation`、关键时序反馈 `timing_feedback` 任一成立 | E-2 将渲染列为关键选型，实际做外观试做及手感可玩原型，检查时序、中断与预算；E-3 首个可玩增量作贴合复核；Q-1 安排录屏、时序记录与人的试玩。 |
| 流量高峰 `traffic_peak` | 研发与质量按项目负载目标安排压测，明确负载与测量方法；目标未知先给有依据的估计，实测结果另记。 |

已有阶段人审照常。外观试做用候选技术画实际核心片段。命中骨架要求时，E-2.3 按样张画出活动对象、状态与基本动作，用实际截图复核；E-3.1 核对承接记录仍有效。E-2.4 交试做、骨架与限制；手感原型交人随核心评审或已有试用安排试玩。命中首增量复核时，E-3.2 对照当前方向做贴合与 D-6 设计走查。Q-1 的证据是计划，实际验收到 Q-2 等执行时留存。

骨架与首个可玩增量分别留贴合记录（`skeleton_fit`、`increment_fit` 各用自己的文件）。比较当前契约图与本次实际截图；`reference_screenshot` 记录方向图的路径和摘要，`reference_viewport` 与 `viewport` 写相同的数值视口（如 `1280×800`），`comparison_state` 写要对照的代表状态或复现步骤。方向缺截图时，实际人工对照用 `reference_manual_review` 引用契约中的看稿记录，`mode` 写 `human`。仅本次成果缺截图时，人可实际看稿与当前方向图对照。其余贴合字段见阶段关卡。

设计自查和贴合检查按[应用感信号](APPLICATION-DRIFT.md)定位偏离。记录使用[阶段关卡](STAGE-GATES.md)所列格式，内置与导入专家按同一专业、阶段和活动范围执行。
