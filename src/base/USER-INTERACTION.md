# 用户确认、审阅提示与流程位置

何时读：需要用户确认、选择或补充；主要阶段完成后征求意见；显示多步流程的位置；结束一轮前判断能否停下。适用于所有角色，各 skill 只补充本角色的阶段名称和审阅节点。

## 1. 主动征求意见的节点

准备审阅、出现专业缺口或需要人的决定时，读取[具体说明](REVIEW-PREPARE.md)。

## 2. 审阅提示写什么

准备审阅、出现专业缺口或需要人的决定时，读取[具体说明](REVIEW-PREPARE.md)。

## 3. 确认选项

到达确认点时，先完成准备和自检，再展示上一节的内容。如果宿主提供选项式提问工具（能向用户展示几个选项并返回其选择），用它提供两个选项，文字保持不变：

- **确认，可继续**
- **需要进行调整，进入调整对话**

- 问题要能独立读懂：写清流程位置、成果与版本范围、待确认内容和下一步，不能只问"是否确认？"。
- 工具返回成功才算"已展示选项"。Markdown 列表、截图或"按钮如下"都不算。遵守工具的用途限制，不借用仅限澄清或仅限规划模式的工具来请求批准。
- 没有可用控件或调用失败时，展示文本回退卡：“本次无法显示确认控件。请回复‘确认，可继续’或‘需要进行调整，进入调整对话’，也可以只确认其中一部分、提出问题或直接写修改意见。”随卡给出具体成果、版本与确认范围，状态保持“待确认”。
- 需要在对话之外审阅（离线或请他人审阅）时，可用 [review.html](tools/review.html)：导入请求 JSON、核对后导出回复文件交回原任务；页面不联网、不自动批准，导出不等于已收到。
- 缺少必要事实，或需要在互斥方案中选择时，先问真正的问题或列出方案，不能用"确认，可继续"掩盖缺口。
- 彼此独立的确认项可以合在一次交互中，每项标明范围；用户可以只确认其中一部分。

## 4. 收到回应后

处理真实答复、判断停点或交出成果链接时，读取[具体说明](REVIEW-RESPONSE.md)。

## 5. 能否结束本轮

处理真实答复、判断停点或交出成果链接时，读取[具体说明](REVIEW-RESPONSE.md)。

## 6. 成果链接

## 7. 流程位置

在流程里做了工作、或回答进展的回复，第一行写：

**{流程}：共 {N} 步，当前进行第 {X} 步「{名称}」｜依据：{本轮之前已有的记录文件；本轮新开的流程写"本轮开始"；没有记录写"按你的描述推断，可查 {能核实的文件}"}｜{真实状态}｜下一步：{动作}（{由谁}）**

每一栏都填。首次给出完整路线；完成时写"共 N 步，第 N 步已完成，本流程完成"。

- **依据**：写本轮实际读过、本轮之前已有、能证明当前步骤的记录，例如工作状态文件或任务库。本轮刚写的记录不算依据；这一轮刚建立记录时，照样写"按你的描述推断"或"本轮开始"。人说了在哪一步、项目里却没有记录可核对时，同样写"按你的描述推断"，并写出哪份文件能核实；不只写"未能核实"。

- **下一步**：停下的回复都写，包括约定范围已完成时：下一项是什么、由谁触发，例如"你确认后我写对象与规则""质量工程复核显示效果，需要你安排"。整个项目都没有后续时写"下一步：无"。审阅提示里"回复后会怎样"就是下一步。
按顺序取第一种适用的情形；专业或问询流程不代表全项目：

| 情形 | 第一行写 | 步数与位置来自 |
| --- | --- | --- |
| PM 显示项目阶段，任务库有阶段里程碑 | 原样使用任务工具的 `stage_line`，补充信息另起一段 | 任务库 `continue` |
| 前台回答进展 | 本轮问询流程；项目实际阶段写在正文 | 本轮处理步骤，见前台 R01 |
| 在本专业流程里工作 | 本专业流程；缺项目记录时位置标“按你的描述推断”并给核实路径 | 专业登记 `stage_flows`，可用任务工具 `stage_flow` 查询 |
| 只有明确的局部计划 | 该计划的实际步数 | 计划本身 |
| 以上都定不了 | 项目阶段待核实｜当前事项：{…}｜依据：{…}｜{真实状态}｜下一步：{…} | 当前事项与已有依据；写出可核实阶段的记录 |

- 审阅节点不另计步。用户约定裁剪后按实际步骤显示，注明与原编号的对应；计划变化说明范围与原因。N、X 等占位符必须替换，无法核实的数字省略。
- 暂停和额度恢复条件另列，不改称任务待人审。
- PM 按 [PM-REPORTING](../orchestration/PM-REPORTING.md) 另附任务编号、下一任务与剩余数；专业角色可另显示自己的局部流程。
- **位置不等于完成量**：第 3 步不代表完成了 3/N。不显示没有依据的百分比或剩余时长；父子任务、工具调用、对话轮次不计入步数。
- **并行与返工照实写**：并行写"当前并行进行第 X、Y 步"；返工写明主步骤、回查步骤、原因和返回点，不默默回到第 1 步；合并审阅注明覆盖哪几步。

同时区分三类状态，不要混成一个"进行中"：

- **阶段位置**：主阶段，以及必要的回查或协同阶段。
- **工作情况**：未开始、正在处理、等你补充、等你审阅、等待协作方、修正中、已暂停、受阻、已完成。每个等待、暂停、受阻都指明具体事项、责任方和恢复方式；"正在处理"必须对应本轮正在执行或已核实仍在运行的任务。
- **成果状态**：草稿、待确认、已确认、待复核、已替代，并注明版本和确认范围。协作方返回"完成"，不等于成果已被验收，更不等于用户已确认。

等待协作方时说明谁提供什么、结果怎样返回、之后怎样恢复。只准备了交接文件时写"交接材料已准备，尚未发送"。
