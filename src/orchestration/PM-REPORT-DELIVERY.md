# 2. 向上报告

何时读：准备向上报告或核验投递回执。调用前置与其余操作见[原入口](PM-REPORTING.md)。

## 2. 向上报告

- **只向派发者回报**，一层一层往上：执行者报给本专业的 master，master 检验、整合后再报给派发它的人；PM 不直接收执行者的回报。任务来自别的专业的请求时，完成后还要通知请求方核对采用。
- **三个必报**：受领开始（有实际开始的记录）；受阻（立即报，写清卡在哪、需要谁做什么）；交出（自检完成，写成果与证据的位置，状态变为等检验）。交出不等于完成，派发者检验通过并采用后才记已完成。其余时机：首次拆分、计划改变、重要检查点、暂停与恢复，写父/子任务 ID、源修订、当前与剩余量、下一动作、成果证据、影响与待人事项。
- **先记录，再通知**：回报先写进任务库，再经实际通道叫醒派发者；没有通道时，事项留在派发者列表的"下一步"里。平台运行时记录本身就是通知：调度器看到交出或受阻，就拉起登记在任务上的派发者；派发者是 PM 时唤起 PM。
- **完成后推动**：由工具按任务关系算出，写进相关列表的"下一步"与"完成后"：派发者检验并整合；输入齐了的任务变为就绪，由它的派发者派出（平台运行时派发者登记，调度器拉起）；交付集合的出口记为完成，出口齐了提示关闭需求；来自请求的，通知请求方。
- **打回与返工**：没完成的任务重开原任务（编号不变，修订号加 1，旧的检验作废）；已完成且下游已在用的，建后继任务并注明替代哪一项；澄清改变范围或承诺的，走变更流水（C07）。返工写原因类别：执行问题、需求澄清、依据变化、其他，由检验或审查方写；制作方有异议时按 C24 §5 处理。
- 普通内部变化归并汇总；改变跨任务接口或输入、交付承诺、范围，或需要人决定时及时报告具体影响和建议。子角色在委托内自己解决内部问题，不把所有选择上交，也不悄悄改变顶层承诺。
- 任务 ID、协作请求 ID、执行尝试和实例分开。任务事件按 event_id 去重并校验修订冲突；没有更新时先核实，不假定完成或失败，不偷偷重派。
