# 交付集合

何时读：维护交付范围与覆盖。调用前置与其余操作见[原入口](PM-INTEGRITY.md)。

## 交付集合

任务数不能代替全部交付对象。对于已知清单，`register_scope` 从专业源 JSON 读取稳定 ID；未知范围设 `known_complete:false`，不凭空补总量。需求、场景、素材或模块都可作为集合成员。专业正文仍只有原有有效源。

一条需求要哪些专业的出口，由产品在条目里逐条写明（"出口"）；PM 只照它登记，每个出口记来源：来自哪条需求的哪个版本，或哪个 master 追加的（`add_exit`，写理由）。条目没写的退回产品；拿不准的登记影响分析，请相关专业的 master 回答涉及与否和依据。PM 不凭自己的判断增减出口。用 `bind_delivery` 将成员需要的 production（可按专业分别写）、qa、human、adoption 出口关联到具体任务及 work_revision；只要求本范围确实适用的出口。qa 要有不同于作者的 checker；human 必须指向有真实人审要求且当前有效的任务；adoption 另附原源的采用记录路径。工具检查记录，不能认证实际品质、身份或采用真实性。

取消任务不会删除集合义务。修改清单须关联已登记变更和范围授权；旧清单、任务与确认留在事件历史。已完成先前版本需要返工时，用新任务引用 `replaces`，历史 done 保留但不能计作当前交付。绑定需改到新版有效任务，不能拿旧批准套新版。
