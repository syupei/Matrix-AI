# 回答问询

何时读：有人问进展、自己要做什么、某个决定或成果在哪里时。

## 从哪里读

| 问题 | 先读 |
| --- | --- |
| 项目整体到哪了、在等谁 | `management/views/project.md`、`plan.md`、`digest.md` |
| 我现在要做什么、和我有关的有几项 | 名单中有多人时读 `management/views/people/<id>.md`；否则读 `plan.md` 的"现在等人处理" |
| 某个子方向的细节进度 | 项目总入口"详细进度"列链接的专业源，以及该工作区 `00-工作状态.md` 的摘要块 |
| 某个决定是谁定的、记在哪里 | 群摘要的"最近的人工决定"、各角色的确认记录与反馈索引 |

## 怎样回答

### 本轮问询与项目阶段

阶段行按 CORE 模板显示**本轮问询流程**，写出实际处理的步骤、当前位置和下一步。例如本轮按“核对记录 → 汇总答复”处理：记录缺失时仍处在“核对记录（待补记录）”，依据为“本轮开始”。这描述前台正在做的事，不是项目计划，不改变任何任务状态。

正文另列**项目实际阶段**及被问到的专业进展：有记录就附来源回答；没有记录写“未知，待记录核实”，说明去哪里、找谁核实。用户描述足以推断位置时可以标注“按你的描述推断”，同时列核实来源；仅问“进展怎么样”不提供阶段依据，不据此猜产品或设计做到哪。已经有记录时按记录回答，不为了展示问询步骤再次索要已存在的材料。


- 每个事实附来源链接，写明视图的读取时间或文件版本。
- 视图是派生物。它的事件修订落后于任务源时，按 X01 运行 `--render` 刷新再回答；刷新只重建视图，不改任务事实。
- 文件里没有的，说"未知"，并说明由谁、在哪里可以确认，例如"设计还没登记这一步，问设计角色"。不按印象补全，不估工期。
- 问题要专业判断才能回答时（例如"这个方案行不行"），不替角色回答：按 R02 转给负责的角色，或建议人到该角色的会话里讨论。
- 只回答被问到的范围。人要全貌时，给项目总入口的链接和三五行摘要，不复述整张计划表。

## 项目层和实例问询

优先按 [任务完整性](../../../../matrix/orchestration/PM-INTEGRITY.md) 用 query 读取当前任务：默认 project；岗位问题合并该岗位全部实例，具体实例问题用 instance，子项问题用 children 和 parent。摘要不能冒充全表；范围未展开或未登记须说明。执行者为空就写未登记，不把 owner 岗位名当实际实例。当前读取时间不代表当前执行回执，缺失进展再向责任方核实。
