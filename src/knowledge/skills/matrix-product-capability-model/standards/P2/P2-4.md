# P2-4 用户预期与信任建立能力

### 5. 用户预期与信任建立能力

能力定义

识别用户对产品行为、结果、作用范围、时间、风险、不确定性和可逆性的默认预期，发现这些预期与产品真实能力和运行事实之间的差距，并建立可预测、可解释、可控制、可修正的认知条件，使用户形成与事实相匹配、能够持续校准的信任。

本能力的目标不是无条件增强信任。合理信任既包括在产品可靠时敢于采用，也包括在能力有限、结果不确定或风险较高时保持必要警觉、检查与保留判断。

核心问题

用户认为接下来会发生什么，为什么会这样发生？

用户如何理解结果、影响范围、所需时间和后续步骤？

哪些结果是确定的，哪些存在概率、条件或产品能力边界？

用户是否理解风险、损失、可逆性和自身控制范围？

产品承诺、真实行为与用户预期是否一致？

当产品出错、结果变化或能力有限时，如何修正预期并维持有根据的信任？

用户是信任不足，还是已经形成超过事实的过度信任？

关注重点

行为与结果之间的因果预期；

结果的范围、时间、条件和影响对象；

风险、不确定性、概率和证据边界；

可逆、撤销、恢复、修正与人工控制能力；

产品承诺、系统表现和跨场景一致性；

失败、异常和能力局限对既有信任的影响；

信任不足与过度信任的双向校准；

说明强度与任务风险之间的匹配。

为什么重要

用户是否敢于行动，取决于其能否预测结果并理解风险。产品偶尔出错不一定立即失去信任；真正破坏信任的，往往是承诺与行为不一致、结果无法解释、边界被隐藏或用户失去控制。符合事实的预期使产品可被理解和依赖，也能防止用户在高风险场景中对产品能力形成过度信任。

常见错误

把信任理解为让用户更相信产品，只强调确定性和成功；

隐藏结果的不确定性、条件限制或作用范围；

使用模糊承诺，使用户无法判断何时完成、影响什么；

高风险操作前弱化后果，或对所有低风险操作反复强确认；

产品行为在不同入口、角色或时间下不一致，却只用说明补救；

出错后只道歉，不解释已有结果、控制范围和恢复可能；

以品牌语气、权威感或视觉品质代替真实可预测性。

简洁案例

AI 产品生成回答时，不应以绝对确定的语气掩盖能力边界。对重要任务，产品需要让用户知道内容由模型生成、哪些依据可核查、哪些部分存在不确定性，并保留检查和修正空间。目标不是降低或增强信任，而是让信任与结果可靠程度相匹配。

与相邻能力边界

“用户行为动机与引导能力”关注用户为什么愿意行动；本能力关注用户相信会发生什么、如何认识风险与结果。“用户心理状态理解与调节能力”关注不确定性引发的焦虑、警觉或失控感。产品真实状态、规则和结果由“产品逻辑”定义；具体确认与撤销机制属于“交互与反馈”；阶段、进度和恢复路径属于“过程与状态”；具体说明属于“语义与表达”。
