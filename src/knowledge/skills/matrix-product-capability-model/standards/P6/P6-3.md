# P6-3 等待与进度设计能力

> 《产品领域专家能力要求模型》P6 过程与状态 V1.0 原文，按章节拆分，正文未改写。

### 4. 等待与进度设计能力

能力定义

根据过程持续时间、可预测性、用户在场要求与结果风险，选择并设计可信的进度、阶段、剩余时间、时间范围、等待条件和可离开性，使用户在客观等待中能够判断任务是否推进、是否卡住、是否需要行动以及如何安排注意与时间。

核心问题

过程通常与最坏可能持续多久，波动来自什么，用户是否需要持续在场？

进度能否真实计算，适合百分比、完成数量、阶段、时间范围还是等待条件？

何时应立即回应，何时应解释过程，何时应转入后台并通知？

剩余时间是否足够可靠，更新、停滞、倒退和跳变时如何处理？

用户能否离开页面、锁屏、切换网络或并行做其他事？

等待依赖系统处理、网络、设备资源、他人、规则时间还是线下事件？

进度停滞多久应视为超时或转入异常过程？

已完成部分、正在处理对象和未开始对象是否可区分？

关注重点

客观时长、波动范围与可预测程度；

确定进度、阶段进度、数量进度、时间范围和等待条件；

即时响应与持续等待的交接；

剩余时间的可信度、更新频率和不确定性；

前台在场、后台执行、可离开性和注意安排；

暂停条件、资源约束、排队和外部依赖；

进度停滞、超时门槛与异常转入；

中老年、低熟练度和无法持续盯屏用户的判断。

原则性产出与验收证据

原则性产出： 等待策略矩阵、进度表达选择、时间范围与承诺、可离开性规则、停滞和超时阈值、前台转后台原则、部分进度与阶段结果要求。

验收证据： 用户对剩余时间和可离开性的判断；等待放弃、重复发起与误关页面；进度可信度；停滞发现；后台转移成功；完成时间误判；不同用户能否在无持续盯屏下完成。

为什么重要

等待的核心问题不是让时间看起来更短，而是让用户能正确分配注意、理解不确定性并保持控制。客观 4秒、20 秒或数小时都可能成立；没有事实支撑的转圈、百分比和“马上完成”会让用户以猜测替代判断。

常见错误

所有等待都使用无限转圈；

百分比快速到 90% 后长期停住；

给不可预测审核提供分钟级虚假剩余时间；

未说明能否离开，用户被迫持续看屏；

等待他人却呈现为系统正在计算；

进度只显示总量，不说明失败或暂停对象；

到达超时门槛后仍保持相同加载状态；

用游戏化动画分散注意，却不提供真实过程信息。

简洁案例

iOS 更新的进度可能因文件数量和操作类型而缓慢、看似停滞或重新开始。产品需要区分准备、安装与完成，说明电源等必要条件，并为真正无响应提供判断和恢复边界。优化安装耗时是技术问题；用户如何理解和安全等待归本能力。

与相邻能力边界

P5 负责用户发起后立即获知操作已接收；本能力负责随后持续等待。能力 5 负责用户离开注意现场后的结果到达，能力 6 负责等待超时、失败和降级。P2 判断等待焦虑与信任目标，P7 决定进度的视觉、声音与动态表现。
