# P7-6 感知可用性与包容性判断能力：详细阐述

> 《产品领域专家能力要求模型》P7 感知体验设计 V1.0 原文，按章节拆分，正文未改写。

## 7. 二级能力六：感知可用性与包容性判断能力

### 7.1 能力定义

判断产品的感知设计是否能被不同年龄、能力、设备、语言、文化和环境中的用户看见、听见、辨识、操作和理解；把可访问性视为产品质量底线，而不是上线前的合规补丁。

### 7.2 包容性不只服务“特殊用户”

以下情况都会暂时或长期降低感知与操作能力：

年龄增长导致视力、对比敏感度、听力和精细操作下降；

强光、暗处、反光屏幕；

公交车颠簸、单手操作、手指较大；

疲劳、焦虑、时间压力；

设备静音、耳机断开、网络中断；

语言不熟悉、文化差异；

低端设备、屏幕色彩和分辨率差异。

因此，可访问性往往同时改善普通用户体验。

### 7.3 可见性底线

对比

普通文本至少 4.5:1；

大文本至少 3:1；

关键图标、控件边界等非文字元素通常至少 3:1；

不应只依赖颜色传达状态。[S1][S2][S3]

产品经理应要求设计团队提供对比检测结果，而不是仅凭肉眼判断。

文字缩放

支持系统文字大小和缩放；

放大后不丢失信息、功能或操作；

关键文本不应被固定容器截断；

长文字、不同语言和中老年大字模式都需要真实检查。

WCAG 要求网页文字可放大至 200% 而不丢失内容和功能；Apple 也鼓励支持更大文字和动态类型。[S1][S4]

字体选择

避免过细、装饰过多或字形难辨的正文；

数字、字母和相似汉字需易区分；

金额、验证码、日期等关键信息应特别检查。

### 7.4 可操作性底线

WCAG 2.2 的 AA 最小点击目标参考是 24×24 CSS 像素，或具有足够间距；增强标准建议 44×44 CSS像素。[S15][S16] 产品经理不需要把这些值机械应用到所有平台，但应理解：重要控件、触屏设备、中老年用户和颠簸环境通常需要更大的目标与更充分间距。

验收问题：

主要操作是否容易点击？

相邻的“确认/取消”“删除/更多”是否容易误触？

点击区域是否只覆盖图标本身，而不是完整控件？

单手、左手和大字体模式下是否仍可操作？

### 7.5 不依赖单一感知通道

颜色状态配合文字、形状或图标；

音频提示提供视觉或触觉替代；

动画不作为唯一信息；

语音操作提供可见结果确认；

图表不只通过颜色区分系列。

### 7.6 动效与身体舒适

尊重“减少动态效果”等系统设置；

避免无必要的大幅缩放、视差和快速位移；

闪烁和强烈运动需要安全检查；

长时间使用产品要考虑视觉疲劳。

### 7.7 面向中老年用户的额外检查

中老年用户并不等于“不懂技术”，但可能具有不同的视觉、听觉、记忆和操作条件。设计不应简单切换成“老人版”，而应优先提升全局包容性。

重点检查：

字号是否足够并可调；

字重和对比是否清晰；

主要动作是否稳定、显性；

图标是否同时有文字标签；

是否避免仅靠短暂手势教学；

风险操作是否有清楚后果与恢复路径；

声音是否可调且有替代；

控件是否足够大、间距是否防误触；

页面是否因追求“年轻、时尚”使用大量细灰字和隐式操作。

### 7.8 环境测试矩阵

冻结前至少抽查：

| 条件 | 检查内容 |
| --- | --- |
| 强光户外 | 文字、图标、地图路线和状态是否可见 |
| 暗处与深色模式 | 对比是否过强刺眼或过弱不可读 |
| 静音 | 关键信息是否仍完整 |
| 嘈杂环境 | 声音是否不可用，视觉/触觉是否补足 |
| 单手操作 | 主要操作是否可达，误触风险如何 |
| 大字体 150%—200% | 是否截断、重叠、隐藏按钮 |

### 7.9 常见错误

把 WCAG 达标当作体验已经优秀；

只在开发完成后做一次自动检测；

设计稿只展示理想分辨率和默认字号；

认为“用户可以自己放大”就无需支持重排；

用颜色区分所有图表和状态；

为保持品牌风格拒绝高对比模式；

把中老年用户问题归咎于用户学习能力。
