### 0. 文档目的

《能力模型.md》和《二级能力.md》主要说明产品经理在感知体验方面应具备什么能力、遵守什么原则。

本文件进一步回答三个现实问题：

1. 产品经理不是专业设计师，为什么仍然需要理解字体、字号、色彩、密度、动效、声音和触觉？

2. 产品经理不亲自完成设计时，依据什么提出原则性要求、发现问题并验收结果？

3. 如何把“感觉不对”“不够高级”“有点乱”“看不清”等主观表达，转化为可分析、可讨论、可改进的产品判断？

本文件不是视觉设计、动效设计、声音设计或触觉设计的专业制作教程，也不要求产品经理掌握 Figma、After Effects、音频工程或触觉曲线制作。它提供的是产品经理完成以下工作所必需的背景知识：

在设计前定义感知目标；

与设计师或 AI Design 沟通原则与边界；

判断设计是否准确传递产品逻辑、状态、重点和风险；

识别感知设计对用户认知、心理、选择和行为的影响；

验收不同页面、不同状态、不同设备和不同用户群体下的整体品质；

推动产品从“可用”走向“好用”，再走向“喜欢”和“爱不释手”。

### 0.1 产品经理在本章中的角色

产品经理不是感知设计的专业实现者，而是四种角色：

| 角色 | 需要完成的工作 |
| --- | --- |
| 目标定义者 | 明确用户此刻应先看到什么、感受到什么、理解什么、担心什么或放心什么 |
| 原则提出者 | 对层级、强调、色彩倾向、节奏、声音、触觉、包容性和产品气质提出方向性要求 |
| 问题识别者 | 能指出“哪里不对”，并说明问题影响的是可见性、认知、情绪、信任、操作还是品味 |
| 结果验收者 | 判断设计结果是否服务产品逻辑、覆盖关键状态、适配目标用户并形成统一品质 |

### 0.2 感知体验的三层价值

本章所有能力都服务于三层递进目标：

第一层：可用

用户能够：

看得清；

听得到或获得替代信息；

找得到；

分得出不同对象和状态；

知道哪里可以操作；

知道什么重要、什么危险；

知道操作是否成功。

这一层是兜底。任何所谓“高级感”都不能以牺牲基本可见性、可辨识性和可操作性为代价。

第二层：好用

感知系统主动降低用户的理解、判断和决策成本：

重点自然突出，而不是让用户逐项阅读；

信息按任务阶段显现，而不是一次堆满；

状态变化连续、明确；

反馈强度与行为重要程度匹配；

视觉、声音、触觉互相支持，不互相干扰。

第三层：喜欢与强烈偏好

产品形成统一、克制、有细节、有个性的感知品质。用户不仅能完成任务，还会感到：

可信；

舒服；

精致；

稳重或活泼得恰到好处；

产品“懂我”；

长期使用不疲劳；

相比同类产品，更愿意打开和使用。

这就是产品从工具价值向情感偏好和“品味判断”递进的过程。

### 1. 感知体验的基础知识地图

### 1.1 感知不是装饰，而是产品信息传输系统

产品内部存在对象、规则、状态和结果，但用户无法直接看到这些内部逻辑。用户只能通过界面、声音、动作、震动和设备反应去推断产品正在发生什么。

一个简化链路是：

---

<a id="pdf-page-249"></a>

<!-- 原 PDF 第 249 页 -->

产品事实 → 感知刺激 → 用户注意 → 用户解释 → 心理感受 → 判断与选择 → 行为

例如支付已经成功，这是产品事实；成功页、金额、状态文字、提示音和轻微触觉是感知刺激；用户据此形成“钱已经付出、对象正确、无需重复操作”的判断。若刺激缺失或矛盾，即使后台事实正确，用户仍可能重复支付、焦虑或不信任产品。

因此，感知设计的验收标准不是“好不好看”，而是：

1. 是否准确承载产品事实；

2. 是否让目标用户正确注意和理解；

3. 是否产生与产品目标相符的心理影响；

4. 是否促成合理行为；

5. 是否形成一致的整体品质。

### 1.2 产品经理需要认识的常用术语

以下术语不要求产品经理进行专业制作，但需要理解其含义和可能影响。

| 术语 | 基本含义 | 常见影响 | 产品经理应关注的问题 |
| --- | --- | --- | --- |
| 色相 Hue | 红、橙、黄、绿、蓝、紫等颜色类别 | 建立区分、情绪倾向和文化联想 | 颜色含义是否符合场景与文化？是否与产品已有规则一致？ |
| 饱和度 Saturation/Chroma | 颜色鲜艳、纯粹的程度 | 通常影响刺激强度、活跃感、疲劳感和“廉价/克制”印象 | 是否所有元素都过度鲜艳？真正需要强调的内容是否反而不突出？ |
| 明度/亮度Lightness/Brightness | 颜色看起来明或暗的程度 | 影响可见性、空间层次、沉重或轻盈感 | 深浅差异是否足以区分层级？暗色模式是否仍清晰？ |
| 相对亮度与对比度 | 前景与背景在亮度上的差异 | 直接影响文字和控件能否看清 | 是否达到可访问性底线？是否只“隐约能看见”？ |
| 色值/色号 | 颜色的数值标识，如 HEX、RGB、HSL 或设计 Token | 便于一致复用，本身不等于心理含义 | 团队是否用语义化颜色，而不是到处写任意色值？ |
| 字体 Typeface | 字形风格与字族 | 影响可读性、正式感、亲和力、时代感与品牌气质 | 字体风格是否符合产品定位？是否为了个性牺牲阅读？ |
| 字号 Font size | 字符显示大小 | 影响可读性、层级和阅读负担 | 目标用户、设备距离和场景下是否看得清？能否随系统放大？ |
| 字重 Weight | 笔画粗细 | 影响强调、稳定感和小字号可读性 | 是否大量使用过细字重营造“高级”，却让普通用户看不清？ |
| 行高 Leading | 相邻文字行之间的距离 | 影响长文本阅读节奏和行间识别 | 是否过挤导致串行，或过松破坏段落整体性？ |
| 字间距 Tracking | 字符之间的整体间距 | 影响辨识、节奏和视觉气质 | 是否因追求风格导致中文、数字或英文难以连续阅读？ |
| 信息密度 Density | 单位空间内信息和控件的数量及视觉重量 | 影响扫描效率、认知负担、专业效率和压迫感 | 密度是否匹配用户熟练度和任务？高密度是否有清晰层级？ |

| 术语 | 基本含义 | 常见影响 | 产品经理应关注的问题 |
| --- | --- | --- | --- |
| 留白 Whitespace | 元素之间未被内容占用的空间 | 用于分组、分隔、聚焦和形成呼吸感 | 留白是否服务关系与层级，还是单纯把页面拉得很空？ |
| 对齐 Alignment | 元素在共同轴线或网格上的排列关系 | 影响秩序、专业感和扫描路径 | 相同类型内容是否共享对齐规则？ |
| 动效 Motion | 元素的位置、大小、透明度等随时间变化 | 解释空间关系、状态变化和操作结果，也可能分散注意或引发不适 | 动效是否有明确意图？是否过多、过慢或不可关闭？ |
| 节奏 Rhythm | 页面、动效、声音和反馈在强弱与时间上的组织 | 影响产品是从容、敏捷、紧张还是拖沓 | 不同页面和反馈是否有统一节奏？ |
| 提示音 Earcon | 用短声音表达状态或事件 | 可跨越视觉注意，适合确认、提醒和风险提示 | 用户静音、嘈杂或公共环境下是否仍能获得信息？ |
| 触觉 Haptics | 通过震动、阻尼或触感反馈表达操作和状态 | 强化确认、边界、选择和物理感 | 是否与事件重要程度匹配？是否过度频繁造成打扰？ |
| 视觉层级 Visual hierarchy | 通过大小、位置、对比、间距等建立阅读顺序 | 决定用户先看到什么、后看到什么 | 第一眼是否落在真正关键内容上？ |
| 视觉复杂度 Visualcomplexity | 页面中元素数量、差异、纹理和关系的综合复杂程度 | 影响第一印象、搜索速度、记忆与美感 | 复杂是否来自任务需要，还是缺乏取舍和秩序？ |

### 1.3 术语不是固定配方

产品经理要避免把专业术语变成简单口诀。例如：

红色不永远等于危险；在节日、品牌、文化或投资场景中可能有不同含义；

高饱和度不永远“年轻”，也可能造成疲劳或廉价感；

大字号不自动等于易读，若行长过长、字重太细或层级混乱，仍难阅读；

留白多不自动等于高级，可能只是信息组织不足和效率低；

动画多不自动等于精致，常常会分散注意、拖慢任务或造成身体不适。

研究显示，色相、饱和度和明亮程度可能影响唤醒度和情绪评价，但效果受到组合、内容、文化和场景影响；红色等颜色的正负含义也存在明显的情境依赖。[S9][S10][S11] 因此，本章使用这些知识来提出假设和检查问题，而不是用颜色心理学替代真实用户验证。

### 1.4 一次完整感知验收的基本顺序

产品经理可按以下顺序验收，而不是先问“好不好看”：

1. 事实正确：设计是否准确对应产品对象、状态和规则？

2. 基本可见：目标用户在真实设备、距离、光线和声音环境下能否感知？

3. 层级正确：用户是否先注意到最重要的信息和动作？

4. 心理适配：感知语气是否符合风险、信任、紧迫、舒适等场景？

5. 行为有效：是否帮助用户做出合理判断和操作？

6. 系统一致：跨页面、状态和通道是否保持统一？

7. 品质成立：整体是否形成符合产品价值的气质和品味？

## 9. 七项能力之间的关系

七项能力不是七种设计工种，而是一条产品经理验收链：

---

<a id="pdf-page-272"></a>

<!-- 原 PDF 第 272 页 -->

感知目标定义

→ 决定用户应该感知什么；

感知层级与重点判断

→ 决定用户先感知什么；

感知一致性与秩序判断

→ 决定这些规则能否被持续理解；

感知心理影响判断

→ 判断形式会带来怎样的情绪和选择；

多感官反馈判断

→ 决定通过哪些通道传递；

感知可用性与包容性判断

→ 保证不同用户和环境都能获得信息；

产品品味与品质判断

→ 让整体从正确、清晰走向统一、克制和强烈偏好。

其中：

前六项是产品品味的基础；

品味不能绕过可用性；

心理影响贯穿全部能力；

感知目标必须受产品逻辑约束；

语义内容由 03 定义，外在表现由 07 验收；

交互与状态决定发生什么，07 判断这些事实如何被感知。

## 10. 统一工作法：如何提出要求、评审和验收

### 10.1 设计前：提交感知要求简报

每个重要功能至少说明：

1. 用户和真实环境；

2. 任务与心理状态；

3. 首要、次要感知目标；

4. 关键风险；

5. 必须覆盖的状态；

6. 视觉、听觉、触觉通道要求；

7. 包容性底线；

8. 产品气质；

9. 不允许使用的感知方式；

10. 验收场景。

### 10.2 设计中：用问题而不是个人喜好评审

避免：

“我不喜欢这个蓝色。”

改为：

“当前品牌蓝同时承担主行动、普通链接和选中状态，导致用户无法区分操作优先级。请保留主行动的最高权重，并说明普通链接和选中状态的语义化颜色规则。”

避免：

“页面太挤了。”

改为：

“价格、取消政策、库存和促销同时处于高视觉权重，用户无法在比较房型时先识别总价与风险条件。

请重新分配层级，而不是简单增加留白。”

避免：

“动画再高级一点。”

改为：

“该动画需要解释卡片展开后的空间关系并确认用户选择，时长不应阻碍高频操作；开启减少动态效果时应保留状态确认。”

### 10.3 冻结前：至少做八类验收

1. 主任务验收；

2. 风险与异常状态验收；

3. 跨页面一致性验收；

4. 浅色/深色/高对比验收；

5. 大字体与多语言验收；

6. 静音、无触觉、减少动态效果验收；

7. 小屏、低端设备和真实环境验收；

8. 普通用户、商务用户、中年和中老年用户抽查。

### 10.4 结果判断的五级语言

为了避免“好看/不好看”，评审结论可以使用：

---

<a id="pdf-page-274"></a>

<!-- 原 PDF 第 274 页 -->

| 结论 | 含义 |
| --- | --- |
| 阻断问题 | 用户无法看清、分辨、操作，或会误判风险和结果 |
| 重大问题 | 层级、反馈或心理影响明显偏离产品目标 |
| 一致性问题 | 局部可用，但破坏全局规则和长期学习 |
| 品质问题 | 不影响完成任务，但造成粗糙、疲劳、不可信或气质偏差 |
| 优化机会 | 已达到目标，可进一步增强细节、节奏和偏好 |

这不是职级评分体系，而是一种问题严重度语言。

## 11. 二级能力验收总表

| 二级能力 | 产品经理必须回答的问题 | 典型证据 |
| --- | --- | --- |
| 感知目标定义 | 用户此刻应先感知什么、感到什么、做什么？ | 感知要求简报、关键状态说明 |
| 层级与重点判断 | 第一眼是否落在真正关键的信息和动作上？ | 一秒观察、任务扫描、眼动或可用性测试 |
| 一致性与秩序判断 | 相同含义是否使用稳定规则，跨页面是否像同一产品？ | 页面拼图、状态矩阵、设计 Token/组件语义 |
| 心理影响判断 | 色彩、字体、密度、动效等会带来什么情绪和选择倾向？ | 用户访谈、对比方案、行为数据、长期使用观察 |
| 多感官反馈判断 | 是否选对通道、强度和频率，关闭某通道后是否仍完整？ | 通道映射表、静音/无触觉测试 |
| 可用性与包容性判断 | 不同能力、年龄、设备和环境下是否仍能感知和操作？ | 对比检测、大字体、真实设备、辅助功能测试 |
| 品味与品质判断 | 整体是否价值一致、克制、比例准确、细节完整且长期耐用？ | 五秒印象、跨页面拼图、长期任务、竞品盲测 |

## 12. 常见误区汇总

1. 认为设计由设计师或 AI 完成，产品经理无需判断；

2. 把感知体验等同于颜色和美观；

3. 只看正常页面，不看加载、失败、空白和权限状态；

4. 只在高端设备和理想光线下验收；

5. 用年轻设计团队的视力和习惯代表所有用户；

6. 认为专业产品必须高密度，普通产品必须低密度；

7. 用低对比、细字体和大留白冒充高级；

---

8. 用强动画、声音和震动冒充精致；

9. 依赖“红色危险、蓝色可信”等简单心理口诀；

10. 让所有提示都强烈，最终没有真正的重点；

11. 只看截图，不体验连续任务和长期频次；

12. 设计系统只统一外形，不统一状态和感官语义；

13. 把可访问性当作合规任务，而不是产品质量；

14. 认为达到 WCAG 最低值就完成了体验设计；

15. 只选择知名产品的成功部分作为案例，忽略其问题和妥协；

16. 把个人审美包装成产品判断；

17. 把“品味”理解为固定的高端风格；

18. AI Design 生成结果漂亮就直接接受，没有检查真实数据、状态和包容性。

| Hue 色相 | 颜色类别；需考虑语义、文化和系统一致性 |
| Saturation 饱和度 | 颜色强度；影响显著性和刺激感，不宜无限提高 |
| Lightness 明度 | 颜色看起来明暗；影响层级、舒适和可见性 |
| Luminance 相对亮度 | 用于计算可访问性对比的测量概念 |
| Contrast ratio 对比度比值 | 判断前景与背景是否足够可辨的量化指标 |
| Typeface 字体/字族 | 字形风格与气质系统 |
| Font weight 字重 | 笔画粗细；与字号和对比共同影响易读性 |
| Leading 行高 | 行与行之间的垂直距离 |
| Tracking 字间距 | 整段文字字符间距的整体调整 |
| Type scale 字体层级 | 标题、正文、辅助信息等字号和字重体系 |
| Density 密度 | 单位视野内的信息、控件和视觉重量 |
| Whitespace 留白 | 用于分组、层级、聚焦和节奏的空间 |
| Grid 网格 | 维持位置、比例和对齐秩序的结构规则 |
| Motion easing 缓动 | 动画速度随时间变化的方式；影响自然感和节奏 |
| Reduced motion 减少动态效果 | 用户减少或关闭大幅动画的系统偏好 |
| Earcon 提示音 | 用短声音表达事件或状态的声音符号 |
| Haptics 触觉反馈 | 通过震动或力反馈表达选择、边界和状态 |
| Semantic color 语义色 | 按用途命名的颜色，如“危险”“主行动”，而非仅按色号命名 |
| Visual hierarchy 视觉层级 | 决定用户注意和阅读顺序的感知结构 |

## 15. 冻结说明

本文件是 07_感知体验设计 V1.0 冻结能力模型的详细学习层，不改变已确认的一级和二级能力结构。

6. 感知可用性与包容性判断能力；

7. 产品品味与品质判断能力。
