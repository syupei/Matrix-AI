# P4-5 导航、定位与返回设计能力

> 《产品领域专家能力要求模型》P4 空间与结构 V1.0 原文，按章节拆分，正文未改写。

### 6. 导航、定位与返回设计能力

能力定义

建立稳定、可解释的空间移动与定位关系，使用户知道当前处于哪个产品范围、账号、组织、工作区、对象、层级和任务上下文，理解可去往何处、切换会改变什么，并能返回上一级、原上下文、任务起点或安全位置。

核心问题

全局导航、对象内导航和任务内导航如何分责？

用户能否识别当前账号、组织、工作区、家庭、项目、行程或对象？

当前范围和选中对象是否在页面变化、滚动和深链接进入后保持清楚？

返回代表浏览历史、上一级结构、原对象、任务退出还是安全起点？

深链接、通知、搜索和外部入口进入后，如何补足位置与上文？

范围切换、标签切换、面包屑、历史与系统返回是否形成一致预期？

手机、PC 和其他端是否共享可迁移的空间逻辑？

关注重点

全局、对象内、任务内导航的层次与分责；

当前账号、组织、工作区、角色、对象与层级；

选中对象、父级归属、兄弟空间和可去方向；

返回、取消、关闭、退出和回到首页的不同含义；

深链接与非主入口的上下文补足；

范围切换前后的影响和位置保持；

多标签、多窗口、手机系统返回和桌面导航的差异；

迷失、循环、死路和错误上下文的识别。

原则性产出与验收证据

原则性产出： 导航层次、当前位置与范围线索、对象归属要求、切换原则、返回语义、深链接上下文补足、跨端导航迁移规则。

验收证据： 用户能否说出自己在哪里；错误账号、组织或对象操作；返回成功率；循环与死路；从通知、搜索和外部链接进入后的定位；跨端后能否迁移已有空间理解。

为什么重要

页面标题和导航控件存在，不等于用户有方向感。多组织、多账号、多对象和深链接产品中，位置感缺失可能导致错误对象操作、资料泄露或任务中断。可靠返回也是用户探索和恢复信心的基础。

常见错误

页面标题存在，但账号、组织、对象和父级上下文缺失；

切换组织后界面相似，用户不知道作用范围已改变；

返回只遵循浏览历史，用户却期望回到所属对象或任务起点；

深链接进入后成为孤岛；

标签、面包屑、系统返回和页面内返回表达不同空间逻辑；

结果页只提供首页入口，无法回查原对象。

简洁案例

Microsoft Teams / 365 从会议通知深链进入文件时，用户应知道文件属于哪个组织、团队、频道和会议，并能回到会议或文件所属空间。标签文字归 P3，切换动作和反馈归 P5，位置、归属与返回关系归P4。

与相邻能力边界

“入口与可发现性”负责进入，“导航、定位与返回”负责空间内持续移动和方向感。“任务路径”围绕一个真实目标组合多个空间，本能力提供可复用的通用移动规则。P6 主责时间中断后的状态连续，本能力主责恢复后位于哪里和如何继续定位。
