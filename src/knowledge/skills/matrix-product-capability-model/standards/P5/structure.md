# P5 交互与反馈：二级能力结构、边界与冻结结论

> 《产品领域专家能力要求模型》P5 交互与反馈 V1.0 原文，按章节拆分，正文未改写。

### 9. 二级能力树结构检查

### 9.1 七项能力的不可替代主责

| 行为问题 | 主责二级能力 | 不可替代理由 |
| --- | --- | --- |
| 用户意图应通过什么动作、输入或选择表达 | 1. 用户意图与操作映射判断 | 决定意图—动作—对象关系，不是线索是否醒目 |
| 用户能否识别眼前什么可以怎样操作 | 2. 操作可发现性与可理解性判断 | 负责动作层可供性、状态和范围，不是功能入口位置 |
| 系统如何确认接收、校验并说明结果 | 3. 行为反馈闭环设计 | 负责动作后的事实闭环，不等于撤销或长时过程 |
| 用户如何反悔、修正和从失败中恢复 | 4. 用户控制、撤销与恢复 | 负责主动控制和已投入工作保护，不只处理高风险 |
| 如何在高风险行为发生前防止重大错误 | 5. 防误操作与风险交互设计 | 负责按风险分级的预防和阻断，不能由一般恢复替代 |
| 等价动作如何跨路径与输入保持一致 | 6. 多路径与多输入方式一致性 | 负责迁移与替代输入，不等于单一映射或效率优化 |
| 如何支持连续、高频、批量和熟练操作 | 7. 高频操作效率与熟练度设计 | 负责重复成本和熟练度增长，不以少步骤替代安全 |

### 9.2 高频内部边界

意图映射 / 动作可发现： 前者判断动作是否准确表达意图，后者判断用户能否识别这一动作、范围和可用状态；动作自然但隐藏、或动作可见但语义错配，都是独立失败。

反馈闭环 / 控制恢复： 前者回答“发生了什么”，后者回答“我还能怎么办”；正确反馈不等于可反悔，有撤销入口也不能替代真实结果确认。

控制恢复 / 风险交互： 前者处理用户主动取消、行为后的反悔和错误恢复，后者优先处理重大错误发生前的预防、核对和阻断。

多路径一致 / 高频效率： 前者保证快捷方式与主路径语义相同，后者证明快捷、批量和自动化为何值得存在以及是否真正提效。

校验的归属： 输入约束与方式归能力 1，可用条件与现场理解归能力 2，校验时点和反馈归能力3，错误后的内容保留与修正归能力 4，高风险非法结果的预防归能力 5。

### 9.3 与相邻一级能力的边界检查

P1：动作与规则事实 vs 用户如何执行并获知结果

反事实检查：删除界面后，动作是否合法、对象是否正确、结果是否可撤回仍不明确，先归 P1；产品事实明确，只改变触发、校验、确认、撤销或反馈即可改善，主责归 P5。

P2：心理目标与判断机制 vs 行为实现机制

反事实检查：用户根本不理解、不信任、不愿意或无法形成正确预期，先检查 P2；心理目标已明确，问题在确认强度、控制权、反馈或恢复机制，主责归 P5。

P4：位置与路径 vs 节点内具体行为闭环

反事实检查：功能入口、操作区域、作用对象关系或任务节点错误，归 P4；用户已在正确位置，但触发、输入、焦点、校验、确认、撤销或反馈失败，归 P5。

P6：一次动作回应 vs 时间过程与生命周期

反事实检查：用户需要知道点击是否被接收、是否重复、短时校验和即时结果，归 P5；用户需要经历排队、阶段进展、后台运行、中断、过期和长期恢复，归 P6。

P7：反馈逻辑 vs 感官呈现

反事实检查：去除颜色、声音、震动和动效后，是否反馈、反馈时点、结果类型和下一步仍错误，归 P5；

逻辑正确但用户看不见、听不到、无法区分，归 P7。

### 9.4 产品经理判断力检查

七项能力的共同证据是产品经理能否：

明确用户意图、对象、风险、频率、输入方式和真实结果；

识别行为主因并与相邻一级能力确定主责；

在直接与确认、效率与安全、自动化与控制、统一与情境之间作出取舍；

将判断写成行为原则、允许差异、失败条件、降级方式与验收口径；

用代表性用户、错误、弱网、跨输入、高频和高风险任务证据复核结果。

流程图、交互稿、原型、组件说明、动效和埋点可以辅助判断，但不构成能力本身。

### 9.5 遗漏与合并检查

七项能力覆盖行为闭环的主要问题，且无须新增独立能力：

“输入与选择设计”已按映射、线索、校验、恢复和风险分责，避免另设横向能力重复；

“无障碍交互”作为所有核心任务的结果约束，重点由能力 1、2、4、6 承担，并与 P7 感知可用性协作；

“微交互”和“动效”属于实现粒度及 P7 感知呈现，不是独立产品判断；

“交互目标与风险界定”是七项共同前提，不单列通用研究能力；

自动化分别按意图授权、反馈、控制、风险、一致性和效率归属，无需新增“智能交互”。

当前未发现需要新增、删除、合并或调整顺序的结构性问题。

### 10. 冻结结论与应用约束

P5 V1.0 正式二级能力树为：

1. 用户意图与操作映射判断能力

2. 操作可发现性与可理解性判断能力

3. 行为反馈闭环设计能力

4. 用户控制、撤销与恢复能力

5. 防误操作与风险交互设计能力

6. 多路径与多输入方式一致性能力

7. 高频操作效率与熟练度设计能力

九类跨类型案例已完成覆盖、独立性、边界与反事实检验。七项能力均能形成可观察问题、原则性产出和验收证据；未发现需要合并、增删或改变一级定义的结构性反证，自 2026-08-25 起冻结为 V1.0。

冻结后继续遵守五项应用约束：

1. 先确认产品事实： P1 未明确动作条件、权限、状态和后果时，不用确认、撤销或反馈制造虚假确定性；

2. 动作可发现不接管结构： P5 只判断正确位置内的可操作线索与行为关系，功能入口和导航仍由 P4主责；

3. 即时闭环与长时过程分责： 接收与短时结果归 P5，等待、阶段、后台和生命周期归 P6；

4. 风险强度必须成比例： 不把多一步、强提醒或身份认证当作天然安全，也不以少步骤和高转化否定必要保护；

5. 跨人群与跨输入必须实测： 熟练触屏用户的成功不能替代键盘、语音、辅助技术、中老年和低数字熟练度用户证据。
