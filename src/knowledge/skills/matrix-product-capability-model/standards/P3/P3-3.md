# P3-3 状态语义表达能力

> 《产品领域专家能力要求模型》P3 语义与表达 V1.0 原文，按章节拆分，正文未改写。

### 4. 状态语义表达能力

能力定义

准确表达当前处于什么状态、状态属于哪个对象、已经发生什么结果、为何发生、影响谁、事实是否最终成立以及接下来可以做什么，使用户在行动中、行动后和外部变化发生时建立正确判断。

核心问题

“处理中”表示系统已接收，还是正在等待银行确认？

当前状态属于请求、订单、付款、文件还是用户？

结果是成功、失败、部分完成、取消还是仍不确定？

用户需要知道哪些原因、影响范围、时限、可恢复性和下一步？

关注重点

状态属于哪个对象、请求或阶段，是否避免把局部事实误写成整体事实；

状态名称是否表达用户关心的事实，而不是内部流程节点；

已接收、处理中、待外部确认、已完成和最终生效是否被正确区分；

成功、失败、部分成功、取消和结果未知是否有清晰语义；

状态产生的直接原因、影响对象、有效期限和可恢复性；

用户是否需要等待、检查、重试、补充信息或联系其他角色；

状态在页面、通知、邮件和历史记录中的含义是否一致。

为什么重要

状态语言是用户判断“现在成立什么事实”的直接依据。若产品把技术过程、请求状态和最终结果混在一起，用户可能重复支付、误以为文件已保存、错过处理期限或对产品失去信任。优秀状态表达让用户在变化和不确定中仍能掌握事实、影响与下一步，而不是只获得一个看似完整的标签。

常见错误

使用“完成”“成功”等总状态，却不说明完成的是请求、处理还是最终结果；

显示内部状态码或流程节点，用户仍不知道自己受到什么影响；

只说明失败，不说明已产生的结果、是否扣款、是否保存或能否恢复；

用一个对象的状态覆盖其他对象的并行事实；

把外部确认中的不确定结果表达成确定结果；

解释原因却没有提供用户可执行的下一步；

页面、推送和客服使用不同状态词描述同一事实。

简洁案例

付款异常时表达为“付款未完成，未扣款；订单将保留 15 分钟。银行暂未响应，你可以稍后重试或更换付款方式”，同时覆盖结果、资金事实、原因、时限和可用行动。

与相邻能力边界

P1 定义真实状态、转换规则与结果；本能力负责状态如何被命名和说明。P6 负责阶段如何推进、等待、中断与恢复；本能力负责用户如何理解每个阶段当前成立的事实。
