# 游戏与玩乐做法：产品

何时读：做方向样张或推进 P-1–P-7 时，项目做法档在该活动范围采用游戏产品做法。P-1 分工、确认与接续见 [方向样张](../../../../matrix/orchestration/DIRECTION-SAMPLE.md)。

## 怎样定义一局

- 先写玩家在玩什么，什么选择会改变胜负，紧张来自哪里，行动后有什么回报。掷骰只产生移动数时，挑战可能在选择路线或权衡下一回合的风险。每回合都只有一个可行行动时，重新核对这是否是预期的运气体验。
- 从开始、设置、进入一局、回合与事件、结算写到再来一局。每个可选动作连接触发、状态变更、可见反馈和下一次可选行动。标出退出、恢复、非法输入、平局及终局；分清本局和再来一局时继承的数据。
- 写清随机来源、可复现的输入、公平边界、节奏与预计时长。区分规则条件、帮助理解的提示和留给玩家的发现。需要人决定的胜负、公平与节奏取舍按已有审阅合看。
- 首个可玩范围保留足以感受核心循环的一条完整路径。用固定输入写规则验收，用实际试玩验证玩家是否看得懂选择和后果。把账号、设置信息、面板或后台列入首期时，说明它解决哪个真实问题及失去它的影响。

## 首稿怎样呈现玩法

选择一小段有前后关系的回合，在场景里同时看到可行动对象、选择、反馈及后续状态。例如先选岔路，再掷骰，看到前进或退回及接下来的操作。找与这段机制相近的实际参照，对照可借鉴的组织与反馈。首稿范围、实际预览和交付回执按[方向样张](../../../../matrix/orchestration/DIRECTION-SAMPLE.md)处理。

## 与事务处理的差异及复查

事务通常追求最短、可核对地办成一件事。玩乐中的挑战、风险和期待可以本身有价值，因此保留有后果的选择，并缩短进入下一次选择的等待。首稿列出了很多功能却说不出完整一局，或玩家过完准备流程仍没作出一次有意义的选择时，回到核心循环，先保留一条能进入、操作、结束和再来的路径。
