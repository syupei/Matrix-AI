# D-2 粗空间与流转

何时读：执行D-2粗空间试制或审阅A。调用前置与其余操作见[原入口](workflow.md)。

## D-2 粗空间与流转
入口：本范围设计基础已明确确认，且当前源与确认版本一致；否则留在 D-1。
- 列页面与状态清单时先归类：同构的做成模板加实例表（R08），不为只差文字的页面各出一稿。
- 先按 R04 试制核心场景并通过检查，再扩展依赖范围；任务总览可先做。
- 从核心活动推导场景、空间、视图或页面，把任务转成起点、动作、结果与返回。运行在网页上不等于用网页范式，页面、菜单、表格只是可选载体；不按对象名生成页面。双向核对：每个任务有承载，每个页面有任务或支持依据。
- 产品给出的集合与管理入口（职责、范围与行为），落到合适的页面、标签、侧栏或工作空间；不由界面标签倒推成员、权限或增删规则，缺口回产品。
- **2A 总览**：各场景、视图、页面、区域的职责，用户在哪、怎样到达与返回。**2B 粗骨架**：低细节表现主要活动区、必要信息、操作入口与反馈关系，能判断主次与顺序；不做装饰、最终色板、精细图标与长篇内容。**2C 路径**：箭头加动作标注或可点击骨架，写明起点、动作、去向、结果、返回/退出；改变结构的角色、权限与中断分支在此出现，只画已定义的分支。复杂项目可先审总览再审骨架，不强制拆成三次审批。
- 用 R09 选定的工具做可编辑的空间图与骨架，附短规格；页面编号稳定，用 DS-PG 等设计编号引用产品条目，不改写产品 ID；先做当前端的主要任务。最低可检查：看得见页面分布与元素大致位置（不是文字清单），动作与去向有标注或可点击。占位按真实尺寸、比例与形态表达将来的素材（R12），不做材质、插画与最终配色。
- **审阅 A**：展示页面分布、粗骨架与主要流转，以及核心活动的交互示意（可点击或关键帧：动作怎样作用于对象、反馈出现在哪里、局部与整体怎样衔接），请人判断页面是否合理、入口能否找到、顺序与返回是否符合预期、核心交互形态是否符合预期；确认范围是所展示的宏观结构、路径与交互形态，不含细节参数与最终视觉。审前自查断路与产品约束，附核心场景检查结论。未确认前不做依赖它的精细制作。

业务规则尚未给齐时，把**交互形态示意**与**业务结果**分开：依据已确认的核心活动，展示一次“操作对象→可见反馈→后续去向”的可点击候选或关键帧，标明仅演示、规则待定；不填合法性、计分、顺序或成功承诺。仅切换高亮不能证明对象操作与反馈。确实无法确定对象或动作时，列出具体缺口与受阻范围，其余骨架可交部分审阅，核心活动仍记未覆盖。
