# 游戏与玩乐做法：美术

何时读：D-1 或 D-4–D-6，且项目做法档在该活动范围采用游戏美术做法。由交互与视觉设计负责，按[外观目标](visual-target.md)和[素材流程](assets.md)完成本阶段记录。

## 怎样从参照做到场景

- 放大看参照，再缩回实际画面。提取轮廓、材质、光色、视角、深浅层次和细节密度。用可观察句写出想保持的关系，例如「棋子轮廓在落点亮起时仍清楚，可靠形状区分阵营；阴影在活动层比底板更强」。说明各条怎样帮玩家看懂对象、状态或重要结果。
- 按用途组织素材家族。例如棋盘与路径、角色与标记、骰子/行动对象、HUD、事件与特效。为各家族先定尺度、轮廓和状态差异。挑能暴露相互冲突的代表元素，放进同一张真实比例的场景看，逐条核对遮挡、层级、明暗对比和文字留白，再扩展已确认的家族。
- 照已授权的制作工具与交付方式选择媒介。造型清楚、可重组的件可用矢量；大量重复、需要运行中变化的图形可试程序化绘制；细节与质感受图像工具支持时可用已有接入。保留可编辑源和使用权记录，先比较目标端能否保持样稿里的特征，再决定做成整套。
- D-6 在实际运行画面按已确认特征逐项看：场景比例、角色可辨、状态色与轮廓、效果是否盖过行动、最小视口和减少动效。把差异定位到状态与对象。

## 与事务处理的差异及复查

事务组件强调识别和一致的操作习惯。戏剧性、空间感和反馈同样是游戏场景的工作内容。按[共用应用感信号](../../../../matrix/base/APPLICATION-DRIFT.md)定位偏离。比如可行动棋子只是统一控件换色，静止和可行动的轮廓完全一样，就回到家族锚点重做状态差异并放回对局读图。
