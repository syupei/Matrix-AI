# 游戏与玩乐做法：以活动为中心

何时读：方向样张任务或 D-1–D-3，且本范围以场景、直接操作或关键时序承载玩法。适用的成果和贴合记录见 [做法档](../../../../matrix/base/PRACTICE-PROFILES.md)。

## 怎样组织场景与反馈

- 按场景、HUD、浮层、特效四层组织：场景承载对象和局势，HUD 承载持续状态，浮层处理临时选择，特效表达过程与结果。按开始、设置、对局、关键事件、结算划分活动；暂停和结算优先覆盖在当前场景上，保留局面，避免整页切换。对局中把玩家观察、选择和影响的对象放在主视线。HUD 留当前决策需要的信息，例如行动方、剩余资源、目标进度。暂停、帮助、记录按需要呼出，返回时保留位置和局面。
- 让操作靠近对象。选中棋子显示可达格，点中合法格预示移动，键盘提供同样路径和可见焦点。情境菜单只暴露此刻可用的选择，留出取消和退出路径。比较直接操作、快捷动作和等价可访问入口。
- 逐拍写反馈：可操作提示 → 预备 → 动作 → 确定结果 → 轮到谁或下一步。让玩家在结果发生后看到因果关系；连发、跳过动画、恢复时检查状态与提示一致。预告和庆祝可变化，关键结果与损失保持清楚。用实际试玩调校时长并保留减少动态效果的路径。
- 试制时在目标视口摆足真实规模的对象，跑一次开始、行动、反馈、后续行动，补容易拥挤的关键状态。看主要操作能否留在对象与结果视线内，截图辅助判断空间，操作稿辅助判断动作与反馈。

## 默认模式与起始参数

游戏范围内，本表替代通用交互默认值中不适合玩法的时长与表现建议；可访问性、焦点与取消路径仍保留。以下是桌面回合玩法的试做假设，可按设备、动作密度、减少动态效果和试玩观察调整；不是所有项目的验收阈值。

| 反馈 | 起始假设 | 怎样验证或调整 |
| --- | --- | --- |
| 输入已接收 | ≤100ms | 量输入至首次可感反馈，区分网络裁决等待 |
| 骰子表现 | 600–1000ms，可跳过 | 玩家能认清结果；跳过仍到同一局面 |
| 逐格移动 | 每格150–250ms | 长路径加速或合并，不遮住落点因果 |
| 换手 | ≤800ms | 下一行动方可辨，等待不变成空停顿 |

## 与事务处理的差异及复查

事务界面往往需要跨记录导航、详查和批量录入。对局需要连续看到局势，跨视图切换会打断选择与反馈。按[共用应用感信号](../../../../matrix/base/APPLICATION-DRIFT.md)定位问题。比如选中棋子后，视线要离开棋盘才能找到下一步，并回到棋盘猜测作用对象，就把可行动作和结果移到当前对象附近。
