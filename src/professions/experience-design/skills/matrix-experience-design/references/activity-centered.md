# 游戏与玩乐做法：以活动为中心

收到项目方向样张任务或确认的游戏做法档时读。D-1、D-2 以当前调性契约和核心循环为依据。

- 以标题、设置、对局、事件、结算等场景组织；主画面留给活动对象及状态。需要时用场景浮层、暂停层和直接操作（如操作骰子或棋子）。保留键盘与等价操作。
- 预备、动作、结果、庆祝有区别。起始建议：可操作对象马上反馈，规则动作约 180–280 ms，关键结果约 300–500 ms；根据试玩调整，支持减少动态效果。失败及重要后果使用清楚、克制的反馈。
- 交回一张推荐方向的实际低细节渲染及目标视口截图，并用可点首稿覆盖核心循环。审阅试用脚本列动作、预期、可恢复状态；截图记录目标视口、捕获方式及成果版本。

给人看 P-1 样张及 D-1、D-2、D-4、D-6 之前，由另一实例优先换模型，只看调性契约、实际截图、相关文案。单对话标同一实例检验。记录是否像该品类、哪里像普通应用、哪句像说明书，写到具体位置。未通过先返工。无截图能力时交给人实际看稿，记录能力缺口与人的结果。

关卡状态用 `tone_fit_review` 指向 JSON，字段含 `outcome`、`checker`、`producer`、`mode`（independent、same_instance 或 human）、`artifacts`（当前文件路径及摘要）、`screenshot`（路径与摘要）、`viewport`、`capture`、`genre_fit`、`application_drift`、`copy_fit`。成果有变更须重查。

人工实际看稿则用 `human`，将记录摘要填入 `manual_review`，写明 `capture_unavailable`。
