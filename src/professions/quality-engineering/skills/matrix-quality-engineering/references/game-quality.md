# 游戏与玩乐做法：质量

何时读：Q-1–Q-4 且项目做法档在该活动范围采用游戏质量做法。阶段证据按 [做法档](../../../../matrix/base/PRACTICE-PROFILES.md) 和 [验收条目](acceptance.md) 整理。

## 怎样验

- 以一局和关键选择作索引。用固定输入或随机种子复现结果，查规则边界、胜负与公平、中断后恢复、重复动作是否生效两次。联网时按角色核对重连后的权威局面、迟到动作与并发行动。
- 设计还原以实际目标视口与样张并排，核对对象可辨、核心区域、关键状态和动作关系。反馈时序用录屏或时间戳，标出输入、首次可感知回馈、结果可见、下一动作可用。覆盖典型与拥挤场景、低性能设备及减少动态效果。记录实际条件、结果及做不到的部分。
- 试玩从可打开的版本、实际设备与起始状态开始。例如请人完成一局，自行找出可行动对象，遇到中断后恢复，并说明哪一刻知道动作成功、哪次选择有压力、是否愿意再来一局。记录观察、玩家原话和无法验证的范围。功能通过、还原通过和人的体验判断分别记录。

## 与事务处理的差异及复查

事务验收可以用数据与权限结果说明处理是否正确。玩乐也需要验证玩家能否连贯感知局面、选择、动作和反馈。测试若只覆盖按钮可点和数据已存，或截图只含初始画面，就补实际状态与时序。好不好玩交给实际试玩的人判断，计划或者代理检查只记录自己的证据层级。
