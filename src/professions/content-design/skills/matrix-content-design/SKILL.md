# 内容设计与审读

版本：0.9。

一个专业：负责产品与最终用户之间交互层面的文字，包括界面文案、提示与错误提示、空状态、通知与引导，以及语气与用语的统一；维护带键的文案表（R03）。程序内部的异常、错误码与日志由代码工程负责，法律条款的内容由法务负责。项目设立了内容专业时由它承担；没有设立时按缺专家处理（CORE §7）。共同规则见 C03，本 skill 只写方法。

## 启动

有项目任职或具体任务包时，先按 C90 核对身份与范围；执行实例只处理派给它的文案。

1. 读 [共同底线](../../../matrix/base/CORE.md)、[共用规则索引](../../../matrix/base/GUIDANCE-INDEX.md)、C03 和 [指引索引](GUIDANCE-INDEX.md)。
2. 从产品索引读 STYLE 的受众、场景与语言要求、相关 ACCEPTANCE、事实依据与认可样板；项目的具体要求留在这些源，不写进本 skill。
3. 建立或沿用文案范围索引（R02），确定本轮覆盖范围。

## 工作流

1. **定判据**（R01）：读者此刻要理解或决定什么、文字须提供什么；术语、必须保持的事实/条件/后果、锁定原文与可改写范围；语气随正文、操作、错误、风险调整（年轻不默认玩梗，严谨不默认公文腔）；配少量中文正反例。
2. **成稿**：撰写或转译，保留事实来源。
3. **审读**：按读者完成任务的顺序通读整组文字（不只是把形容词换成口语），依次查：
   - 事实与行动：对象、条件、数值、结果、不确定性和下一步有依据；未知原因不猜，恢复动作真实可用。
   - 理解与情境：读者看得懂当前情况与可选动作；无内部核查口吻、错误码或原料；按钮、链接与目标一致。
   - 表达与精简：符合具体要求；无空泛宣传、套话、说教、整组重复；以"删掉是否损失必要信息"判断，不以同词重复或句长直接判错。
   - 实际呈现：放回真实宽度、层级、状态和动态值，查截断、换行、顺序与可访问名称；按设计 skill 制作并回读工具中的实际文字，不绕过其制作规则。
4. **记录与交接**（R02）：写位置、原文、违背的判据、修订、语义是否保持；成稿写进文案表，按键交给设计与研发，改动按 C04 §5 通知已在使用的下游。

样板默认一套推荐，随调用方既有审阅校准，不增加逐句人审；用户认可才标"已认可"，作者自拟只标"候选"。

## 硬性关卡

- 不以"自然度 90 分""全部符合"代替具体问题。
- 只审了代表样本或读不全时不称全量覆盖。
- 确定性工具只核对已明确的术语、标点、变量和禁用项，结构化交付工具只核对版本、引用与证据是否存在；语境与自然度必须实际审读。工具不可用时按可读范围审查，不虚报执行。

## 职责边界

- 措辞、句序和长度在原授权内修正；改变产品事实、风险、结果或承诺回产品。
- 名称按 N01 核对状态与依据，不以"更有创意"为改名理由。
- 不为普通改稿安装外部框架；独立审读实例只按既有授权调用。
- 隐私政策、用户协议等法律文本，条款内容不由本专业起草，按缺专家处理（CORE §7）。人选择之前只交送审材料：事实表（收集什么、为什么、存多久、给谁、怎样同意）、请专家判定的要点、可读性判据，以及应用内的同意与权限提示（带键的文案表）。

## 完成的含义

本轮范围的文字已审读，修订已合入唯一成稿源并回读实际呈现；未覆盖范围与待实现验证项写明责任。安装本 skill、阅读标准或生成文件，都不等于已审读或质量通过。
