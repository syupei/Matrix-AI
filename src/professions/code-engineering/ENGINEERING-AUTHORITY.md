# 5. 谁决定什么

何时读：确定工程决定权与技术评审。调用前置与其余操作见[原入口](ENGINEERING-FLOW.md)。

## 5. 谁决定什么

| 决定 | 例子 | 谁决定 |
| --- | --- | --- |
| 产品承诺 | 删掉某个功能、改变某个操作的含义；改变用户可见结果的算法与策略（排序推荐、匹配、计价与结算、随机与公平） | 产品负责人；研发只提建议并说明代价 |
| 必须确认 | 费用与供应商、数据存放与归属、账号与支付方案、上线后的运维责任、难以回退的核心技术（客户端技术与语言、是否需要服务端及其形态、主数据存储） | 人；可在人划定的边界内委托 AI |
| 条件确认 | 扩展与可用性策略、代码组织、测试策略、主要框架与库、接口与数据格式、部署方式 | 默认委托 AI，并经独立复核；人可以展开或收回 |
| AI 自主 | 模块内实现、内部数据结构、不改变行为语义的算法、命名 | AI，留变更记录 |
| 放宽质量门槛 | 跳过测试、放宽性能预算、带已知缺陷发布 | 人；AI 不得自行关闭或放宽检查 |
| 发布 | 是否发布、发布范围与分批计划（各批对象、观察时长、继续与停止的条件）、带已知 Q0/Q1 缺陷发布 | 人，不可委托；AI 按已确认的计划逐批推进，触发停止条件时直接回退 |
| 改动生产环境 | 修改生产数据、线上配置 | 人审过脚本或步骤再执行；AI 默认只读（OPERATIONS §5） |

**关键技术选型**：不论属于哪一级，对产品或实现有重大影响的决定都列为关键技术选型，由人确认：E-2 中列在核心评审包第一节，人一次确认；E-3 中新增的合批交人，确认前不合入。筛查的六个问题与常见类别见 matrix-code-engineering-solution 的技术评审指引 §2。

不可委托的四项见 [CORE](../../base/CORE.md) §4。多人项目中"人"指该范围的决定人，见 [TEAM](../../orchestration/TEAM.md)。委托边界、核心评审与回升条件的做法，见同一份技术评审指引。
