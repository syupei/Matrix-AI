# professional-agents-kit v0.27

本版补强需求变更、任务完整性及同岗位多实例管理。用户已完成提交前审阅并明确授权提交、发布；对应源码的维护检查与行为发布门槛已通过。

本次补强长程项目的任务完整性：需求在对话中新增、修改或撤销后，能够关联专业影响分析与实际任务调整；PM 管项目层任务，专业实例管理内部子项，同一岗位可以分派多个实例。

## 主要变化

- **交付集合与任务关联**：从有效专业源 JSON 读取稳定对象或需求 ID，关联制作、独立检验、必要人审和采用出口。按本次范围选择适用出口；未知范围如实保留，取消任务不能使必需交付从统计中消失。全量关闭检查集合覆盖。
- **实质变更闭环**：原话先落盘并登记分析任务，各专业责任方返回影响、无影响或待分析依据，准备自己的任务调整。PM 汇总计划；评估未齐、任务没有处置或修订冲突时不生效。受影响范围不能按未同步的计划启动或关闭，独立任务继续。
- **变更流水与任务弃用**：需求变更自动生成项目内唯一递增编号（如 CHG-000001），保存登记时间、原话、来源和计划处置；支持流水查询与只读视图。受变更撤销的任务登记为“已弃用”，自动备注“受 （编号） xxx 需求调整变更”，保留原任务、完成事件及成果。弃用项单列，不计完成或剩余，也不替代原交付义务；未评估的撤销不能用普通取消绕过。
- **计划原子写入**：PM 的项目任务命令和各 owner 准备的命令在同一任务库事务中应用，失败整体回滚，原事件 ID 可幂等重试；不放宽 owner 权限，不代签专业检验或人审。文件、消息与数据库仍不构成跨系统事务。
- **保留历史与版本边界**：制作完成、检验、人工决定和采用分别核对。已完成任务可关联新版返工后继，保留原完成事件；登记成果摘要后，同路径内容变化会提示复核。未登记摘要的成果仍需责任方核对。
- **只读审计**：按指定任务返回缺口与修复动作；读取不创建数据库、不迁移旧库结构。涉及父项或关联交付的未同步变更同样阻断关闭，独立兄弟任务可继续。
- **按层问询**：新增项目层、直接子项和全部任务查询，可按岗位或具体实例筛选。默认项目问询不混算父子；取消、弃用及历史完成待复核项分别呈现。未登记的范围不计成零剩余，读取时间不当作最新执行时间。
- **同岗位多实例**：登记稳定实例 ID、岗位、执行端点与独立写范围。不同项目任务可分派给不同实例，各实例自行拆解内部任务；派发检查已登记的实例占用、写范围冲突和并发额度。可配置每个实例的计划命令批量上限，不依据模型名称推断能力。
- **回归修正**：PM 查询显式路由到流程位置规则，领域长讨论提供可选专业会话与结论归档说明；QA 在业务资料不齐时继续起草有依据的接口层越权检查，不补造取消条件、退款或权限例外。首次遗漏样本保留为失败，最终回验结果另列。
- **暂停与恢复**：保存被插入工作打断的任务版本、检查点、剩余项和恢复条件；审计提出恢复候选。版本变化需重新核对，恢复只转为可规划状态，不自行启动后台任务。

已授权的登记、影响分析安排与内部计划准备不新增用户确认点；仍保留真实事实缺口、专业审阅及超出委托决定的人工入口。

公共做法集中在 `collaboration/PM-INTEGRITY.md`，技能入口及相关索引只增加必要路由。关系存入现有任务库，专业正文仍留在原有效源。

## 验证

- 本地候选构建通过：199 个运行文件、381 条本地链接。
- 维护测试 136 + 93 + 14，共 **243 项通过**，其中 40 项完整性机制测试（本次追加 10 项，覆盖编号、幂等、并发、弃用、历史、停止证据、绕过与关闭约束）。
- 四项受改技能通过 skill-creator 格式验证。
- 当前发布源码的隔离 v0.26 → v0.27 升级通过：原任务数据库与业务文件不被安装器改写，新增工具安装成功，重复安装零额外写入，兼容读取原任务库。
- 行为对比覆盖 **54 个场景、223 项判据**。v0.26 基线全部实际运行，共 63 轮；最终候选实际新运行 20 个场景、28 轮，另有 34 个场景、35 轮按既有协议复用基线样本，限岗位文件字节一致，并保留原回复、工具轨迹及复用来源。
- 发布矩阵：基线 217/223，候选 223/223，所测范围无退步。基线遗漏专业会话/归档、接口越权检查，以及在专业分析前取消任务；首次候选还遗漏个人问询的流程位置。失败记录保留；PM/QA 路由修正及所有已改岗位均有最终源码实际回验。两次模型容量错误作为执行失败保留，补跑成功，不计作行为通过。
- 需求新增、修改、撤销、流水编号四个合成项目场景，各三轮。最终候选实际保存变更编号、原话和分析任务，按岗位与实例查询；保留旧完成历史，不伪造专业回执或人的批准。专业评估不齐时撤销保持候选，不提前记为已弃用。

评测使用同一 CLI 及相同预写输入，每个判据为一组样本，由实施会话回读实际回复及相关成果评分，未经独立人工或盲审。复用检查只能证明岗位文件未变；公共规则相对基线有变化，首轮候选实际运行作为补充诊断证据，不能当作最终源码的新运行，也不能据此保证所有公共规则效果或统计意义上的性能提升。

机制测试中的执行、检查与批准均为模拟。模型场景使用合成任务库，止于接收、分析安排与计划准备；未取得真实专业回执或执行完整交付链。任务关系与摘要检查不能认证真实身份、专业质量或消息送达；不同 checker 标识也不能单独证明实际独立检验。

## 兼容与后续验证

- 既有任务保持原有权限和状态语义；新集合和变更约束按明确接管范围启用，不批量补签或重开历史。
- 端点登记与派发约束已实现；PM 分派到宿主实际投递、接单、回传的自动衔接尚未新增，未通过真实多实例完整链验收。
- 岗位聚合依赖明确的岗位/实例映射；无法映射的责任方会单列，不能据角色名称猜实际执行者。实例登记不证明在线，工具也不是操作系统文件锁。
- 审计可限定任务输出，当前仍读取已登记任务元数据与相关摘要；尚未进行大规模任务库响应时延基准，不承诺任意规模下实时回答。
- 清单接入当前支持 JSON 数组及对象 ID 选择；其它专业格式需先提供可追溯的集合来源，不能声称已自动覆盖所有文档。
- 本次发布门槛覆盖上述 54 场景矩阵及其复用边界；跨模型能力分档、持续后台调度、真实专业回执、多实例完整交付链和目标设备上的视觉体验仍未验证。
- 本次仅发布技能包，不升级使用方项目。后续正式发布继续受对应源码行为证据与无退步检查约束。
