# professional-agents-kit v0.26

本版补上研发中安全、性能、运维与部署的具体做法，并规定把具体工作交给其他执行者时怎样准备任务包。执行者可以是外部的 Agent，也可以是群里的人。

## 主要变化

- **三份专项检查指引**（`collaboration/SECURITY.md`、`PERFORMANCE.md`、`OPERATIONS.md`）：
  - 按需读取，按研发阶段写清每一步做什么。
  - "默认"指中型及以上默认要做；"建议"按风险选用；小型档只保留最低限度。
- **中型及以上默认要做的**：
  - 自动检查默认带依赖漏洞扫描与凭证（密钥）扫描。有已知高危漏洞的不能合入、不能发布；放宽由人决定。
  - 每个有归属的对象（订单、消息等）至少一条越权验收：别人看不到、改不了、删不掉。在接口层检验。
  - 研发承接用业务语言写出"最多能停多久、最多能丢多少数据"；技术方案据此定部署与备份；发布前的恢复演练按这两个数计时。
  - 骨架就带日志、健康检查与告警。日志不记个人数据与凭证，并实际制造一次错误来验证。
  - 技术方案阶段做环境规划：几套环境、测试数据从哪来、谁有生产权限。要有预发布环境。
  - 交接包增加四项：由非作者照着重建一次环境；证书、域名、账号、许可证、付费服务的到期清单；费用告警；值班与事故处理。
- **AI 接触生产环境**：默认只读。改生产数据或线上配置，先写成脚本或步骤，由人审过再执行。
- **只写进指引、作为建议的**：数据与威胁清单、加密与密钥、外部 AI 服务、性能指标进入自动检查、容量与成本模型、长时间稳定性、部署与数据流向图。
- **外发任务包**（`collaboration/TASK-PACKET.md`，研发与设计共用，人和 AI 用同一格式）：
  - 粒度标准："新人测试"（只看任务包就能做完并自检）、只改一个模块、有自己的验收、用到的规则已确定或已标明待定。
  - 任务包内容：带来源编号与版本的摘录、每条的性质（必须保持、范围内可自定、待澄清）、约束、运行环境（不放凭证与真实个人数据）、完成证据、不提供的背景、找谁提问。
  - 回交只算执行者自检：新增依赖按关键技术选型筛查，设计偏差交设计判断，验收由质量验证独立检验。
  - 执行者自带的规范与本项目冲突时，接口契约、验收、设计规格与委托边界以本项目为准，模块内写法按执行者自己的规范。抽查比例按执行者被推翻的记录调整，由人决定。

## 版本

- 有更新：研发承接 0.12、技术方案 0.5、增量构建与发布 0.4、质量验证 0.3、交互与视觉设计 0.22。
- 未变：项目前台 0.1、项目管理 0.11、产品 0.25、专业协作 0.10、内容设计与审读 0.5、产品能力模型 1.0。

## 检查与行为评测

- 维护测试 136 + 53 + 14 项全部通过；367 个链接有效。
- 从 v0.25、v0.24、v0.17 升级的端到端检查都通过，每次 12 项。
- 行为评测新增 8 个情境，现在共 50 个情境、203 项判据。新增的情境：
  - 有高危漏洞的依赖；
  - 只写了"系统要稳定"时的质量要求；
  - 越权验收；
  - 运维交接包；
  - 搭骨架与工程基础；
  - 有人要求直接改生产数据；
  - 把一个按钮任务外发给外部前端 Agent；
  - 外部 Agent 交回的结果。
- 评测范围：
  - 研发承接、技术方案、增量构建与发布、质量验证、交互与视觉设计五个角色有改动，它们原有的 27 个情境在 v0.26 上重新运行；
  - 新增的 8 个情境在两版上各跑一次；
  - 其余 15 个情境所用角色的文件与 v0.25 完全相同（发布工具逐文件核对），沿用 v0.25 发布时的回复。
- 结果：v0.26 通过全部 203 项，v0.25 通过 196 项，没有退步。
  - 新增的 8 个情境里，v0.25 已经通过 5 个：依赖漏洞阻断合入、用业务语言问服务目标、越权验收、不直接改生产库、回交只算自检。原有规则已经覆盖这些判断。
  - 差别在 3 个情境：
    - **搭骨架**：v0.25 只通过 1/5，没有不记个人数据的日志、健康检查与告警验证、预发布环境、默认的依赖与密钥扫描；v0.26 全部写到。
    - **运维交接包**：v0.25 通过 2/4，有证书到期与账单告警，但没有交接前的测试告警、响应时限，也没有由非作者重建环境。
    - **外发任务包**：v0.25 通过 4/5，没有列出不提供的背景。
- 评测方式的限制：
  - 本次在另一个 Agent 会话中进行，每一轮由全新上下文的子 Agent 执行，回复由维护会话原样记录。
  - 评分由执行本次修改的会话完成，未经人工复核。每个情境只运行一次，情境里没有项目文件，任务包与交接包都只到草稿。
  - 沿用的回复在记录中标明了最初生成的版本。
  - 共享规则有新增与改动，所有角色都可能读到。我判断不影响沿用的情境，但工具无法核对。
  - 文字情境证明不了扫描、告警与环境真的配置好，也证明不了外部执行者按任务包交付的质量。
