# v0.28 候选变更说明

多实例协作现在区分专业能力、任职和实际执行实例。产品、设计、研发承接、技术方案、工程实现、验收、项目管理、前台和协作入口共用负责人/执行者规则：负责人处理授权内拆解、安排与整合，执行者只处理分派范围；人的关键判断和保留审阅继续有效。文案校核沿用调用方任职，能力标准仍为共享参考。

- 在现有任务库中登记任职范围、可调配实例及专业参与义务；工作流 PM 只管理获分配的任务树。专业负责人可安排本层任务，不能直接调走其它团队实例。新增法务、安全等专业可按配置参与咨询或必需审查，未完成的审查会阻断相关关闭与下游启动。
- 每个实例使用独立候选工作区，共享专业源由指定负责人整合；回交绑定任务、输入和任职版本。新增宿主派发接口连接已有任务库与协作账本，区分已投递、已启动、已回交和已验收，处理重试、迟到回执及过期结果。
- 授权内阶段决定与人工确认分别记录。阶段检查核对授权范围、来源、期限、成果版本及独立检查；实际作者与决定者不能自行签独立通过。发布决定仍须真人决定。
- 新增宿主侧工具网关与受保护文件参考适配器：每次调用核对实例、任务、运行、授权修订、连接、操作、资源、配额和会话占用。旧授权变更、撤权、越界与不确定重复操作被拒绝；未授权替代工具不会自动启用。

## 视觉风格：先定样子，再定做法

用户给出风格词或样稿时，设计先把它写成外观目标，再决定用什么做法实现，避免把"3D 风格"直接做成"用三维模型搭"。

- **外观目标**（设计 D1）：逐条写出可观察的特征，包括构图与视角、细节密度、光线与氛围、色彩、材质、人物比例与神态、动态感；每条标"必须保持"或"可调整"，并注明出处。风格词只描述外观；样稿是生成或手绘的静态图时，标"可制作性未验证"。
- **画面实现方式是关键技术选型**：
  - 设计提出候选（2D、分层、预渲染或实时三维、混合）和推荐，研发评估目标设备上的运行；比较还原度、交互需要、美术成本与由谁来做、成套一致和素材权利。
  - 由人在风格锚点确认时决定，不新增审阅节点；不能作为委托内的常规决定。实现中途改换做法，要重新交人决定。
- **锚点实做、并排对照**：风格锚点用候选做法实际做出一小块画面（场景局部、带动作的角色、关键物件），在目标设备上与样稿逐条对照。先做推荐的一种；达不到或几种做法代价差别大时，再做第二种。都达不到时，调整目标还是增加美术投入由人决定。
- **走查与美术回交**：实现走查加"外观还原"，必须保持的特征明显不符记为实现偏差；美术交给执行实例时，任务包附样稿、特征清单、已定做法和授权工具，回交的对照图只算自检。
- 设计新增按需读取的指引 `references/visual-target.md`；产品风格选项、技术方案的关键选型类别与风险试做（外观可达性）同步；设计工作区模板加"外观目标"和"外观还原"两栏。

## 能力边界

身份认证、受保护凭证、实际模型调用与唤醒由宿主接入提供。网关参考适配器不等于外部设计服务已经适配；各服务须逐项验证权限粒度和会话隔离。实例仍可绕过网关访问终端、网络、浏览器或共享凭证时，不能称为强隔离。任务记录与检查脚本不认证人的身份、不代替专业质量验收，也不自动创建后台守护进程。
