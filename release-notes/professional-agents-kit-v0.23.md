# professional-agents-kit v0.23

本版让项目的主对话保持精简。新增"项目前台"角色作为主对话入口，PM 退到后台调度。主对话启动时检测宿主能否创建子 Agent，经你一次授权后，在每个角色的第一项任务就绪时才为它创建子 Agent。

## 主要变化

- **项目前台（新角色 project-front-desk-agent）**：
  - 作为主对话入口：按项目文件回答进展问询，没有记录就说未知；登记新要求与反馈，转交给负责的角色；展示 PM 准备好的待决事项，记录真实答复。
  - 不调度、不做专业判断、不改专业成果。
  - 适用于多人或中型以上的项目。小项目、只有一个人或宿主不支持子 Agent 时，可以不设前台，由 PM 兼做这些事。
- **启动检测与按需拉起**（`collaboration/RUNTIME.md` §4）：
  - 每次新会话启动时，按实际拥有的工具检测：能否创建子 Agent、能否续接、能否并行、同时最多几个，结果登记到 `collaboration/runtime/host.md`。
  - 第一次检测到可用时，请你授权一次，之后不再逐次询问。
  - 不在启动时把全部角色拉起来；某个角色的第一项任务就绪时才创建它。交给它的只有任务包，不带主对话的聊天记录。
  - 宿主不支持或没有授权时，在主对话里切换角色。
- **PM**：
  - 有项目前台时在后台运行，只在新需求、角色上报、任务完成或需要合批时被唤起。
  - 任务工具新增 `configure`：登记前台身份后，前台可以直接录入人工决定。
  - 项目总入口显示进行中任务的执行者，例如子 Agent、独立会话或主对话。
- **入口说明**：安装后的入口块把项目前台列为多人或中型以上项目的主对话入口。

## 检查与行为评测

- 维护测试 136 + 49 + 14 项全部通过。新增的测试覆盖：
  - 前台身份登记后才能录入人工决定；
  - 项目总入口显示执行者；
  - 发布门槛对沿用回复的核对。
- 从 v0.22、v0.21、v0.17 升级的端到端检查都通过，每次 12 项。
- 行为评测新增 3 个项目前台情境：启动项目、问进展、提新要求。现在共 36 个情境、144 项判据。
  - 按你的要求，未变更的部分不重复测试：27 个情境所用角色的文件与 v0.22 完全相同（发布工具逐个文件核对），沿用 v0.22 发布时的回复。项目管理的 6 个情境和新增的 3 个情境在 v0.23 上重新运行。
  - 结果：v0.23 与 v0.22 都通过全部 144 项，没有退步。
- 观察：
  - 新增的三个情境，v0.22 的 PM 也处理得当：如实说明不能创建其他会话、只按文件回答、登记并转交新要求。本版的变化主要在结构上：主对话只做问询、登记与转交，调度和专业讨论分到别处，上下文更短。这一点文字情境测不出来，要在真实项目中长期使用才看得出效果。
  - 在同一环境中，两次前台运行对"能否创建子 Agent"的判断不一致：一次按工具列表判为可以，并标明尚未实际创建；另一次判为不能。检测结果依赖 Agent 自己的判断，真实项目中以第一次实际创建的结果为准。
- 评测方式的限制：
  - 本次在另一个 Agent 会话中进行，每一轮由全新上下文的子 Agent 执行，回复由维护会话原样记录。
  - 评分由执行本次修改的会话完成，未经人工复核。每个情境只运行一次，情境里没有项目文件。
  - 沿用回复的 27 个情境：所有角色都可能读到的共享规则有改动，包括 CORE 的角色清单、USER-INTERACTION 中的一句、RUNTIME、PM-REPORTING 与角色配置模板。我判断这些改动不影响这些情境，但工具无法核对这一点。
